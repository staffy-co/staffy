# Epic 1 Retrospective

Ретроспектива проведена по решению владельца на CHECKPOINT 2 (2026-10-08, вариант А — рекомендация SM). Канон статусов — `sprint-status.yaml` (порядок доверия: git > sprint-status.yaml > DEVLOG > пересказ); все цифры ниже проверены по файлам репозитория на коммите `737d4f9`.

## 1. Фактическое состояние эпика — главная находка

**Epic 1 НЕ закрыт: 12 из 14 stories имеют статус done, 1-13 и 1-14 — backlog.**

- Stories 1-1 … 1-12 — done: полный цикл каждой (спека → CHECKPOINT 1 → dev на ветке → review R1/R2 свежим контекстом → PR → merge в main), CI зелёный на ветке и на main.
- Story 1-13 «Утверждение Operating Profile и правил измерения» (FR-84) — **backlog**, спеки нет.
- Story 1-14 «Readiness-проверка и контролируемая публикация» (FR-6, FR-78) — **backlog**, спеки нет.

Записи DEVLOG `24-sm` («в backlog Epic 1 осталась только 1-12») и `28-merge` («Epic 1 полностью закрыт: все 14 stories done; 1-13/1-14 закрыты ранее») **не соответствуют действительности**. Git-история `sprint-status.yaml` показывает `backlog` у 1-13/1-14 во всех коммитах без исключения; решения, коммита или спеки, «закрывающих» их ранее, не существует. Корректирующая запись — DEVLOG `29-retro` (п. 6 протокола возобновления: расхождение → верь git → зафиксируй correction).

Причины ошибки процесса:
1. Статус-декларации в DEVLOG писались по пересказу плана, а не сверялись с `sprint-status.yaml` перед записью.
2. `check-continuity.sh` сверяет спеки ↔ sprint-status, но не валидирует epic-уровень заявлений DEVLOG («эпик закрыт», «осталась одна story»).
3. Формулировка «закрыты ранее» создала видимость задокументированного решения там, где его не было.

Последствие: владелец выбирал между ретроспективой и Epic 2 на CHECKPOINT 2 в неверной предпосылке «эпик закрыт». Это ошибка процесса, не кода: код и тесты 1-1…1-12 валидны и зелёные. Решение владельца «ретроспектива» остаётся осмысленным — она и выявила расхождение.

## 4. Что сработало — перенести в Epic 2

1. **BMAD-контур с владельцем на каждом чекпоинте.** Четыре story полного цикла за три календарных дня; владелец одобрял спеку до кода и получал отчёт после merge. Спека как единственный source of truth для Dev (frozen-after-approval) удерживала объём срезов.
2. **Append-only + derived-состояния + честные словари исходов.** Единый паттерн от evidence (1-9) до data map (1-10), usage-событий (1-11) и манифеста (1-12): факты immutable, состояния — чистые функции, unknown ≠ ноль, «квартет честности» (complete/partial/stale/unknown и аналоги) во всех модулях.
3. **Review свежим контекстом.** Каждый R1 (субагент без истории сессии) находил реальные дефекты: мёртвая поверхность в продакшн-бинар (1-12), фиктивный RLS-тест (1-12), маскировка 500 под неявный scope (1-12), summary-утечка коммерческих данных (1-11), тихий fallback чисел (1-11). Роль Review обязательна, «Dev проверяет сам себя» — недостаточно.
4. **CI на ветке до merge.** Единственный механизм, поймавший потерю файлов journeys (инцидент §5-4). Правило: merge только после зелёного CI ветки.
5. **Регистр deferred-work с evidence.** Долги не терялись; три долга 1-8 закрыты в 1-9. Требуется разметка закрытия (см. §6 AI-2).
6. **Система непрерывности.** bootstrap + check-continuity + git-канон пережили все сбросы без потерь; порядок доверия сработал и в этой ретроспективе — sprint-status опроверг DEVLOG.

## 5. Что не сработало — инциденты и корни

1. **Ложное закрытие эпика (§1).** Корень: статус-заявления DEVLOG не сверялись с каноном. Закрытие: correction-запись 29-retro + AI-1 (валидация в check-continuity). Не повторять: любое «закрыто/осталось N» в DEVLOG — только после `git diff` канона.
2. **Deferred-work без разметки.** Три закрытых долга числились открытыми; счёт «12 открытых» в 24-sm неточен. Корень: регистр рос, но не размечался. Закрытие: AI-2 (сделано в этом коммите).
3. **Merge-конфликт PR #10** из-за параллельных DEVLOG-записей на main и ветке. Правило «все записи story — на ветке» введено и соблюдалось в 1-10…1-12.
4. **.gitignore без анкера**: паттерн `journeys` молча исключил папку tests/journeys целиком — 2 файла не попали в git, CI ветки упал. Фикс: анкер `/journeys`. Урок: unanchored-паттерны годами маскируют потери.
5. **`[skip ci]` в head гасит CI всего пуша** (bundle) — осознанно: trigger-коммит без маркера для запуска прогона.
6. **REST API 401 при живом git-канале** (цикл 1-11): PR и merge выполнены git-каналом с задокументированным CI-эквивалентом (свежий клон + diff + полный прогон). Инцидент исчерпан сам; вывод: git-канал — резервный путь с честной фиксацией.
7. **gofmt -w по всему internal/** — 12k строк шума в чужих файлах; откат, правки пере-применены в родном стиле. Правило: форматирование только внутри файлов story.
8. **Токен на сессию** — единственный хрупкий канал (перевыдача владельцем). Приёмлемо для одного разработчика; следить на Epic 2.
