## Intent

**Problem:** Словарь бизнес-действий не существует как класс (FR-27, AC-блоки 1-3, 8-9, 11): нет структуры Action Definition — стабильного ID, версии, typed input/output schema, связей с Domain Pack / требуемой Connector capability / Owning System; нет типизированной системы условий (risk, Autonomy Class, допустимые Conversation Modes, роли/authority, обязательные Facts и freshness, Confirmation, required gates, timeout, materiality, consumption rules, допустимый stage) и материальной дисциплины «отсутствие обязательного условия = запрет» — сегодня нечему быть fail-closed, потому что словаря нет; нет классификации delivery-контракта (provider_idempotent / query_reconcilable / compensatable / unsafe) с объявленными idempotency scope, terminal evidence, reconciliation query и cancel/compensation semantics — в Connector CapabilityDeclaration (1-8) эти слова живут, но на стороне действия никто их не объявляет и не сверяет; нет версионирования определений с пин-семантикой (прошлые версии остаются резолвимыми для будущих Manifest/Operation/Receipt); нет поверхности каталога для Owner/Integration Admin; дисциплина «произвольный endpoint или свободная команда не становится Business Action» не заявлена структурно. Честное состояние контура сегодня: НИ ОДИН опубликованный Domain Pack не связан с коннектором, объявляющим query/command-способности (auto-parts/montagio-services ссылаются на типы catalog/inventory/service_catalog, чьи коннекторы StatusDeferred с нулём capabilities; единственный коннектор с объявленными capabilities — синтетическая телефония staffy-synthetic-telephony@1.1.0, которую ни один пак не ссылает) — бинарный каталог первого среза честно ПУСТ, вертикаль закрывается fixture-определениями тестового контура.

**Approach:** Первый срез — рождение модуля `internal/action` (AD-6: только `action` строит Authorized Action; срез — словарная основа, НЕ исполнение) с ЧЕТЫРЬМЯ слоями: (1) домен action/domain: структуры ActionDefinition (ID+Version — неизменяемая пара, пин-семантика прецедента connector-каталога 1-8; Name понятный пользователю; Purpose; TypedInputSchema/TypedOutputSchema — FieldSchema-паттерн 1-8; PackRef {pack_id, pack_version}; RequiredCapability {connector_id, connector_version, capability_id}; OwningSystem — слово словаря 2-7 {catalog, erp}; полная система условий: RiskClass словарь {low, medium, high, critical}; AutonomyClass словарь FR-42 {shadow, copilot, assisted, auto, exception}; AllowedConversationModes — непустое подмножество лестницы 2-5 (7 слов); AllowedRoles — непустое подмножество ролей identity (5 слов); RequiredFacts — список {material_field из 2-7 {price, availability, order_status}, freshness_word словаря 2-7}; ConfirmationRequirement {required, not_required} — мутирующие классы (query/command) ТОЛЬКО required (AD-6 confirm-before-mutate структурно); RequiredGates — список ID-слов GATE-REGISTRY (OQ-*/AG-* словарь); TimeoutMS — bounded 1..600000; MaterialityClass словарь {immaterial, material, critical}; ConsumptionRule словарь {single_use, bounded, unlimited}; AllowedStages — непустое подмножество стадий GATE-REGISTRY {synthetic, closed_account_test, controlled_real_customer, live, scale}; DeliveryContract: CapabilityClass словарь {provider_idempotent, query_reconcilable, compensatable, unsafe} + IdempotencyScope слово + TerminalEvidence слово + ReconciliationQuery (capability_id) + CancelCompensationSemantics слово — ВСЁ типизировано словарями compile-time, расширение рантаймом/конфигом тенанта NEVER) + GuardValidateActionDefinition — fail-closed полнота: каждое обязательное условие ОБЯЗАНО быть объявлено валидным словом словаря (отсутствие/вне-словаря → определение НЕ может существовать в каталоге — материальный зонд); unsafe-дисциплина: CapabilityClass=unsafe → AllowedRoles/autonomy ограничены assisted-семантикой (человеческий контур), иначе guard-отказ (AC-3 «unsafe остаётся assisted/human-only»); версионирование: List() — новейшая версия каждого ID, Get(id, version) — пин точной версии, старые версии неизменяемы и резолвимы (прецедент catalog.go 1-8 байт-в-байт); (2) порты action/port: PackRefResolver + CapabilityRefResolver (консьюмер-owned интерфейсы) — резолюция ссылок определения против живых каталогов employee (пак) и connector (capability) БЕЗ прямых импортов чужих domain (архитектура: cross-module через typed api; валидация резолюции — app-слой, домен гейтит структуру); (3) app: read-only CatalogService — скоуп-гейт integrations|configuration 403 словами ДО материала (персона истории: Owner/Integration Admin; оператор/audit — честный 403, материал настройки не аудиторский — прецедент decision-context 2-14), не-участник 404, membership через identity-порт; ValidateCatalogRefs — полный проход бинарного каталога против резолверов (compile-time-каталог проверяется тестом); (4) каталог action/catalog: бинарный словарь — ЧЕСТНО ПУСТОЙ массив с комментарием-обоснованием (запись появляется ТОЛЬКО когда: пак опубликован + коннектор пака объявляет capability + refs резолвятся + guard зелёный; AG-4 гейтит реальные провайдеры) — вертикаль (транспорт/UI/OpenAPI/интеграционные тесты/journeys) закрывается fixture-определениями, регистрируемыми тестовым composition root (прецедент fixture-сервера 2-x: фикстура НЕ в продуктовом бинарнике); поверхности: GET /v1/tenants/{t}/action-definitions (список новейших версий) + GET /v1/tenants/{t}/action-definitions/{id}/{version} (пин точной версии — материал для будущих Manifest/Operation/Receipt ссылок AC-8); страница каталога действий (карточки: имя, версия, risk-бейдж, stage, capability-ссылка, owning system, состояние; условия раскрываются прогрессивно details/summary — прецедент provider-техники 2-14; a11y 320px/≥44×44/клавиатура/semantic headings — AC-11); OpenAPI +2 пути + ActionDefinitionView схема; контракт-тест зеркалит словари; матрица ~20 строк поимённо + journeys-цепь z29 (fixture-каталог: карточки с условиями, прогрессивное раскрытие, пин-чтение старой версии, пустой-кейс — честная страница отсутствия, a11y).

**Boundaries см. ниже; ядро честности среза: определение без полного набора условий НЕ существует (fail-closed guard — отсутствие условия = запрет, материально); unsafe НИКОГДА не покидает assisted/human-only семантику; бинарный каталог честно пуст — ни один пак не имеет capability-коннектора (дисциплина AC-1 живёт структурно: произвольный endpoint не становится действием, потому что действий в каталоге НЕТ до полных определений); версии неизменяемы и пин-резолвимы — «последняя предлагается, старые закреплены».**

## Boundaries & Constraints

**Always:** модуль internal/action рождается по AD-6 (api/app/domain/port/catalog, БЕЗ store — таблиц в срезе НЕТ: определения compile-time, tenant-состояния — будущие срезы); ActionDefinition — неизменяемая пара (ID, Version) в двоичном каталоге (прецедент 1-8): List() отдаёт новейшую версию каждого ID, Get() пинит точную, старые версии НИКОГДА не перезаписываются и не удаляются (AC-8: будущие Manifest/Operations/Receipts ссылаются на прежние — резолвимость пин-чтением); GuardValidateActionDefinition fail-closed: каждое поле словаря валидируется против compile-time словаря — RiskClass {low, medium, high, critical}; AutonomyClass {shadow, copilot, assisted, auto, exception} точно словами FR-42; AllowedConversationModes ⊆ лестницы 2-5 {safety, claim, cancellation, privacy_no_contact, human_requested, unclassified, sales} НЕПУСТО; AllowedRoles ⊆ ролей identity {owner, configurator, operator, expert_qa, integration_admin} НЕПУСТО; RequiredFacts: material_field ∈ {price, availability, order_status} (2-7) + freshness-слово словаря 2-7; ConfirmationRequirement {required, not_required} с материальной парой: класс действия query/command → ТОЛЬКО required (confirm-before-mutate AD-6; guard отказывает мутирующему определению с not_required — зонд); RequiredGates ⊆ словаря GATE-REGISTRY (OQ-1…OQ-19, AG-1…AG-4); TimeoutMS 1..600000; MaterialityClass {immaterial, material, critical}; ConsumptionRule {single_use, bounded, unlimited}; AllowedStages ⊆ {synthetic, closed_account_test, controlled_real_customer, live, scale} НЕПУСТО; DeliveryContract.CapabilityClass ∈ {provider_idempotent, query_reconcilable, compensatable, unsafe} + обязательные declared слова IdempotencyScope/TerminalEvidence/ReconciliationQuery/CancelCompensationSemantics (отсутствие → guard-отказ); unsafe-дисциплина AC-3: CapabilityClass=unsafe → guard требует человеческой семантики (confirmation required + consumption single_use, иначе отказ — зонд; «unsafe остаётся assisted/human-only» материален); скоуп-гейт чтения: integrations|configuration (Owner/Integration Admin/Configurator — персона истории), 403 словами скоупа ДО материала, оператор/audit — честный 403 (материал настройки); не-участник тенанта → 404 ×пути; слепота RLS на месте (чтение глобального словаря под tenant-путём — membership-гейт); каталог НЕ несёт секретов: определения — декларации полей и словарных слов, значений секретов НИКОГДА; OpenAPI синхронен: +2 пути, ActionDefinitionView со словарными enum-ами, additionalProperties false; UI: прогрессивное раскрытие details/summary, risk/stage/capability/owning-system текстом, недоступное объясняет причину (в срезе — честное отсутствие определений: «каталог пуст — определения появятся с опубликованными pack-коннекторами» + причина словами, НЕ пустая страница без объяснения — AC-11 «недоступное объясняет причину» живёт в пустом состоянии); тестовые файлы прошлых срезов не правятся; словари расширение рантаймом/конфигом тенанта NEVER (compile-time).

## I/O & Edge-Case Matrix

- Given валидное fixture-определение (полные условия + резолвящиеся ссылки), when Guard + ValidateCatalogRefs, then определение допускается в каталог тестового контура; карточка отдаёт: имя, версию, risk, stage, capability, owning system, условия прогрессивно — AC-1/AC-2/AC-11.
- Given определение без ОДНОГО обязательного условия (risk / autonomy / modes / roles / facts / confirmation / gates / timeout / materiality / consumption / stages / delivery-слова), when guard, then отказ со словарной причиной — «отсутствие обязательного условия = запрет» материально (AC-2 зонд: каждая ветка поимённо).
- Given мутирующее определение (query/command) с ConfirmationRequirement=not_required, when guard, then отказ (confirm-before-mutate AD-6 — пара словаря зондом).
- Given CapabilityClass=unsafe без человеческой семантики (confirmation not_required ИЛИ consumption unlimited), when guard, then отказ; unsafe с confirmation required + single_use → допускается, карточка честно показывает «human-only/assisted» — AC-3.
- Given CapabilityClass=provider_idempotent при коннекторной декларации Idempotent=false, when ValidateCatalogRefs, then отказ с причиной «коннектор не объявляет идемпотентность» (сверка delivery-слов определения против CapabilityDeclaration 1-8); query_reconcilable без Reconciliation-декларации → отказ — AC-3 живой сверкой.
- Given PackRef на несуществующий пак / CapabilityRef на несуществующий коннектор-версию-capability, when резолюция, then отказ с честной причиной; catalog-тест бинарного словаря: НУЛЕВОЕ записей — ValidateCatalogRefs проходит vacuously, пустота задокументирована комментарием (AG-4).
- Given AllowedConversationModes вне лестницы 2-5 / AllowedRoles вне ролей / material_field вне 2-7 / gates вне GATE-REGISTRY / stages вне словаря стадий, when guard, then 400-эквивалент словарной причиной (зеркала словарей пиннятся контракт-тестом против источников — drift = красный тест).
- Given две версии одного ID (fixture 1.0.0/1.1.0), when List, then ТОЛЬКО новейшая 1.1.0; when Get(id, 1.0.0), then пин старой — резолвимая неизменяемая ссылка для будущих Manifest/Operations (AC-8); изменение любой опубликованной версии в коде = новая версия, НЕ правка (ревью-дисциплина).
- Given не-участник тенанта / чужой тенент, when GET каталога, then 404 ×пути (membership-гейт до материала); Given участник без скоупа integrations|configuration (operator/audit), when GET, then 403 словами скоупа ДО материала — AC-9.
- Given слепая проба секретов, when каталог-чтение, then значений секретов НЕТ (определения — декларации полей; secret=true только помечает поле схемы) — AC-9 «аудит без секретов».
- Given production-бинар (пустой каталог), when GET, then 200 с честным пустым списком + страница объясняет причину словами (не пустая заглушка) — контрольная ветка байт-в-байт.
- Given OpenAPI, when контракт-тест, then словарные enum-ы зеркальны домену (RiskClass/AutonomyClass/CapabilityClass/стадии/ConfirmationRequirement/MaterialityClass/ConsumptionRule), additionalProperties false, секретных полей-значений нет.
- Given journeys-цепь z29, when fixture-каталог (2 определения + 2 версии одного ID), then карточки с полными условиями (прогрессивное раскрытие details), пин-чтение старой версии, risk/stage текстом, a11y 320px/клавиатура/заголовки, пустая страница с причиной — сквозной путь живой.
