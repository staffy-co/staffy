## Intent

**Problem:** Epic 4 закрыл контур 4-1..4-10 (10/11), но результата пилота НЕ ВИДНО: владелец не может ответить на вопрос «приносит ли пилот пользу» даже на уровне наблюдаемых фактов — (1) исход одного обращения не собран в одну цепочку: атрибуция (какой источник привёл), профиль автомобиля, доказанная применимость, заказ, проверка менеджером, отправка поставщику живут в РАЗНЫХ панелях без общей воронки (FR-63 «связывать источник обращения, Conversation, ABCP Order, доступное состояние 1С, отмену/возврат...» — связи-представления нет); (2) агрегатов пилота НЕТ вообще: объём обращений, конверсии между доказанными этапами, коррекции/Handoff/Recovery — не считаются нигде; (3) словарь измерений не существует: определения показателей (формула, grain, numerator/denominator, окно зрелости, owning source, exclusions, версия) не зафиксированы — сравнительный вывод по OQ-7 нечему блокировать; (4) неизвестные исходы (исполнено/оплачено/отменено/возвращено — владеющие источники вне контура OQ-4/OQ-3) не имеют категории «unknown/pending» — молчаливое исключение узаконило бы ложную картину; (5) выручка/маржа/переменные расходы/человеческие минуты НЕ ИЗМЕРИМЫ в контуре (1С не подключён OQ-4; закупочные цены за фенсом 4-9; usage-записи 1-11 не несут кейс; утверждённого способа пересчёта минут нет) — без честных слов любая цифра была бы подменой (AC-4/AC-5/AC-7/AC-8: «отсутствующая составляющая делает маржу неполной или неизвестной», «отсутствующие данные не заменяются нулём»).

**Approach:** модуль action (якорь — операция заказа и её окружение 4-6..4-10, прецедент 4-9/4-10). ЧИСТЫЙ read-time срез — 0 миграций, 0 пишущих путей, 0 OpenAPI-изменений (новых JSON-маршрутов нет — HTML-поверхности, прецедент pilot.html 4-1). Четыре части: (1) домен `internal/action/domain/pilot_outcome.go` — словари compile-time (10 стадий воронки + 3 состояния + слова evidence-источников; атрибуция; Measurement Dictionary v1: измеримые и неизмеримые показатели с полными определениями) + DeriveCaseOutcome (чистый fold над материалом: атрибуция первого принятого inbound события Timeline кейса + воронка с evidence) + DerivePilotReport (чистый агрегатный fold: counts/конверсии/выборка/период + неизвестная доля); (2) app-сервис `internal/action/app/pilot_outcome.go` — CaseOutcomeView (кейс-материал через НОВЫЙ узкий порт PilotCaseSource {CasesView, CaseView, FactsView} — cases Service удовлетворяет структурно, composition-root адаптер по прецеденту assurancesource.New 4-10; action-материал — чтение существующими сторами OrderStatusView-паттерном) + PilotReportView (листинг кейсов периода → per-case деривация → агрегат; честная деградация nil-порта = нулевая панель/страница); (3) панель «Исход обращения» на странице кейса после «Обслуживания заказа» (id="case-outcome") + НОВАЯ страница «Отчёт пилота» `/app/tenants/{tenant_id}/pilot-outcome` (period=YYYY-MM query, отсутствие = «весь период наблюдения»); (4) интеграционная eval-матрица живым PG + journeys z48 + wire-тесты.

**Ядро честности среза:** исход обращения — ЖИВАЯ деривация записанного материала, никогда не хранимое слово: повторное чтение неизменного мира даёт тот же ответ; поздний факт (запись поставщика 4-9, коррекция 4-8) меняет чтение БЕЗ переписывания истории (факты append-only по построению — AC-13 read-time-исполнением, versioned indicator store честно отложен); стадии fulfilled/paid/cancelled/returned — unknown_pending ВСЕГДА в этом срезе с пинами причин (OQ-4/OQ-3/№215) — «не доказано и не опровергнуто», НЕ ноль и НЕ исключение (AC-14); выручка/маржа/расходы/минуты — НЕизмеримые показатели словаря: строки отчёта словами причин, чисел НЕТ (AC-4: созданный заказ ≠ выручка, ожидаемая оплата ≠ полученные деньги; AC-5: маржа «неизвестна»; AC-7: usage без атрибуции на кейс; AC-8: минуты без утверждённого способа); КАЖДОЕ число отчёта сопровождается размером выборки и периодом (AC-11); OQ-7 гейт словом в заголовке отчёта: baseline/когорт/порогов НЕТ → наблюдаемые показатели БЕЗ заявления об улучшении, корреляция ≠ причинность (AC-12); атрибуция — только переданное источником (provider/channel/event ID/время первого принятого события), campaign/referrer = unknown словом — НЕ восстанавливается догадкой модели (AC-1, envelope v1 не трогается); VIN/текст диалога НЕ попадают в агрегаты — структурный зонд полей вью (AC-15); доступ — view-скоуп обращений (review/configuration/audit), drill-down — ссылками на страницы кейсов под существующими правами (AC-16).

## Boundaries & Constraints

**Always:** словари compile-time BY NAME (стадии/состояния/показатели) + зеркала в юнит-тестах (прецедент mirrors_test); состояния стадий — {proven, not_reached, unknown_pending} BY NAME: proven ТОЛЬКО при наличии evidence BY NAME с временем и источником; воронка/агрегаты — read-time деривация существующими портами/сторами (панели и машины 2-3/2-13/3-6/3-8/4-6..4-10 — только чтение, name-only дифф); КАЖДОЕ число отчёта — с размером выборки (число кейсов) и периодом (слово BY NAME); конверсии — только между ДОКАЗАННЫМИ соседними стадиями (numerator/denominator BY NAME; unknown_pending-стадии в знаменатели конверсий НЕ входят — честная граница измеримости); доля неизвестных исходов — отдельная строка (влияние неизвестного на достоверность — AC-14); Measurement Dictionary v1 рендерится на странице отчёта (определения всех показателей + версия v1 + владелец-слово — AC-9: «утверждаются до сравнительного вывода» = одобрение спеки CHECKPOINT 1; смена определения — новая версия словаря через Spec Change Log, НЕ молча — AC-9); деградация честная (nil-порт/forbidden = нулевая панель/страница, остальная поверхность жива — прецедент 4-9/4-10); серверная истина актёра + view-скоуп review/configuration/audit (чужой — 403 словами); отчёт перечитывает листинг кейсов периода (ListCases → per-case чтения — объём пилота мал, AG-1 конверт; честное слово о стоимости чтения в Implementation Notes); регресс — build/vet/unit + интеграция ×2 TZ + journeys + скан.

**Never:** НЕ записывать НИЧЕГО (срез read-only: 0 миграций, 0 пишущих путей — зонд: SQL-дифф ветки = 0 файлов миграций); НЕ заводить записи выручки/оплаты/возврата менеджером (AC-4: выручка — только Owning System 1С, отсутствует OQ-4; «менеджер записал оплату» — подмена источника, запрещено); НЕ показывать выручку/маржу/переменные расходы/человеческие минуты ЧИСЛОМ (никогда 0 — только слова причин + ссылки: AC-4/AC-5/AC-7/AC-8); НЕ строить baseline/когорты/пороги/сравнение с базовым процессом/заявление об улучшении (OQ-7 не пройден — слово-гейт; SM-2 живой этап — будущая поверхность); НЕ атрибутировать usage-затраты тенанта на обращения (1-11: UsageEvent не несёт кейс — conflating запрещён; страница бюджета — словом-ссылкой); НЕ выводить человеческие минуты из lifecycle-событий 2-13/задач 4-7 (утверждённого способа учёта нет; ожидание клиента ≠ активная работа материалом не различимы; 0 не подставляется — AC-8); НЕ добавлять campaign/referrer в ingress envelope (schema v1 заморожена — неизвестность словом, восстановление догадкой запрещено AC-1); НЕ строить экспорт/JSON-API/webhook метрик (HTML-поверхности среза; экспорт — будущий срез AC-15); НЕ строить хранилище версионируемых значений показателей и фоновый пересчёт (исход — живая деривация; «предыдущая версия показателя, причина и время изменения» — история append-only фактов + версии словаря, словом; versioned store — честно отложено AC-13); НЕ строить обогащение атрибуции ретроактивно (source фиксируется канал-событием при приёме — AC-1); НЕ трогать ингресс/каналы/уведомления (OQ-1/OQ-2 — поверхности клиента не строятся); НЕ выносить VIN/полный текст диалога/телефон в агрегаты и отчёт (структурный зонд: поля вью агрегата — counts только; AC-15); НЕ пинать терминальные стадии (fulfilled/paid/cancelled/returned ВСЕГДА unknown_pending в срезе — «успех не заявляется, пока терминального доказательства нет», прецедент матрицы OQ-19); цвет — НЕ единственный различитель (слова состояний текстом — AC-18); НЕ заводить рантайм-изменение словаря измерений (compile-time v1; утверждение — процесс спеки, НЕ кнопка).

## I/O & Edge-Case Matrix

- Given кейс создан (первое принятое inbound событие канала), when CaseOutcomeView, then inquiry_accepted = proven с evidence «кейс создан» + время создания + атрибуция {provider, channel, provider_event_id, время события BY NAME}; campaign/referrer = «источник не передал — не восстанавливается» (unknown словом — AC-1); цепочка исхода рендерится (источник → диалог → кейс → … BY NAME — AC-2).
- Given свежий кейс без материала идентификации, when воронка, then vehicle_profile_confirmed = not_reached (материал отсутствует — обращение не дошло), остальные стадии дальше — not_reached; fulfilled/paid/cancelled/returned = unknown_pending ПОИМЁННО с пинами (OQ-4/OQ-3/№215) — НЕ ноль, НЕ исключение (AC-14).
- Given профиль автомобиля подтверждён (материал 4-2), when воронка, then vehicle_profile_confirmed = proven (evidence: подтверждённые атрибуты идентификации BY NAME + время); применимость не доказана → applicability_proven = not_reached.
- Given применимость доказана (лестница 4-4 FitmentStatusProven), when воронка, then applicability_proven = proven (evidence: доказанная применимость BY NAME + время); заказ не создан → дальше not_reached.
- Given операция create_abcp_customer_order с committed-квитанцией 4-6 (внешний ABCP order ID), when воронка, then client_order_created = proven (evidence: операция + квитанция диспетчера + внешний ID BY NAME); менеджер не проверил → manager_verified = not_reached.
- Given задача проверки 4-7 approved, when воронка, then manager_verified = proven (evidence: подтверждённая проверка BY NAME + время + исполнитель).
- Given факты поставщика 4-9 содержат {sent} (запись менеджера), when воронка, then supplier_sent = proven (evidence: запись отправки поставщику BY NAME + время + supplier_order_id); фактов нет → not_reached.
- Given ПОЗДНИЙ факт: сначала прочитан исход (supplier_sent = not_reached), затем менеджер записал факт sent 4-9, when повторное чтение, then supplier_sent = proven — исход перечитался живой деривацией, история фактов append-only не тронута (AC-13 read-time; зонд интеграции).
- Given владелец открывает Отчёт пилота (период=месяц BY NAME), when PilotReportView, then объём обращений (count кейсов периода) + воронка стадий (counts proven) + конверсии между ДОКАЗАННЫМИ соседями (numerator/denominator BY NAME; unknown_pending-стадии НЕ в знаменателях) + corrections/handoff/recovery counts + доля неизвестных исходов — КАЖДОЕ число с размером выборки и периодом (AC-11); строки revenue/margin/variable_costs/human_minutes — словами причин БЕЗ чисел (AC-4/5/7/8); заголовок OQ-7: «утверждённых baseline нет — без заявления об улучшении; корреляция — не причинность» (AC-12); словарь измерений v1 с определениями (AC-9).

- Given period=YYYY-MM задан / не задан, when отчёт, then выборка = кейсы, созданные в месяце BY NAME / «весь период наблюдения» (слово периода всегда рядом с числом — AC-11); пустой период = честная нулевая выборка со словом (числа 0 допустимы только как СЧЁТ кейсов, не как значения неизмеримых).
