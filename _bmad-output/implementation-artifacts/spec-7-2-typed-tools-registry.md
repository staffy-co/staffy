## Intent

**Problem:** AR-17 требует, чтобы каждый AI-сотрудник запускался по Release Manifest, связывающему в том числе tools — но tools в системе не существует: RuntimeDictionary помечает tool_schemas статичной запиской «Поверхность компонента ещё не существует в системе» (честный gap спеки 1-12, зафиксированный до Epic 7). (1) AD-7 разрешает модели запрашивать только deterministic/read инструменты, но словаря типизированных tool-контрактов нет: Planner Epic 8 (предварительная story 8.3 «tool-rounds над реестром Story 7.2») и MCP-сервер 7.3 строятся поверх несуществующего субстрата. (2) Привязка пак → tools невозможна: артефакт пака 7-1 не имеет поля tools. (3) Путь внешнего автора tool-контракта = правка кода ядра — нарушает дух AD-1 (субстрат 7-1 закрыл это для паков, но не для tools). (4) Оператор не может увидеть, какие инструменты объявлены, каковы их классы детерминированности и реализованы ли адаптеры: поверхности словаря нет. (5) Гарантия AD-6/AD-7 «исполняемые записи никогда не входят в tool set модели» держится только дисциплиной ревью — реестр с fail-closed словарём классов делает её машинальной.

**Approach:** субстрат без исполнения, полным зерном дисциплины 7-1 (сменён носитель — не построен рантайм): реестр типизированных контрактов как версионируемые JSON-артефакты `internal/tools/registry/<id>@<version>.json` + `index.json` с sha256-пинами (append-only, go:embed — версионируется git'ом с ядром) + fail-closed загрузчик с полной валидацией ДО любого использования и поимёнными причинами. Привязка пак → tools — опциональным полем `tools` артефакта пака (прецедент optional-полей 4-2..4-5: nil для всех паков без привязки); первая живая привязка — auto-parts@6.1.0 (minor существующего major 6: совместимая по умолчанию, UpgradeFrom не требуется по правилам 7-1), привязывает 3 вертикальных контракта над СУЩЕСТВУЮЩИМИ машинами (идентификация автомобиля 4-2, классификация запроса детали 4-3, доказательство применимости 4-4). RuntimeDictionary/BuildRuntimeState вычисляет tool_schemas производно из привязки пина пака. Поверхность оператора — read-only словарь по прецеденту «Каталог действий» 3-1. Drift-CI и путь внешнего автора — по прецедентам 7-1. Исполнение tool-вызовов (диспетчеризация контракта вызывающей стороной) не строится: будущие вызыватели — Planner 8.3 и MCP-сервер 7.3; регистрация контракта ≠ доступность вызова.

**Ядро честности среза:** (1) write-инструмент структурно невозможен: платформенный словарь determinism_class содержит единственное значение deterministic_read; значение вне словаря = реестр не грузится ЦЕЛИКОМ (fail-closed на классе, AC-1); расширение словаря = правка ядра, никогда — правка артефакта. (2) Ничто не заявлено сверх доказанного: все живые контракты объявляют adapter not_implemented (дисциплина AdapterImplemented коннекторов; прецедент Монtagio/Avito — capability неподтверждённого провайдера не заявляются); tool_schemas остаётся честным absent в манифестах, вызов невозможен вдвойне (адаптеров нет и диспетчера нет). (3) Смена семантики контракта — только новой версией: sha-пин ловит правку опубликованного артефакта (drift-FAIL; новая версия = новый файл + новая запись индекса). (4) Sealed-история манифестов неизменна: производное состояние tool_schemas вычисляется только при новых seal'ах (AD-10; дайджесты запечатанных манифестов не пересчитываются). (5) Манифест не расширяется чужими инструментами: в Ref попадают только контракты, привязанные пином пака этого сотрудника. (6) AC-3 честно частично: статическая кросс-валидация зависимостей (dependency.connector_type ∈ connector_types привязывающего пака) в срезе; динамический capability-probe (evidence, stale при ротации) требует вызова — 7.3/8.3, граница в deferred-work.

## Boundaries & Constraints

**Always:** (1) Реестр tools — ЕДИНСТВЕННЫЙ источник tool-контрактов: артефакты + индекс sha256 append-only + go:embed (прецедент 7-1 дословно); невалидный артефакт = реестр не загружается целиком, «частичный словарь лучшим усилием» запрещён. (2) Валидация при каждой загрузке, поимённые причины: обязательные поля {id, version, name, purpose, determinism_class, input_schema, output_schema, owner, evidence_ref, adapter_status} — урок ValidateVariants 5-1: ВСЕ незащищённые поля обязательны; платформенные словари {determinism_class: deterministic_read — единственное значение; adapter_status: implemented | not_implemented; типы ключей input/output-схем — существующий словарь типизации паков}; строгий semver-core (без prerelease/build — прецедент 7-1); дубликаты id@version, неиндексированные файлы, канон имени <id>@<version>.json, sha256-пины — как 7-1. (3) Кросс-валидация привязки в загрузчике паков: каждый реф поля tools разрешается в реестре tools (составная публикация обязана включать цель — прецедент UpgradeFrom); привязанный контракт с dependency: connector_type ∈ connector_types привязывающего пака; нарушения = реестр паков не грузится (fail-closed поимённо). (4) tool_schemas в манифесте — производное состояние при seal: пак без tools → absent с производной запиской; пак с tools, все адаптеры not_implemented → Present=false + честная записка о числе контрактов; ≥1 реализованный и проверенный → Present=true + Ref «<pack>@<version>: N tool-контрактов» (машина покрыта fixture-тестами; живых implemented-контрактов в срезе нет); nil-ветка статики не оставляется как путь по умолчанию — вычисление явное. (5) Поверхность оператора read-only за лестницей членства: read-gate FIRST (не-member тенента = честный 404; member без скоупов = 403 со словами скоупов ДО выдачи материала — прецедент 3-1); несуществующий или малформед tool id/version = честный 404; словари реестра зеркалятся OpenAPI (enum-зеркала, contract_test). (6) Drift-CI на каждом ране: sha256 индекс↔файлы; полная валидация всех артефактов; append-only против базы origin/main (GITHUB_ENV только в ветке успеха — урок 7-1 CI ×2 ремонта); вертикальный зонд: словарь артефактов tools добавляется осознанной правкой drift_test (обновление словаря = новая версия артефакта = осознанный шаг), зона зонда расширяется платформенным пакетом internal/tools. (7) Существующие 7 артефактов паков байт-стабильны: witness-подсерия 7-1 переживает и поле tools (omitempty, nil у старых артефактов), и восьмую запись индекса (auto-parts@6.1.0 — дополнения реестра разрешены).

**Never:** не строить исполнение/диспетчеризацию tool-вызовов и runtime capability-probe при вызове (зависимости декларируются и валидируются статически; динамическая проверка evidence/stale — 7.3/8.3, deferred-work); не строить MCP-сервер (7.3) и внешние MCP-коннекторы (7.4); не вводить HTTP-поверхность публикации/администрирования записей реестра (путь внешнего автора = git PR «артефакт + индексная запись», 0 правок .go); не пересчитывать sealed-историю манифестов и не менять структуру RuntimeComponentState/RuntimeDictionary (порядок и поля словаря фиксированы — меняется только вычисление состояния tool_schemas при новых seal'ах); не расширять платформенные словари артефактами (значение вне словаря = отказ); не менять сигнатуры/семантику Get/List/Impact каталога паков и их потребителей 7-1 (packresolver, action catalog, transport domain_pack, employee app/store — 0 правок вне перечисленных в Code Map зон); 0 SQL-миграций (реестр — актив кода; манифест — вычисляемое содержимое); не заявлять implemented-адаптеры, которых нет (все живые контракты not_implemented); не строить машину review-гейтов внешних авторов (граница — deferred-work, прецедент 7-1); не регистрировать платформенные контракты поверх каталога паков (потребность не доказана — по реальному спросу позже артефактом без правки ядра); не вводить стандарт json-schema.org или внешние зависимости схем (платформенный язык типизированных ключей).

## I/O & Edge-Case Matrix

- Given валидный артефакт tool (auto-parts.vehicle-identification@1.0.0) с совпавшим sha256-пином, when загрузка реестра, then контракт доступен Get/List, deep-equal артефакту; мутация возвращённой копии невидима следующему читателю (clone-дисциплина 1-4 над артефактным источником)
- Given артефакт tool с отсутствующим обязательным полем (например, evidence_ref), when загрузка, then отказ поимённо «<id>@<version>: обязательное поле evidence_ref отсутствует» И реестр tools ЦЕЛИКОМ не грузится (fail-closed: частичный словарь запрещён) — даже если остальные артефакты валидны
- Given determinism_class вне платформенного словаря (например, «write» или «mutation»), when валидация, then отказ «determinism_class: значение … вне платформенного словаря» — write-инструмент в реестре невозможен (AC-1, fail-closed на классе)
- Given adapter_status вне словаря или тип ключа input/output-схемы вне словаря, when валидация, then отказ поимённо с именем поля
- Given version артефакта tool не semver-core (prerelease, двухкомпонентная), when валидация, then отказ поимённо (parseSemver 7-1)
- Given дубликат id@version, неиндексированный файл в registry/, или имя файла вне канона <id>@<version>.json, when загрузка, then отказ поимённо (дубликат/не индексирован/канон имён — 7-1 дословно)
- Given sha256 файла ≠ пин индекса, when загрузка или drift-CI, then FAIL «артефакт изменён после индексации» — смена семантики контракта только новой версией (AC-1)
- Given из индекса tools удалена существующая запись id@version, when drift-CI, then FAIL append-only (версии не удаляются — защита привязок паков; локальная симуляция удаления = поимённый отказ)
- Given артефакт пака привязывает реф tool, отсутствующий в реестре tools, when загрузка реестра паков, then отказ поимённо «<pack>@<version>: tool <id>@<version> отсутствует в реестре tools» И реестр паков не грузится целиком (составная публикация обязана включать цель)
- Given привязанный tool декларирует dependency.connector_type ∉ connector_types привязывающего пака, when кросс-валидация, then отказ поимённо (зависимость не декларирована доменом пака — AC-3, статическая половина)
- Given auto-parts@6.1.0 (tools: 3 контракта, все adapter not_implemented), when загрузка обоих реестров, then пак и контракты валидны: рефы разрешаются, dependency «catalog» ∈ [catalog, inventory], impact-машина возвращает совместимость minor-перехода (правила 7-1 сохранены)
- Given seal манифеста сотрудника с пином пака без tools (≤6.0.0, montagio), when вычисление состояния, then tool_schemas Present=false, записка производная (пак не привязывает контракты) — НЕ статичная «поверхность не существует»; sealed-история не пересчитывается
- Given пин auto-parts@6.1.0, when seal, then tool_schemas Present=false + честная записка «привязывает 3 tool-контракта, адаптеры не реализованы — вызов невозможен»; ни один tool не попадает в manifest как присутствующий (AC-2: без действующей проверки)
- Given fixture-пак с привязкой implemented-контракта (fstest.MapFS в тесте), when вычисление состояния, then Present=true + Ref «<pack>@<version>: N tool-контрактов» — машина присутствия покрыта тестом (живых implemented нет — честная граница)
- Given оператор — member тенента со скоупами, when GET /v1/tenants/{id}/tools, then словарь новейших версий контрактов (id, версии, классы, статусы адаптеров, dependencies, owner); GET …/tools/{tool_id}/{tool_version} — пин-чтение точной версии (материал для будущих Manifest/Planner-ссылок — прецедент 3-1)
- Given несуществующий tool id/version или малформед-параметры пути, when GET, then честный 404 (изобретённое будущее не существует — прецедент пин-чтения 3-1)
- Given не-member тенента / member без скоупов, when GET любой tools-поверхности, then 404 / 403 по лестнице членства (read-gate FIRST — до выдачи материала)
- Given внешний автор: PR «+registry/<id>@<version>.json +запись индекса», 0 правок .go, when CI, then валидация PASS при корректном артефакте, полный сьют зелёный (дополнения реестра разрешены — прецедент подсерии 7-1); review-гейты = существующий PR-процесс (honest)
- Given вертикальная фраза артефактов tools («Идентификация автомобиля», назначение контрактов…) в прод-.go ядра (зона 7-1 + internal/tools), when зонд CI, then FAIL поимённо (словарь зонда расширен фразами артефактов tools — 0 нарушений держится)

## Implementation Notes

- Словарь классов детерминированности — ЕДИНСТВЕННОЕ значение deterministic_read: точка расширения будущего — всегда правкой ядра (машинальная гарантия AD-6/AD-7 «исполняемые записи никогда не входят в tool set»); «класс детерминированности» AC-1 = это поле
- Вход/выход «(JSON Schema)» AC-1 = JSON-описанные схемы в платформенном языке типизированных ключей (существующий словарь типизации паков: string/integer/boolean + values/min/max/optional): стандарт json-schema.org не вводится (новое понятие/зависимость вне среза); расширение словаря типов = правка ядра
- evidence_ref — символьный версионируемый реф (как policy_ref/knowledge_ref/eval_ref паков): непустой, формат свободный; семантика — доказательство контракта (спека + машина + тесты: 4-2/4-3/4-4); разрешение — review PR (честность заявлений capability — прецедент Монtagio/Avito)
- adapter_status — дисциплина AdapterImplemented коннекторов, применённая к инструментам: not_implemented контракты видны в реестре/на странице, но не попадают в manifest как присутствующие и не могут быть вызваны (вызова в срезе нет вовсе — двойная честность)
- dependency — только connector_type (тип, не конкретный коннектор): статическая кросс-проверка против connector_types привязывающего пака (самодостаточно в packs loader — без импорта каталога коннекторов); конкретные разрешённые источники остаются в вертикальных полях пака (fitment.allowed_sources 6.0.0); динамический capability-probe (evidence/stale при ротации) — с исполнением вызова, 7.3/8.3, deferred-work
