## Implementation Notes

- Решение «unknown/reconciling» слэша эпика: операция ОСТАЁТСЯ unknown, reconciling — 8-е ledger-слово НЕ state-bearing (зеркальное решение dispatch_blocked 3-6: DeriveOperationState пропускает). Сверка — активность, не состояние; «Operation находится в unknown/reconciling» исполняется парой {состояние unknown, активность reconciling в истории} — прецедент «submitted/accepted слэш» 3-6.
- Решение «failed/no_effect» слэша эпика: no_effect — ВЕРДИКТ сверки (доказанное отсутствие эффекта), отражается парой {ledger-слово failed, receipt-исход failed с доказательством отсутствия словами/ссылками в references}. Словари состояний (6) и квитанций (3) НЕ растут — доказательство едет содержимым квитанции, не новым словом.
- no_effect принимается ТОЛЬКО при объявленной семантике отсутствия: непустой LIVE Reconciliation слов декларации каталога коннектора И непустой ReconciliationQuery определения (гейт 3-1 catalog.go:404 зеркально). Голый 404/молчание без объявленной семантики = no_answer, unknown остаётся, повтор НЕ разблокирован (AC-3 дословно).
- Retry-unlock — ядро AC-3/AC-6: записанный вердикт no_effect — доказательство пустоты внешнего эффекта, заменяющее роль гарантии provider_idempotent в запрете слепого повтора (повтор не может дублировать эффект, которого доказанно нет).
