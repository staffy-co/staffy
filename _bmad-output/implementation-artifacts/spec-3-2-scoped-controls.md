## Intent

**Problem:** Аварийное ограничение работы не существует как класс (FR-32, AC-блоки 1-4, 8-12): оператор не может остановить рискованный маршрут точечно, без отключения всей платформы. Нет записи ScopedControl — scope-объект + режим + причина + владелец + время изменения + поколение; нет словаря режимов контроля AD-12 {accept, intake_only/no_promises, human_only, paused} с лестницей ограничительности и наиболее ограничивающим пересечением («более узкое разрешение не может отменить более широкую блокировку» — сегодня нечему быть материальным: controls нет, пересечение нечему вычислять); нет control_generation (AD-16: invalidates affected queued work through scoped control generation — поколений не существует, stale-детекции нечем детектировать); нет оптимистичной конкурентности двух операторов с сохранением истории обеих попыток; нет append-only аудита и versioned outbox события изменения (AD-13 transactional outbox); нет expiry/scheduled-семантики идемпотентного истечения («автоматическое истечение возвращает к предыдущему явно вычисленному effective mode»); нет операторской поверхности выбора scope {Tenant, Connector, channel, service, Policy Outcome, Autonomy Class, campaign} с показом current effective mode, источника правила, владельца и времени. Честное состояние контура: enforcement-точки, обязанные читать controls, сегодня НЕ существуют — workers/dispatch строятся в 3-3..3-6 (повторная проверка поколения перед отправкой к Connector), разговорный движок/AI Runtime отсутствует (AG-4 — активные conversation останавливать некому), admission приёма внешних событий в cases существует (2-1 IngestEvent), но семантики per-режима (приём данных без нового Commitment, маршрутизация человеку, объявленный останов/fallback) сплетаются с поверхностями commitments (2-9), handoff (2-13) и quarantine (2-1), имеющими собственных владельцев и жизненные циклы. Первый срез рождает модуль записи и вычисления: полный жизненный цикл control-точки, наиболее ограничивающее пересечение с провенансом, монотонные поколения, аудит обеих попыток, outbox, чтение-временные окна, операторские поверхности — и типизированный read-API EffectiveFor для enforcement-точек будущего.

**Approach:** Рождение `internal/control` по AD-12/13/16 (мутации: ONLY через приложение; словари compile-time; tenant-состояние — PG по AD-13). Пять слоёв: (1) домен internal/control/domain — словарь режимов ТОЧНЫМИ словами {accept; intake_only/no_promises (слово AD-12/FR-32 дословно, слэш — часть слова, НЕ переименование); human_only; paused} + ранги ограничительности: порядок перечисления нормативен (accept наименее, paused наиболее безопасный); словарь scope-видов {tenant, connector, channel, service, policy_outcome, autonomy_class, campaign} с честной валидацией refs: tenant = собственный tenant_id (равенство материально — объект чужого тенента выбрать НЕЛЬЗЯ, AC-1), connector = живой реестр коннекторов тенента 1-8 через порт (нерезолвящийся → отказ с честной причиной, fail-closed), channel = слово словаря девяти каналов cases (зеркало + контракт-пин), policy_outcome = слово словаря исходов 2-6 (зеркало + пин), autonomy_class = слово FR-42 пяти слов (зеркало против action-домена 3-1 + пин), service/campaign = charset [a-z0-9._-] 1..120 честной границей (реестров нет — словари придут с будущими модулями; невозможность резолюции НЕ расширяет допуск); ScopedControl — scope-пара (kind, ref), mode, причина, actor, prev_mode, generation, окно [scheduled_start, expires), состояние active/removed; вычисление Effective: активные controls маршрута (now в окне — чтение-временная семантика: scheduled в будущем не действует, истёкший не действует, идемпотентно по построению), ранг-максимум = наиболее ограничивающее пересечение, провенанс ВСЕХ повлиявших + итоговая причина (самое ограничивающее правило + слова пересечения); отсутствующие controls = accept (маршрут не ограничен); испорченное/неизвестное значение при чтении → наиболее безопасный применимый (paused, fail-closed чтением); поколения монотонны на КАЖДОЕ изменение состояния (установка И снятие — оба поднимают generation) и НИКОГДА не сбрасываются; конкурентность: ExpectedGeneration (оптимистичная; вторая попытка = conflict, материал состояния возвращается оператору, история НЕ теряется); RuleError/ErrInvalid-паттерн 1-8. ## Boundaries & Constraints

**Always:** модуль internal/control рождается по AD-2/AD-12/AD-13/AD-16 (api/app/domain/port/store + миграция; словари compile-time, расширение рантаймом/конфигом тенанта NEVER); слова режимов ТОЧНЫЕ: accept, intake_only/no_promises (дословно, слэш — часть слова), human_only, paused; лестница ограничительности = порядок перечисления AD-12, paused наиболее безопасный; пересечение = ранг-максимум с провенансом всех повлиявших и итоговой причиной; испорченное/неизвестное значение mode при чтении → paused (наиболее безопасный применимый; зонд прямой записи в БД); generation монотонен на каждое изменение состояния (set И resume), НИКОГДА не сбрасывается; оптимистичная конкурентность ExpectedGeneration: конфликт → audit outcome='conflict' с материалом актуального состояния, изменение НЕ применяется, история обеих попыток сохранена; окно [scheduled_start, expires) — чтение-временная семантика: scheduled-будущее не действует, истёкший не действует, истечение идемпотентно by construction, «возврат к предыдущему явно вычисленному effective mode» = пересчёт по оставшимся (НЕ сохранённый снимок); гейты мутаций ПО ПОРЯДКУ: membership-404 → скоуп operations 403 словами ДО материала → step-up (StepUpVerified, ErrStepUpRequired) → причина обязательна; гейты чтения поверхностей: membership-404 → скоуп operations (страница и API оператора); ## I/O & Edge-Case Matrix

- Given оператор со скоупом operations (step-up подтверждён, причина валидна), when POST set на scope (connector своего тенента, режим human_only), then 200: state=active, generation=1, audit applied, outbox-строка; карточка показывает режим словом, владельца, время, поколение, причину — AC-1/AC-4.
- Given не-участник тенента / чужой тенент, when любые пути controls, then 404 ДО материала (membership-гейт; RLS слепота зеркалом).
- Given участник без скоупа operations (configurator/integration_admin/expert_qa), when чтение/мутация, then 403 СЛОВАМИ скоупа ДО материала — AC-1.
- Given StepUpVerified=false, when POST set/resume, then step-up-отказ (403 со словами подтверждения; прецедент membership) — AC-4.
- Given причина пустая/мусорная ИЛИ mode вне словаря ИЛИ scope_kind вне семи слов ИЛИ ref вне charset, when POST, then словарный отказ честной причиной (400-семейство), состояние НЕ меняется, audit НЕ пишется (недошедшие до конкурентности зонды — валидация ДО транзакции).
- Given два оператора меняют одну точку concurrently (expected_generation обоих = 0), when оба POST set, then ровно один applied (generation=1), второй conflict с материалом актуального состояния; ОБЕ строки в audit (applied + conflict); второму интерфейс показывает актуальное состояние и требует повторного подтверждения — AC-11.

## Implementation Notes

- Слова режимов — дословные из AD-12/FR-32: `intake_only/no_promises` со слэшем — одно слово, НЕ два; переименование в intake_only запрещено зеркальной дисциплиной (контракт-тест пинит точную строку).
- Полярность словарей: control-режимы {accept, intake_only/no_promises, human_only, paused} — НЕ разговорные режимы 2-5 {safety..sales} и НЕ autonomy FR-42 {shadow..exception}; домен документирует различие, страница не смешивает понятия (autonomy_class — лишь один из scope-видов).
- Истечение идемпотентно by construction: effective вычисляется по живым записям и окну каждый раз — «возврат к предыдущему явно вычисленному» = пересчёт без истёкшей точки, снимков НЕ храним; фоновая материализация событий истечения — с воркерами 3-3+.
- Generation — не версия данных, а версия СОСТОЯНИЯ точки: снятие тоже поднимает; монотонность навсегда закрывает обман stale-детекции будущего (переустановка не совпадёт со старым поколением).
- Конкурентность: SELECT FOR UPDATE по UNIQUE scope-паре сериализует транзакции; вторая пишет audit-conflict и возвращает материал — «должен подтвердить изменение повторно» = UI показывает актуальное состояние рядом с формой.
- resume НЕ удаляет строку (state=removed): история точек остаётся читаемой, аудит полной, re-set продолжает поколение.
- connector-референс — единственный живой внешний реестр в срезе: порт консьюмер-owned (прецедент packresolver 3-1), адаптер над connector-каталогом в composition root; service/campaign честно charset-валидны без реестра (граница документирована в коде и на странице).
- Пустое состояние страницы — с причиной словами: «активных controls нет — маршруты не ограничены» (честный ответ, НЕ пустая заглушка).
- Опасные режимы: paused и human_only требуют явного чекбокса в UI (AC-12) — серверная защита = step-up + причина (двойная дисциплина честно задокументирована).
