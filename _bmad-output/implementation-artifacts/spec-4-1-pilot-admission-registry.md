## Intent

**Problem:** Между платформенным readiness-контуром 1-13/1-14 (словарь gateDictionary из восьми определений {OQ-11, OQ-12, OQ-13B, OQ-14, OQ-7B, AG-1, AG-2, …} — пилотные гейты Олега туда СОЗНАТЕЛЬНО не вошли: «Tenant-specific pilot gates (OQ-1..OQ-10, OQ-19, AG-3…) stay project-planning artifacts — deliberately not carried into the product surface») и стартом Epic 4 «Эксперт по автозапчастям магазина Олега» отсутствует сам РЕЕСТР ДОПУСКА пилота: пилотные гейты Олега {OQ-1 телфония, OQ-2 Jivo-семантика, OQ-3 ABCP-заказ, OQ-4 ABCP→1С, OQ-5 применимость, OQ-19 State/Authority Matrix, AG-4 runtime credentials} существуют только в Markdown/JSON планировочных артефактах — владельцу неглядно, системе неизвестно; маршрутная матрица пилота (текст/голос × Jivo/SIP, ABCP/Laximo, 1С, Human Inbox, fallback со стадиями допуска — AC-11) нигде не выводится машинно; трёхстадийность candidate/verified/admitted (AC-13) не определена и не различается; capability-требования probe-наборов Jivo (AC-3: inbound, outbound, media, delivery status, назначение человеку, acknowledgement, one-writer, fallback), ABCP read-only (AC-7) и ABCP order (AC-8) не декларированы в каталоге connector — jivo-chat 1.0.0 и abcp-parts 1.0.0 висят пустыми StatusDeferred без единой CapabilityDeclaration; SIP probe-набор AC-6 (transfer/bridge, callback, DTMF, playback/delivery, failure states) не заявлен; State/Authority Matrix ABCP→кастомная 1С (AC-10) не существует как machine-читаемый объект; правило «отсутствующее или устаревшее доказательство блокирует ТОЛЬКО затронутый маршрут» (AC-12) нечем исполнить — нет ни маршрутов, ни пер-маршрутной деривации; «production credentials запрещены до AG-4» (AC-2) платформенно закрыто 1-8, но неглядно в плоскости пилота.

**Approach:** Модуль `internal/employee` — расширение readiness-контура 1-13/1-14 (таблица возможностей архитектуры: «Employee setup, Domain Pack, profile, release → employee»; единственный модуль, видящий все три источника вывода: собственные gate-инстансы, connector-факты через существующий узкий порт ConnectorFacts, Domain Pack pin sealed-манифестов). Пилотный admission = чистая READ-TIME функция над записанным: расширение gateDictionary семью пилотными определениями по канону GATE-REGISTRY (ID, criticality, owner-роли словами реальных владельцев Олега, evidence-требование, safe state — зеркало пиннится тестом против канона), compile-time словарь маршрутов пилота 6 слов с required capabilities/gates, compile-time State/Authority Matrix ABCP→1С, лестница деривации стадий {candidate → verified → admitted} с honest-словами блокировок; расширение каталога `internal/connector/catalog` тремя новыми версиями определений с полными CapabilityDeclaration. Поверхности: машинный GET + страница «Пилот автозапчастей» + OpenAPI. Испытания unit/интеграционная матрица живой PG/journeys z38. Без AI Runtime (AG-4), без адаптеров Jivo/ABCP, без миграций, без записей.

**Ядро честности среза:** admission — ВЫВОД, а не запись: НИ ОДНОЙ строки ни в одну таблицу из admission-пути (счётчики фейк-репо на нуле; gate-инстансы создаются СУЩЕСТВУЮЩИМ test & release контуром 1-13, не срезом), повторный запрос = тот же вывод; все словари compile-time (маршруты 6, гейты +7, матрица 1С, capabilities каталога — зеркала пинятся контракт-тестом, drift = красный); стадии честны: candidate ≠ verified ≠ admitted, любое open/in_test/fail/expired/missing-гейт-инстанс = НЕ admitted (fail-closed — safe state гейта словами GATE-REGISTRY), неизвестное состояние = unknown; «название продукта или общая документация не считаются доказательством capability аккаунта» (AC-3 хвост) СТРУКТУРНО: verified выводится ТОЛЬКО из живой capability evidence 1-9 (derived states), декларация каталога даёт максимум candidate; отправка поставщику в пилоте не выполняется и не декларируется (supplier_form/send вне словарей — fence), автоматическое создание заказа заблокировано до OQ-3 PASS (parts_order_abcp требует гейт + fence-слова); Mango Office — кандидат, предположения не переносятся (OQ-1 open = голосовой маршрут blocked честным словом «провайдер не подтверждён фактическими данными аккаунта»).
