## Intent

**Problem:** Деградации маршрута не существует ни в каком виде: слова канала/коннектора «timeout, disconnect, rate limit, revoked capability, неоднозначный delivery outcome» (AC-блок 1) некуда записать — ни таблицы, ни словаря причин, ни команды; «затронутый route получает отдельное degraded-состояние» нечему нести — ни слота на маршрут, ни ревизий, ни деривации восстановления; «независимые маршруты не объявляются недоступными без доказательства» не закреплено нигде — сегодня любое суждение о доступности канала живёт только в голове оператора и не является строкой кейса. Delivery-статус исходящего ответа молчит (AC-блок 2): client_reply_outcomes несёт ровно dispatched|stale_needs_review (2-4: «the real channel delivery is the deferred outgoing story» — реальная доставка честно отложена именно на эту историю) — «результат становится unknown, а не delivered» нечему выражать: нет ни evidence-таблицы, ни деривации состояния доставки, ни честного слова «квитанции нет»; «сообщение не повторяется вслепую» держится только однозаписностью drain, но машинного контура решения «reconciliation либо человек» не существует. Degraded Mode Policy отсутствует (AC-блок 3): правило-таблица 2-6/2-11 не знает состояния маршрутов — «разрешённый outcome ограничен вариантами» нечему ограничивать: коммерческий интент на сбойном маршруте сегодня свободно даёт commercial_answer (обещания на деградированном канале!), словарь путей {принять информацию без обещания, переключить на проверенный канал, запросить Human Handoff, согласовать callback, остановить путь} не существует, «выбранный вариант сохраняет причину и rule version» нечему нести. Обещание времени следующего обновления отсутствует (AC-блок 4, FR-17, FR-41): «сообщает время следующего обновления только в пределах утверждённой policy» — ни словаря обещаний, ни гейта, ни поля в reply; оператор может написать в ответе что угодно (включая выдуманное «заказ уже оформлен»), и машина не держит честность тайминга структурно (2-11 явно отложил timing-контур в Never: «не обещать время следующего обновления — story 2-12»). Таймлайн причины молчит (AC-блоки 1/9): строки деградации и delivery-evidence как видимые строки истории кейса отсутствуют — «Timeline показывает фактический результат и время» нечему показывать.

**Approach:** Первый срез — детерминированный серверный контур деградации маршрута + честный delivery-статус + обещание времени обновления (прецедент 2-5…2-11: AI Runtime в контуре НЕТ; продюсер размечает — машина гейтит). Пять частей: (1) словари Domain Pack v0: причины деградации маршрута {timeout, disconnect, rate_limited, capability_revoked, delivery_unknown} (AC-блок 1 дословно); слова разрешённых путей degraded-режима {accept_info_no_promise, verified_channel_switch, human_handoff, agree_callback, stop_path} (AC-блок 3 дословно: принять информацию без обещания / переключить на проверенный канал / запросить Human Handoff / согласовать callback / остановить путь) с фиксированными честными текстами (по одному на слово — рендер панелью, в БД только слова; «модель не может самостоятельно расширить этот набор» — словарь compile-time); слова обещания времени обновления {no_promise, within_1h, within_4h, within_next_business_day} с честными текстами (словарь = утверждённая policy v0: время следующего обновления — только слово словаря); слова delivery-evidence ответа {delivered_confirmed, delivery_unknown, provider_failed} (квитанция подтверждена / таймаут-неоднозначность / терминальный отказ провайдера); DeriveCurrentDegradations — read-time деривация latest-per-route (ключ маршрута = connection_id + channel — прецедент «независимые маршруты»: деривация честно по ключу, соседний маршрут не тронут; cleared-ревизия восстанавливает маршрут; прецедент DeriveCurrentAccommodations 2-11 / DeriveContinuationLinkState 2-10); DeriveReplyDeliveryState — read-time (последнее evidence-событие; dispatched без событий → unknown — «результат становится unknown, а не delivered» (AC-блок 2): dispatched 2-4 — честная запись записи, НЕ доставка; без исхода drain → prepared — истина 2-4); гварды записи; (2) append-only `cases.route_degradations` (tenant, case, route, connection, channel CHECK-словарь 2-1, cause CHECK-словарь, revision — UNIQUE (tenant, case, connection, channel, revision) монотонность, note ≤500, cleared, actor, recorded_at; ## I/O & Edge-Case Matrix

- Given кейс in_work и оператор review, when record_route_degradation (cause=timeout, ревизия 1) на маршруте диалога, then append-only строка + outbox (route/revision/cause/cleared, без note); панель: секция «Состояние маршрутов» несёт слово причины и время; текущий слот маршрута деградирован (AC-блок 1).
- Given в кейсе второй маршрут (иной connection или канал), when запись деградации первого, then слот второго НЕ тронут (деривация по ключу маршрута — «независимые маршруты не объявляются недоступными без доказательства», AC-блок 1).
- Given cause=delivery_unknown (оператор передал неоднозначный delivery-наблюдение коннектора), when запись, then принимается словарём причин (AC-блок 1 «неоднозначный delivery outcome»).

## Implementation Notes

- Маршрут = (connection_id, channel) — слот деградации скоупа кейса; страж требует существования маршрута в разговорах кейса; независимые маршруты честно не тронуты (деривация по ключу; зонд матрицы).
- Словарь путей degraded-режима НЕ фильтруется по capability (реестра проверенных каналов нет; v1 = весь словарь пака — честная граница, прецедент active_alternatives 2-11); verified_channel_switch — слово-путь, проверка канала будущим контуром коннекторов.
- Вопрос-план остаётся в degraded-исходе: вопросы — не обещания; текст исходящего сообщения о сбое выбирает продюсер из словарных честных текстов путей/обещаний (машина гейтит слово, не парсит текст).
- Гейт тайминга безклассовый: деградация маршрута касается любого исходящего сообщения кейса на этом маршруте (AC-блок 4 «короткое сообщение» может быть neutral/protected/sales).
- Digest v3: input_snapshot канонически расширен картой деградаций; та же тройка входов → тот же дайджест; исторические строки v1/v2 не пересчитываются (append-only читаемость); literal-дайджесты в тестах не хранятся (сравнение вычисленных значений — прецедент 2-6).
- Derived default unknown после dispatched — «результат становится unknown, а не delivered» (AC-блок 2): dispatched (2-4) — честная запись записи, НЕ доставка; слово delivered_confirmed — только evidence-наблюдение.
- Delivery-evidence события монотонны (event_no): история наблюдений читаема; последнее событие = состояние (прецедент DisclosureDeliveryEvent 2-5); оператор = передатчик наблюдения коннектора (прецедент ConfirmerOperatorRelay 2-2).
- Гонки: запись деградации/evidence и оценка исхода — один сортированный advisory-lock-план (case+conversation); request-hash записи включает весь материал (note/kind); replay до стражей.
- Privacy: обе таблицы — case-operations; чтение review/audit, команда review; TestPerimeterIntegrity синхронно; note и content в outbox никогда.
- Контрольная ветка: пустая карта деградаций → policy/reply пути идентичны прежним (решение байт-в-байт; tests 2-6/2-8/2-11 не меняются кроме механических расширений формы snapshot/rule_version через константы домена — честная запись в Change Log).
- a11y: select'ы причины/вида evidence/обещания без preselect/без autofocus; формы required с явными label; ошибки — текст + фокус к описанию; 320px single-column; статусы словами не цветом; секция маршрутов aria-live=polite (прецеденты 2-9/2-10/2-11).
