## Intent

**Problem:** Между «Recovery Case создан и назначен» (3-8: строка кейса, события, назначение живыми чтениями, панель с живой деривацией цепочки квитанций) и «ограниченными действиями Staffy во время Recovery» (FR-39, AC-блоки 1-13 эпика 3.9) отсутствует сама ПОЛИТИКА: системе нечем ответить на вопрос «что Staffy вправе делать с этим кейсом?» — конечный набор разрешённых recovery-действий не существует как выводимый объект, условия каждого действия (scope, eligibility, требуемые факты, authority, Confirmation) нигде не объявлены машинно; human-only решения (вина, юридическая ответственность, нестандартная компенсация/возврат/исключение) не перечислены отдельно от разрешённого набора; правило «отсутствующее либо неоднозначное правило означает human_only» нечем исполнить — fail-closed классификации нет; «текст модели не добавляет новый вариант» нечем гарантировать структурно — набора неоткуда читать, будущему planner нечего валидировать; панель 3-8 показывает историю, назначение и дедлайн, но не границы действий оператора и модели.

**Approach:** Модуль `internal/action` (таблица возможностей архитектуры: «Business mutation, receipt and recovery → action + connector»; AD-2 DAG без новых рёбер — живые чтения reused: собственный стор кейса/операции, каталог определений, scoped controls 3-2, факт композиции AG-4). Политика = чистая READ-TIME функция над записанным: compile-time словарь видов 5 + human-only класс 2 + декларированные атрибуты вида; лестница вывода состояния каждого вида {allowed/blocked/human_only} с honest-словом причины; поверхности машинная и панельная; испытания unit/матрица/journeys. Без AI Runtime (AG-4), без записей (миграции нет), без адаптеров (локальный контур).

**Ядро честности среза:** политика — ВЫВОД, а не запись: НИ ОДНОЙ строки ни в одну таблицу (таблиц среза нет структурно), повторный вызов = тот же вывод; НИ одного сетевого вызова в пути (reflect-зонд сигнатур — сеть остаётся в dispatch 3-6/reconcile 3-7); human-only границы — СЛОВАМИ отдельно от набора; отсутствующее/неоднозначное правило = human_only (fail-closed: offer_approved_options честно human_only — вариантов в конфигурации нет); unknown остаётся unknown (статусные слова = локальная проекция 3-8, внешнее состояние не изобретается); материальные виды помечены Confirmation-требованием декларативно, исполнение видов — будущие срезы.

## I/O & Edge-Case Matrix

- Given открытый кейс unknown-операции (trigger reconciliation_exhausted) с назначением и определением каталога LIVE CancelCompensationSem, when GET policy, then набор: show_recorded_conditions allowed (surface=карточка), truthful_status_update allowed (status-слова 3-8 + дедлайн словами), request_evidence allowed (confirmation required), prepare_pause_cancel allowed (LIVE-семантика объявлена), offer_approved_options human_only («утверждённых вариантов нет — решение за человеком»); human-only класс перечислен отдельно — AC-1/AC-2.
- Given определение каталога БЕЗ CancelCompensationSem (пустая семантика), when policy, then prepare_pause_cancel human_only либо blocked честным словом «pause/cancel семантика не объявлена каталогом — подготовка за человеком» — fail-closed AC-1 хвост.
- Given ошибка чтения определения каталога, when policy, then зависимый вид human_only, политика 200 (вывод не отказывает — право ограничивается), НИ ОДНОЙ записи — fail-closed.
- Given paused tenant либо paused connector живым чтением scoped controls, when policy, then материальные виды {request_evidence, prepare_pause_cancel} blocked ТОЧНЫМ словом scoped control; read-only {show_recorded_conditions, truthful_status_update} остаются allowed — «приостановленный контроль блокирует материальное действие, чтение остаётся».
- Given offer_approved_options всегда, when policy, then human_only: «утверждённых вариантов решения в конфигурации нет — только человек» — отсутствующее правило = human_only (AC-1 хвост материализован).
- Given production AG-4 (nil-адаптер сверки), when policy, then статусные слова честны («сверка не подключена» в фактах вида), набор выводится, политики не блокирует — AG-4 — факт композиции.

## Implementation Notes

- Решение модуля: политика — read-time вывод модуля action над записанным (AD-2; таблица возможностей «Business mutation, receipt and recovery»); записей НЕТ — миграция отсутствует ОСОЗНАННО (первый срез Epic 3 без SQL): состояние вида не хранится, каждый запрос выводит заново; идемпотентность выводом (прецедент DeriveRecoveryEligibility/OperationState — read-time деривации семейства).
- Прецеденты повторного использования: лестницы домена (DeriveRecoveryEligibility 3-8), чтение scoped controls (reconcile.go EffectiveFor + точное слово paused — 3-7), чтение def/LIVE-слов (recovery.go catalogDefinition/capabilityFacts — 3-8), AG-4 факт композиции (s.reconcileAdapter != nil — eligibility 3-8), membership-404 до материала (3-6/3-7/3-8), honest-пустые секции и details-дисциплина (3-4/3-8), journeys-репин замороженных слов при расширении поверхности (правило 161, z36 прецедент).
- Долг 3-7 «recovery-scope-разрешения сверки при paused» НЕ разворачивается: политика читает paused-слово и блокирует материальные виды, но поведение команды reconcile не меняется (замороженная секция 3-7) — разворот по явному поручению владельца будущим срезом.
- Human-only класс — слова границы PRD FR-39 дословно («вина, юридический вывод и нестандартный возврат/компенсация требуют человека»); ингресс claim-режима (AC-3) остаётся будущим срезом с потребителем события recovery_case.created (копится pending — прецедент 3-8).
- AC-2 «текст модели не добавляет новый вариант» исполняется СТРУКТУРНО: генеративного пути нет (AG-4 — AI Runtime отсутствует), набор = вывод детерминированного кода; будущий planner получит политику как машинный вид для валидации своих предложений (задел API-поверхностью среза).
