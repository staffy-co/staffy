## Intent

**Problem:** Дисциплина обещаний обновления не существует (AC-блок 2, FR-41): система не хранит «следующий update time» и ответственного за обновление во время ожидания человека; ack_deadline 2-13 — срок ПРИНЯТИЯ раунда (принял ли назначенный специалист), НЕ срок обновления для клиента — это разные обещания с разными владельцами честности; неизвестный срок сегодня нечем записать вовсе: любое число было бы выдуманным обещанием (FR-41 «отсутствие подтверждённого ETA называется прямо» — материального слова для этого нет). Клиентского статуса ожидания нет (AC-блок 1): операторская карточка 2-13 видит lifecycle-слова, но честного КЛИЕНТСКОГО текста тремя различениями («ищем специалиста» / «назначен, ожидаем принятия» / «специалист принял обращение») не существует — состояние выводится живыми деривациями, а слов для клиента нет; персональные и технические сведения (имена операторов, эпохи, идентификаторы) сегодня нечем ЗАПРЕТИТЬ в клиентском тексте — периметра словаря нет. Просрочка обещания невидима (AC-блок 3, частично): слово overdue существует у РАУНДА (deadline_at принятия истёк), но у обещания ОБНОВЛЕНИЯ просрочки нет — нечем честно показать «обновление просрочено, решения ещё нет»; перевод раунда в resolved обновлением не запрещён материально (гварда нет — обещание как запись отсутствует); эскалация/переназначение по Operating Profile — будущий контур, но честная видимость просрочки оператору и клиенту нечем обеспечить уже сейчас. Поверхности: формы обещания нет, строки обещания и статуса ожидания на странице кейса нет.

**Approach:** Первый срез — ОДНА новая append-only запись (обещание обновления раунда handoff) + ДВЕ read-time деривации (клиентский статус ожидания; состояние обещания) + операторская PRG-форма на карточке handoff. Шесть частей: (1) домен waiting_update.go: словарь дедлайн-слов {update_15m, update_1h, update_4h, update_unknown} — update_unknown = обещание БЕЗ выдуманного срока (promised_at NULL — зонд пиннит: слово unknown не может нести timestamp, вычисленный срок — серверная истина от now, НЕ поле запроса); GuardPromiseUpdate (дедлайн-слово словаря; якорь раунда — открытый lifecycle ЭТОГО кейса проверяет стор, домен гейтит слово); DeriveUpdatePromiseState — read-time последняя обещание говорит (pending / missed / unknown-deadline / superseded для прежних / closed по закрытию раунда; missed = now > promised_at && раунд открыт — строка НИКОГДА не мутируется); DeriveClientWaitingStatus — состояние раунда в честный клиентский текст ТРЁМЯ различениями AC-1 (requested → «ищем специалиста», assigned → «назначен, ожидаем принятия», acknowledged → «специалист принял обращение», overdue → честный текст просрочки принятия словарём 2-13) — ТОЛЬКО словарные слова и тексты: имена операторов/эпохи/UUID НИКОГДА (анти-раскрытие AC-1); ## Boundaries & Constraints

**Always:** таблица handoff_update_promises append-only — гранты INSERT/SELECT, RLS + FORCE, UPDATE/DELETE/TRUNCATE нет; UNIQUE (tenant, case, promise_no) — монотонность, обещание никогда не правится;
