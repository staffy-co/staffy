## Intent

**Problem:** после записанного выбора клиента (Selection Snapshot 4-5 с пинами четырёх входов) заказ не существует как действие: нет точной версии заказа для подтверждения клиентом (пины всех пяти входов + позиции + слово менеджерской проверки — FR-56 «после каталогической проверки и Confirmation клиента Staffy должен создать один клиентский Order ABCP»), каталог действий продуктов пуст (3-1: «honestly empty» — комментарий устарел: декларация 4-1 abcp-parts@1.1.0 уже несёт command.prepare-client-order), preview не несёт слова менеджерского забора и ожидаемого перехода pending_manager_verification, execute-time revalidation 3-6 не сверяет версии ПЯТИ внутренних входов заказа (только confirmation-fence + freshness внешнего материала), receipt не отображает состояние заказа и назначение менеджера, производственный забор AG-4 не рекомендует decision-ready задачу словом причин, клиенту нечего сказать о созданном заказе («создан в магазине и ожидает проверки менеджером»), проекция 1С не обозначена честным unknown.

**Approach:** модуль action (действие проходит ТОЛЬКО через Action Gateway — AC-4): канонический OrderCommitment-материал как typed input предложения (оператор НЕ сочиняет материал — app-билдер выводит его из живого CaseView: выборы 4-5 + текущие деривации пяти входов) + OrderDigest (SHA-256 канонического состава: пины ProfileDigest/PartRequestDigest + per-позиция {FitmentDigest, OfferDigest, SelectionDigest, OEM/артикул, оригинал/аналог, количество, клиентская цена, известные условия} + известная сумма + слово менеджерской проверки) + первый продуктовый definition create_abcp_customer_order@1.0.0 в binary-каталоге (адмиссия живьём против packresolver auto-parts@6.0.0 + capabilityresolver abcp-parts@1.1.0/command.prepare-client-order, Idempotent=true → CapabilityClass provider_idempotent) + подтверждение действующей машиной 3-4 (ConfirmPreviewVersion step-up; старая версия → superseded BY NAME) + НОВЫЙ порт OrderVersionSource в лестнице диспетчера 3-6 (живая ре-деривация OrderDigest ДО lease — расхождение = dispatch_blocked с точным словом; nil = fail-closed) + receipt-рендер с производным словом состояния pending_manager_verification и словом назначения менеджера + производственный nil-адаптер (AG-4) с рекомендацией слова order_creation (миграция 00025 reason 6→7) + слова клиенту и 1С-unknown на панели квитанции + eval-матрица синтетическим контуром поимённо.

**Ядро честности среза:** заказ создаётся ТОЛЬКО после явного подтверждения точной версии (ConfirmPreviewVersion step-up; неопределённое согласие и старая версия не авторизуют — состояние superseded/expired/revoked выводится BY NAME); в материале заказа ОБЯЗАТЕЛЬНО слово «заказ сначала будет проверен менеджером и ещё не отправляется поставщику» (AC-1); typed-схемы определения НЕ содержат ни одного поля отправки/формирования поставщику (fence OQ-3: supplier_form/send отсутствует в Action Catalog — «passing OQ-3/OQ-5 does not authorize supplier-send»; SPINE: Staffy may create only the exact-version ABCP client/prepared order after customer Confirmation); execute-time revalidation ПЯТИ пинов живой ре-деривацией ДО lease — любое существенное изменение останавливает dispatch и требует обновлённого подтверждения (AC-5); идемпотентность операции стабильна (HMAC-ключ над {tenant, operation_id} — повтор доставки НЕ создаёт второй заказ, AC-6); результат НЕ считается успешным по транспортному ответу — только по квитанции с внешним ID/версией/временем и подтверждённым состоянием (AC-7/AC-8); unknown → reconciliation существующей машиной 3-7 (слепой повтор запрещён — park_unknown); дубликат → сохранённый Receipt (AC-11); частичный/противоречивый результат → Recovery Case машины 3-8 (AC-12); производственный забор: мутационный адаптер НЕ wired (AG-4: AdapterImplemented false) — dispatch_blocked честным словом + рекомендация decision-ready задачи order_creation (панель рекомендует, оператор создаёт запрос существующей машиной 2-13); скрытая автоматизация интерфейса ABCP как неподтверждённая замена capability НЕ используется (AC-9); клиенту сообщается «заказ создан в магазине и ожидает проверки менеджером» — НЕ «заказан у поставщика, выкуплен, отправлен, гарантирован» (AC-14); проекция 1С — unknown/pending: создание ABCP Order НЕ объявляется успешной синхронизацией с 1С (AC-13, OQ-4/OQ-19); подтверждение и исправление — РАЗНЫЕ понятные действия клиентской поверхности (AC-16); молчаливых исправлений НЕТ ни в одном пути.
