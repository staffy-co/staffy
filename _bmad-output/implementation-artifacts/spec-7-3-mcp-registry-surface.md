## Intent

**Problem:** Epic 7 открывает стандартизованную инструментальную поверхность ядра, но после 7-2 она существует только как HTTP-словари оператора: внешний потребитель (MCP-клиент) не может интегрировать платформу стандартным способом — (1) протокольной поверхности MCP нет: ни negotiate/list/call, ни пиннинга ревизии протокола, ни её транспортных правил; (2) исполнение tool-вызовов не существует вовсе (7-2 сознательно: регистрация контракта ≠ доступность вызова) — путь вызова «через внутренний контракт реестра 7-2, а не отдельным путём» не построен и не доказан; (3) динамическая половина AC-3 спеки 7-2 (capability-probe: evidence живости зависимости, stale при ротации) отложена на этот срез — гейта экспозиции по живым доказательствам нет; (4) сессионная дисциплина MCP-поверхности (tenant-scoping, изоляция, rate/budget, аудит вызовов) не определена; (5) будущий основной потребитель — Planner Epic 8 (story 8.3 «tool-rounds над реестром 7-2») — не имеет подтверждённой формы вызова, под которую строился бы рантайм.

**Approach:** первый срез — протокольная машина поверхности без живых адаптеров: единый машинный endpoint POST /v1/tenants/{tenant_id}/mcp поверх субстрата 7-2, пиннинг ТЕКУЩЕЙ ревизии протокола MCP 2026-07-28 (stateless-ядро — протокол удалил handshake и сессии; server/discover; заголовки Mcp-Method/Mcp-Name; версия протокола в _meta + MCP-Protocol-Version), реализованный stdlib без SDK и внешних зависимостей. Гейт экспозиции = честное пересечение трёх фактов (артефакт implemented ∧ рантайм-адаптер зарегистрирован ∧ зависимость жива по словарю состояний 1-8). Путь вызова = пин-чтение контракта каталогом 7-2 + strict-валидация входа И выхода по платформенному словарю типизации + Adapter-порт с ctx-бюджетом и tenant-скоупом сессии. Продакшн регистрирует НОЛЬ адаптеров (AG-4 — callable set честно пуст), вся машина доказана fixture-миром journeys со scripted MCP-клиентом живьём по протоколу.

**Ядро честности среза:** (1) write через MCP структурно невозможен: экспонируемое множество ⊆ реестр 7-2 ∩ deterministic_read (словарь единственного значения) ∩ implemented ∧ зарегистрирован ∧ зависимость жива; MCP-слой не создаёт инструментов и не расширяет словари — гарантия AD-6/AD-7 машинальна, не ревью (AC-3). (2) Capabilities = факт, не больше: tools only, listChanged=false; resources/prompts/sampling/elicitation не заявляются; server/discover отвечает поддерживаемыми версиями ровно [2026-07-28] — handshake-эпоха (клиенты ≤2025-11-25) честно НЕ поддерживается (отказ со списком; backward-compat — deferred-work). (3) Ноль живых адаптеров: все 3 контракта реестра остаются not_implemented — не выставлены и не вызываемы (двойная честность 7-2 сохранена); гейт и путь вызова покрыты implemented fixture-контрактом в тест-контуре. (4) Вход И выход валидируются по контракту: неизвестный ключ, неверный тип, значение вне enum/границ = поимённый отказ; выход адаптера с undeclared-ключом = ошибка, не passthrough — секреты и внутренние материалы не пересылаются (AC-2). (5) Лестница членства ДО протокольного материала: не-member 404, member без скоупов 403 словами — до единого байта JSON-RPC. (6) Аудит вызовов — append-only поток структурных slog-строк; durable PG-гроссбух — deferred-work с честной причиной (в продакшне вызываемых инструментов ноль). (7) AC-2 честно частично: аутентификация = существующий порт PrincipalResolver (продакшн-резолвер платформенно не существует — AG-4, контур development/loopback); OAuth 2.1 MCP-авторизация и entitlement-бюджеты — deferred-work.

## Boundaries & Constraints

**Always:** (1) Реестр tools 7-2 — ЕДИНСТВЕННЫЙ источник контрактов MCP-поверхности: пин-чтение id@version через каталог (клон-дисциплина); MCP-слой проецирует, но не создаёт и не расширяет; структурный тест: экспонируемое ⊆ реестр ∩ deterministic_read ∩ implemented (AC-3, write структурно невозможен). (2) Лестница членства FIRST в сервисе MCP (прецедент 3-1/7-2 дословно): нет личности = 401 резолвера; не-member = честный 404; member без integrations|configuration = 403 со словами скоупов ДО материала; малформед tenant-путь = 404. (3) Протокол пиннут ревизией 2026-07-28 (current): initialize/initialized и Mcp-Session-Id не реализуются (удалены протоколом); server/discover — обязательный метод (поддерживаемые версии, capabilities, serverInfo); версия протокола — в _meta каждого запроса + заголовком MCP-Protocol-Version (рассинхрон = invalid request 400); чужая ревизия = JSON-RPC ошибка UnsupportedProtocolVersionError со списком ровно [2026-07-28]; JSON-RPC 2.0 одиночным сообщением (batch = invalid request); точные имена wire-полей Dev закрепляет поимёнными контракт-тестами по живому чтению официальной схемы ревизии. (4) Транспорт Streamable HTTP: POST Content-Type application/json (иной = 415); заголовки Mcp-Method/Mcp-Name сверяются с телом (рассинхрон = 400); ответы application/json (SSE-стримы не строятся — сервер не инициирует); GET/DELETE = 405; notification (без id) = 202 Accepted без тела; протокольные ошибки = 200 + JSON-RPC error; HTTP-ошибки лестницы/транспорта = problem-контракт платформы. (5) Гейт экспозиции fail-closed: артефакт implemented ∧ адаптер зарегистрирован ∧ (зависимости нет ∨ живое подключение connector_type: state verified ∃ ∧ failed/stale ∅ — словарь состояний 1-8); гейт повторяется при call (TOCTOU честно); ротация зависимости → stale → инструмент исчезает из словаря. (6) Валидация аргументов по input_schema: закрытая форма (неизвестный ключ = поимённый отказ — strict decode платформы), типы string/integer/boolean (integer = число без дробной части), enum по values, границы min/max, обязательность; ошибки валидации = tool execution error (result isError=true) с поимёнными словами полей (SEP-1303), НЕ протокольная ошибка. (7) Выход адаптера валидируется по output_schema (fail-closed): undeclared ключ или неверный тип = tool execution error, не passthrough (AC-2: секреты и внутренние материалы не пересылаются); результат = structuredContent (типизированный выход) + content с пином <id>@<version>. (8) Адаптер: платформенный порт Adapter(ctx, tenant, arguments) — tenant ИЗ СЕССИИ (путь+лестница), никогда из аргументов; ctx-бюджет исполнения (декларированный таймаут); адаптеры вертикальны по природе — регистрируются composition root'ом (продакшн: НОЛЬ — AG-4) или тест-контуром. (9) Rate/budget декларированы и соблюдаются: тело ≤ 256 KiB (413), фиксированное окно запросов на принципала (429 + Retry-After), ctx-таймаут вызова, границы схем; аудит: slog-строка на каждый tools/call (code, tenant, principal, tool@version, verdict+причина, correlation_id). (10) Вертикальная чистота: internal/mcp — платформенный пакет протокола без вертикальных слов; drift-зона зонда расширяется пакетом mcp осознанной правкой (словарь фраз НЕ растёт); fixture-контракт с вертикальными словами — только тест-контур journeys.

**Never:** не реализовывать handshake-эпоху протокола (initialize/initialized, Mcp-Session-Id, SSE-стримы, batch) — чужие ревизии честно отклоняются со списком, backward-compat — deferred-work по реальному спросу; не вводить MCP SDK или внешние зависимости (stdlib encoding/json + net/http; пиннинг поимёнными тестами); не строить OAuth 2.1 authorization/resource-сервер MCP (продакшн-PrincipalResolver платформенно не существует — AG-4; аутентификация = существующий порт, 401 до материала); не регистрировать живые адаптеры трёх вертикальных контрактов (все not_implemented — двойная честность 7-2; первый живой адаптер = новая версия артефакта implemented + проводка composition root — будущий срез по реальному спросу, deferred-work); не строить PG-аудит-гроссбух и не подключать entitlement-бюджеты (deferred-work: с первым живым адаптером/принципалом; сегодня вызываемых в продакшне ноль); не менять internal/tools и его потребителей (субстрат 7-2 служит как есть — 0 правок пакета; 0 правок tools_catalog.go); не расширять RuntimeDictionary/tool_schemas и не пересчитывать sealed-манифесты (AD-10 — MCP-поверхность не касается манифестов); не заявлять capabilities сверх факта (resources/prompts/sampling/elicitation/listChanged=true запрещены — AC-1 «не больше реального»); не вводить страницу оператора (машинная поверхность; словарь оператора — страница 7-2); 0 SQL-миграций; не заявлять ttlMs/cacheScope (экспозиция зависит от живых доказательств — кэш-слова были бы ложью); не строить MCP-клиент (7-4 — обратное направление, класс Connector; scripted-клиент journey — тест-контур, не продакшн-код).

## I/O & Edge-Case Matrix

- Given запрос без личности (резолвер отказал), when POST /v1/tenants/{id}/mcp с любым методом, then 401 problem ДО протокольного материала (лестница FIRST)
- Given принципал — не-member тенента / member без скоупов, when POST, then 404 / 403 problem со словами скоупов ДО единого байта JSON-RPC (прецедент 3-1/7-2)
- Given корректный server/discover, then 200 result: поддерживаемые версии ровно [2026-07-28], capabilities {tools: {listChanged: false}}, serverInfo {name: staffy, version: 0.1.0 — зеркало info.version OpenAPI}; resources/prompts/sampling не заявлены
- Given запрос с версией протокола 2025-06-18 / 2025-11-25 (согласованной в _meta и заголовке), then 200 JSON-RPC ошибка UnsupportedProtocolVersionError со списком [2026-07-28] — handshake-эпоха честно не поддерживается
- Given _meta.protocolVersion ≠ заголовку MCP-Protocol-Version, then 400 invalid request (рассинхрон заявления версии)
- Given заголовок Mcp-Method или Mcp-Name ≠ method/name тела, then 400 (маршрутизация против тела — SEP-2243)
- Given Content-Type ≠ application/json / тело > 256 KiB, then 415 / 413 (декларированные бюджеты транспорта)
- Given notification (сообщение без id), then 202 Accepted без тела; отмена in-flight в stateless-развороте не гарантируется (202 без действия — честно)
- Given GET или DELETE endpoint, then 405 (стримов и сессий нет — ревизия 2026-07-28)
- Given batch-массив / малформед-JSON / envelope без method, then 400 + JSON-RPC parse error / invalid request
- Given неизвестный метод (resources/list, prompts/get, …), then 200 JSON-RPC -32601 MethodNotFound — capabilities не заявляли, отказ честный
- Given tools/list в fixture-мире (implemented-контракт + адаптер + verified-зависимость), then список ровно экспонируемых: name = registry id, title = Name, inputSchema/outputSchema = тотальная проекция словаря типизации, annotations.readOnlyHint = true; not_implemented-контракты реестра НЕ в списке
- Given tools/list тенента без живого подключения зависимости (кросс-тенент), then пустой массив (не null) — гейт закрывает честно
- Given ротация зависимости (fixture-тумблер → stale), when повторный tools/list, then инструмент ИСЧЕЗАЕТ из словаря (динамический capability-probe — закрытие динамической половины AC-3 спеки 7-2)
- Given tools/call валидного инструмента с корректными аргументами, then 200 result: structuredContent = выход, проверенный по output_schema; content несёт пин <id>@<version>; ауд-строка verdict ok
- Given tools/call с неизвестным ключом / типом не по словарю / вне enum / вне границ / пропущен обязательный, then result isError=true с поимёнными словами поля (tool execution error SEP-1303 — модель самокорректируется), НЕ протокольная ошибка
- Given tools/call неизвестного id или неэкспонируемого инструмента (not_implemented / адаптер не зарегистрирован / зависимость не жива), then честная tool execution error с причиной гейта поимённо
- Given адаптер вернул выход с undeclared ключом или неверным типом (fixture-тумблер), then tool execution error fail-closed — внутренний материал не пересылается (AC-2)
- Given адаптер превысил ctx-бюджет, then tool execution error «бюджет выполнения исчерпан» (rate/budget соблюдаются)
- Given burst поверх декларированного окна принципала, then 429 + Retry-After (окно соблюдается)
- Given продакшн-сборка (main.go: реестр адаптеров ПУСТ — AG-4), then tools/list = честный пустой массив, tools/call = честный отказ «адаптер не зарегистрирован»; протокол отвечает полноценно (discover/list/call — машина поверхности видна)
- Given вертикальные фразы словаря зонда (24 записи) в прод-.go internal/mcp (зона +mcp), then FAIL поимённо — платформенный пакет вертикально-чист, словарь фраз не растёт

## Implementation Notes

- Пинн ревизии: официальная спека MCP 2026-07-28 (modelcontextprotocol.io): stateless-ядро (SEP-2575 удалил handshake, SEP-2567 — сессии), обязательный server/discover, заголовки Mcp-Method/Mcp-Name (SEP-2243), кэш-слова ttlMs/cacheScope (SEP-2549) НЕ заявляются — экспозиция зависит от живых доказательств; Dev сверяет точные wire-имена полей по официальной схеме ДО контракт-теста; SDK не вводится — пиннинг поимёнными тестами вместо зависимости
- Handshake-эпоха (клиенты ≤2025-11-25): честный отказ версией со списком; backward-compat слой — deferred-work по реальному спросу внешнего интегратора (экосистема мигрирует на stateless-ядро)
- serverInfo: name «staffy», version «0.1.0» — зеркало info.version контракта OpenAPI (связь закреплена контракт-тестом; смена версии платформы = осознанный шаг в двух местах)
- Гейт зависимости: словарь состояний 1-8 {verified — PASS; failed/stale — отказ; unverified/unsupported/unknown — не доказано}; «действующий evidence» AC-1 = живое подключение типа ∧ verified ∃ ∧ failed/stale ∅; конкретная capability привязки контрактом 7-2 не декларируема (поля нет) — гейт на уровне подключения честен; уточнение поимённой capability — будущей версией контракта по спросу
- Адаптер: вертикален по природе (связывает контракт с машиной домена); продакшн-реестр адаптеров ПУСТ (AG-4 — прецеденты nil-адаптеров 3-6/3-7: поверхность отвечает, исполнение честно отказывает словами); первый живой адаптер = новая версия артефакта implemented + проводка composition root — по реальному спросу (Planner 8.3 / внешний интегратор)
- Аудит: slog JSON-строка (append-only поток stdout, correlation_id из платформенного middleware); PG-гроссбух — deferred: сегодня в продакшне вызываемых инструментов ноль, гроссбух без строк — по спросу с первым живым адаптером
- Rate: фиксированное окно на принципала в памяти (декларированная константа); в горизонтальном развёртывании окно делится внешним балансировщиком — честная граница (продакшн-разворот платформы не существует, AG-4)
- Изоляция: tenant из пути+лестницы; в схемах аргументов контрактов tenant-полей структурно нет; адаптер получает tenant параметром — не из аргументов (AD-11: скоуп из верифицированной личности, не из payload)
- Проекция словаря типизации в JSON Schema MCP: string→{type:string}, integer→{type:integer, minimum, maximum}, boolean→{type:boolean}, values→enum, !optional→required — тотальная 1:1, обратной проекции нет; реестр остаётся платформенным языком (Never 7-2 «json-schema.org не вводится» сохранён — проекция это провод MCP, не хранение)
- Форма вызова (AC-4, будущий потребитель Planner 8.3): пин id@version + типизированные аргументы/выход по словарю контракта + ctx-бюджет + fail-closed гейты — форма, под которой 8.3 строит tool-rounds; MCP-транспорт и внутренний вызов разделяемы (сервис не зависит от HTTP)
- Прецеденты: лестница/малформед/honest empty — 3-1/7-2; AG-4 nil-адаптер с честным отказом словами — 3-6/3-7; composition-адаптеры над живыми каталогами — capabilityresolver/connectorrefresolver 3-1; инъекция источника реестра — toolResolver packs loader 7-2; fixture-тумблеры — reconcile-verdict/action-dispatch; состояния подключений и stale при ротации — 1-8 DeriveCapabilityStates
