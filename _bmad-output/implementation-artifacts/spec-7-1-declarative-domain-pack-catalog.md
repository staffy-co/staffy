## Intent

**Problem:** Epic 7 «Внешняя экспозиция ядра» стартует по ревизии 1 плана (последовательность к звезде: 5 → 7 субстрат → 8 мозг → 9 голос → 10 онбординг), но субстрат AR-29 («AG-3 обязателен до третьего tenant/domain: сначала доказать конфигурируемость ядра без нового domain-specific core») не существует: каталог Domain Pack — это Go-карта литералов в ядре (`internal/employee/packs/catalog.go`, 7 манифестов). (1) Новая предметная область = правка кода ядра — нарушает дух AD-1 («Customization is common core -> declarative versioned Domain Pack -> …»): пак декларативен по типам `domain.PackManifest`, но не по носителю. (2) Вертикальные слова предметных областей («Автозапчасти», «поиск детали», labels «Интерес к деталям»…) живут в .go-исходниках общих пакетов ядра. (3) Hash-пинов манифестов нет: целостность опубликованного артефакта не доказуема, подмена/дрейф невидимы. (4) Валидация артефакта невозможна до «публикации» — компиляция единственный барьер; enum-словари платформы, правила UpgradeFrom/ReplacementImpact проверяются только вниманием ревьюера. (5) Внешний автор не может принести пак без правки ядра — путь AG-3 отсутствует.

**Approach:** смена носителя без смены контрактов: 7 манифестов → версионируемые JSON-артефакты `internal/employee/packs/registry/<id>@<version>.json` + индекс `index.json` с sha256 каждого файла (append-only); загрузчик с полной валидацией ДО любого использования; сигнатуры и семантика `Get/List/Impact` неизменны — потребители (`internal/adapters/packresolver`, `internal/action/domain/catalog.go`, `internal/transport/http/domain_pack.go`, `internal/employee/{app,store,release}`) не меняются ни строкой. Эквивалентность доказывается golden-фикстурами, снятыми с живого бинарного каталога ДО миграции. Артефакты встраиваются в бинарник (go:embed) — реестр версионируется git'ом вместе с ядром, внешние хранилища не нужны (AG-4 не затрагивается). 0 SQL-миграций: каталог — актив кода; пины `employee.drafts.domain_pack` (jsonb, id@version) не меняются.

**Ядро честности среза:** эквивалентность семантики всех опубликованных версий — байт-стабильно (labels Schema и ReplacementImpact переезжают в артефакты; вывод `Get/List/Impact` сверяется с golden до последнего поля); реестр не отдаёт мутируемых копий (clone-дисциплина сохраняется: `Get` возвращает глубокую копию, мутация результата невидима следующему читателю — прецедент 1-4); невалидный артефакт = реестр НЕ загружается целиком (fail-closed, никогда «частичный каталог лучшим усилием» — CI ловит до деплоя); hash-пин не совпал = артефакт не загружается с поимённой причиной; опубликованная версия неизменяема: изменение содержимого артефакта меняет sha256 → drift-FAIL (новая версия = новый файл + новая запись индекса); honest-границы внешнего авторинга записаны в deferred-work (механика review-гейтов внешних авторов = существующий PR-процесс, отдельной машины гейтов в срезе НЕТ).

## Boundaries & Constraints

**Always:** (1) после миграции артефакты — ЕДИНСТВЕННЫЙ источник каталога: литералы Go удаляются вместе с пакетной переменной `replacementImpact` (значение переезжает в поле каждого артефакта). (2) Валидация при каждой загрузке, поимённые причины отказа: обязательные поля {id, version, name, purpose, support_status, stage, connector_types, journeys, critical_entities, policies, capabilities, gates, schema, policy_ref, knowledge_ref, eval_ref, replacement_impact} — урок ValidateVariants 5-1: ВСЕ незащищённые поля обязательны; enum-словари ПЛАТФОРМЫ {support_status, stage, kind (vin|text|integer|enum), review_slots ⊆ {connectors, knowledge, behavior}} — пак использует, но не расширяет: значение вне enum = отказ; `AtLeastOneOf` ⊆ ключи `Schema`; цели `UpgradeFrom` существуют в реестре (составная публикация обязана включать цель); major-переход (старшая версия отличается) без UpgradeFrom-записи = отказ; `ReplacementImpact` непустой (compatibility + changed + review_slots). (3) Индекс append-only: добавление записей разрешено, удаление/переименование существующей записи id@version = drift-FAIL CI. (4) Drift-CI на каждом ране: sha256 индекс↔файлы; полная валидация всех артефактов; вертикальный словарь (точные фразы Name/Purpose/Journeys/labels артефактов) в прод-.go общих пакетов ядра {internal/**/{domain,app,port,store}, cmd} = 0 (зонд; _test.go — легитимные зеркала-ассерты, прецедент словарей-зеркал; вертикальные поверхности transport/templates — вне зоны). (5) Порядок `List()` стабилен (канонический порядок индекса) — эквивалентность вывода.

**Never:** не строить реестр tools (7.2), MCP-сервер (7.3), внешние MCP-коннекторы (7.4); не менять контракты существующих поверхностей (сигнатуры Get/List/Impact; транспортные маршруты /v1/domain-packs… и /app-страницы; OpenAPI — 0 правок; страницы — 0 правок); не вводить HTTP-поверхность публикации/администрирования реестра (путь внешнего автора = git PR с артефактом и индексной записью); не трогать SQL/миграции (0 миграций среза); не менять формат пинов employee.drafts и машины sealed-манифестов/Release Manifest (pack pin разрешается тем же Get); не подключать внешние хранилища/CDN/сетевые реестры (go:embed; AG-4 не нужен); не вводить «мягкую» валидацию (warning вместо отказа); не удалять и не «улучшать» семантику опубликованных версий при переносе (миграция без поведения — переформатирование носителя, не ревизия контента); не строить машину review-гейтов внешних авторов (граница — deferred-work).

## I/O & Edge-Case Matrix

- Given загрузка реестра, when артефакт auto-parts@6.0.0 валиден и sha256 совпал, then `Get("auto-parts","6.0.0")` возвращает манифест, deep-equal golden-фикстуре, снятой с бинарного каталога ДО миграции (включая labels Schema из артефакта и ReplacementImpact из артефакта) — байт-стабильно
- Given артефакт с отсутствующим обязательным полем (например, `eval_ref`), when загрузка, then отказ поимённо «<id>@<version>: обязательное поле eval_ref отсутствует» И реестр целиком не загружается (fail-closed: частичный каталог запрещён) — даже если остальные 6 артефактов валидны
- Given `AtLeastOneOf` ссылается на ключ вне `Schema`, when валидация, then отказ поимённо «ключ X не описан в schema» (прецедент montagio-services@1.0.0 — валидный случай переносится без изменений)
- Given публикуется major-версия (старшая отлична от всех существующих) без записи `UpgradeFrom`, when валидация, then отказ «major-переход без UpgradeFrom-записи невозможен» (AC-3); minor/patch без UpgradeFrom — допустимы (совместимость по умолчанию — текущая семантика каталога сохраняется)
- Given `UpgradeFrom` указывает версию, отсутствующую в реестре, when валидация, then отказ поимённо (составная публикация обязана включать цель перехода)
- Given sha256 файла ≠ hash в индексе, when загрузка или drift-CI, then FAIL поимённо «артефакт изменён после индексации» (подмена/дрейф)
- Given из индекса удалена существующая запись id@version, when drift-CI, then FAIL append-only (версии не удаляются — защита живых пинов тенентов; runtime-дубль: пин на отсутствующую версию → существующее fail-closed слово packresolver — прецедент сохранён)
- Given вертикальная фраза артефакта («Автозапчасти», «поиск детали», «Интерес к деталям»…) в прод-.go общих пакетов ядра, when зонд CI, then FAIL поимённо (после миграции литералы удалены — зонд фиксирует ноль и держит его)
- Given внешний автор приносит пак (PR: +registry/<id>@<version>.json + запись индекса, 0 правок .go), when CI, then валидация схемы/enum/правил PASS при корректном артефакте; ReviewSlots перехода декларированы в артефакте; PR-review владельца = исполнение review-гейта слотов impact (honest: отдельной машины гейтов нет)
- Given значение enum вне платформенного словаря (например, review_slots: ["billing"]), when валидация, then отказ «review_slots: значение billing вне платформенного словаря» (платформенные словари паком не редактируются — AC-5)
- Given возвращённый манифест мутируется вызывающим кодом, when следующий `Get`, then мутация невидима (clone-дисциплина 1-4 сохранена над артефактным источником)
- Given `List()`, when вызов, then порядок стабилен (канонический порядок индекса: auto-parts 6→1, montagio-services 1.0.0 — порядок текущего литерала сохранён)

## Implementation Notes

- Решение носителя — go:embed: реестр версионируется git'ом с ядром и встраивается в бинарник; sha256 артефакта проверяется при загрузке и в CI; внешнее хранилище/CDN — вне среза (AG-3/AG-4 не нужны: субстрат — чистая инженерия, ревизия 1 плана)
- Эквивалентность, а не переписывание: golden снимается ДО миграции с живого кода и остаётся в testdata навсегда (доказательство «миграция без поведения»); любые расхождения = баг среза, а не «обновление golden»
- replacement_impact: пакетовая переменная → значение в каждом артефакте (JSON-поле уже существует в PackManifest); reverse-Impact и Replacement-ветка тестируются golden
- Семантика версий сохраняется дословно: UpgradeFrom в текущем каталоге есть не у всех версий (1.0.0/2.0.0 auto-parts описывают переходы 1↔2 в обе стороны — зеркалится артефактами как есть); правило «major без UpgradeFrom» — НОВОЕ правило валидатора на публикуемых ВПЕРЕД версиях; существующие 7 артефактов ему удовлетворяют (auto-parts 2.0.0 имеет UpgradeFrom 1.0.0; 3.0.0→2.0.0; 4.0.0→3.0.0; 5.0.0→4.0.0; 6.0.0→5.0.0; montagio 1.0.0 — первая)
- «Major» определяется по семверу старшей версии пака в реестре: изменение major-цифры без UpgradeFrom-записи = отказ; minor/patch по умолчанию compatible (текущая семантика Impact не меняется)
- Enum-словари платформы — канон ядра: support_status/stage/kind/review_slots; источник значений — живые литералы существующих артефактов + словарь review_slots {connectors, knowledge, behavior} (GATE/impact-прецеденты 1-4); расширение словаря = правка ядра (пак не может)
- Валидация «одним барьером»: реестр загружается на старте пакета (init/lazy синхронно) — невалидный артефакт = паника-отказ загрузки (CI ловит тем же кодом); «мягких» режимов нет
- Вертикальный зонд: словарь = точные многословные/уникальные фразы артефактов (Name, Purpose, Journeys, labels Schema); зона = прод-.go общих пакетов {domain, app, port, store} + cmd; _test.go и вертикальные поверхности (transport/templates, honest-слова pilot_montagio) — вне зоны; Dev снимает живой словарь с артефактов шага-01 и фиксирует в тесте (обновление словаря = новая версия пака = осознанный шаг)
