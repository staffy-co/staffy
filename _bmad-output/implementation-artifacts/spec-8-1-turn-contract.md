## Intent

**Problem:** Эпик 7 закрыл инструментальный субстрат (реестр tools 7-2, MCP-поверхность 7-3, внешние MCP 7-4), но «мозга» — Conversation Planner по AD-7 — в системе не существует вовсе: (1) контракта хода нет ни в какой форме — ни типизированного минимизированного входа (Turn Context), ни версионируемого выхода (Turn Proposal): любая будущая интеграция модели была бы контрактной пустотой — материал модели не имел бы закрытой формы, strict-decode дисциплины и версионируемости, которые эпики 2-7 последовательно навели на каждую машину платформы; (2) дисциплина AD-7 «один repair-pass + вторая неудача персистится + только утверждённый безопасный fallback — НИКОГДА вывод модели» не доказана ни одной машиной — это ядро доверия к «мозгу» (§2 звезды: честная эскалация незнания), и оно должно существовать ДО появления живой модели (8.2), tool-раундов (8.3) и интеграции (8.4), иначе каждый следующий срез строился бы на песке; (3) инвентарь read-инструментов реестра 7-2 и внешнего словаря 7-4 существует, но ни один потребитель его не читает — контракт хода закрепляет форму потребления (имена@версии + схемы входа платформенным словарём типизации) так, чтобы 8.3 лишь подключил исполнение; (4) лестница режимов FR-14 и пины Release Manifest существуют в своих контурах, но не имеют места, где они встречаются в одном типизированном входе хода; (5) scripted-модели за портом нет — без неё матрица контракта (валидный/малформед/чужая версия/repair/fallback) недоказуема без живых credentials (AG-4 — Граница Epic 8).

**Value:** первый срез создаёт протокольную машину «мозга» — как 7-3 создал протокольную машину MCP-поверхности ДО живых адаптеров: закрытые формы входа/выхода, строгая валидация, repair×1, персистимая честность исходов, безопасный fallback. Всё, что строится позже (адаптер 8.2, tool-раунды 8.3, интеграция 8.4, eval 8.5, телеметрия 8.6), входит в готовый контракт — прогрессивная детализация Ревизии 3.

## Boundaries & Constraints

**Always:** (1) Turn Context — минимизированная закрытая типизированная форма: референсы {tenant, case, conversation, work item, employee, release manifest@версия, pack@версия}; подтверждённые факты [{ключ, значение платформенного типа, provenance {источник, версия, время}}]; режим разговора (закрытый словарь — зеркало ModeOrder лестницей FR-14) + активная лестница; пины политики {policy bundle ref, Allowed Claims, режим автономности} — РЕФЕРЕНСАМИ (id@версия), не материалом (сборка — 8.2/8.4); инвентарь read-инструментов [{имя@версия, вход — поля платформенного словарём типизации tools.ToolFieldTypes (реюз 7-2, словарь НЕ расширяется)}]; требование раскрытия ИИ (bool); fallback-политика хода (закрытый словарь {honest-stop, handoff, callback}); бюджеты-декларации хода (максимальная длина реплики — платформенная константа). Strict decode ДО модели: undeclared-ключ или неверный тип = поимённый отказ; секретов в контексте НЕТ (AD-11); скрытой цепочки рассуждений НЕТ (AD-8); материала чужих тенентов НЕТ (scope — AD-11). (2) Turn Proposal — версионируемая закрытая форма: schema_version (версия формы предложения — платформенная константа среза); intent (закрытый платформенный словарь намерений среза); mode (зеркало лестницы режимов); safety (закрытый словарь safety-состояний); fact-предложения [{ключ, значение, provenance}] — provenance обязателен; противоречия [{ключ, существующий факт, предлагаемый, provenance}]; read-запросы [{инструмент имя@версия, аргументы {поле: значение}}] — валидируются против инвентаря КОНТЕКСТА (несуществующий инструмент = отказ; аргумент вне схемы/типа/enum/границ = отказ; обязательное поле пропущено = отказ — словарная дисциплина 7-2/7-4); вопросы [{текст в бюджете}]; предлагаемое действие — закрытый union {none, commitment, action, handoff} + контракт-реф (id@версия) для kind ≠ none, БЕЗ материала исполнения (материальная snapshots-машина Confirmation — 8.4; предложение только НАЗЫВАЕТ — AD-6); реплика {текст ≤ платформенного бюджета} — сверх = отказ валидации, усечения НЕТ (зеркало 7-3/7-4 «без усечения»); evidence-ссылки [{тип, id}]; патч Case-памяти [{операция-форма версионированной записи AD-8: ключ, значение, provenance}] — закрытая форма, применение — 8.4. Strict decode: undeclared-ключ = отказ; чужая schema_version = отказ (когерентность). (3) Валидация — строгая: закрытые enum (intent/mode/safety — платформенные словари среза, mode-словарь зеркалит ModeOrder контракт-тестом); обязательность полей; кросс-полевые правила: приоритет mode предложения НЕ НИЖЕ mode контекста по лестнице FR-14; safety-флаги предложения не снимают safety-режим контекста; union-реф обязателен для kind ≠ none; реплика в бюджете; read-запросы против инвентаря контекста. (4) Машина internal/planner: раунд 1 (порт → decode → валидация); поимённый отказ → РОВНО один repair-проход (модель получает поимённую причину отказа + тот же контекст; повторный strict decode + валидация); вторая неудача → честная запись хода failed {поимённая причина} + ход завершает только утверждённый безопасный fallback по fallback-политике контекста — НИКОГДА вывод модели (AD-7 дословно); ошибка адаптера (порт) = failed-ход + fallback (честно, без слепого retry); модельных раундов структурно ≤ 2 (валидация + repair — третий раунд невозможен формой машины); Build() = константа «planner/1.0.0» — пишется в каждую запись хода (смена билда = записи нового билда, честная цена — зеркало семантики 1-8/connectorprobe). (5) ModelPort — порт формы без credentials (model-credentials — AG-4 Граница эпика; живой адаптер — 8.2 параметрической стороной); scripted-адаптер internal/adapters/modelscripted — честное тест-материал продакшн-кода (прецедент verifier.Synthetic): матрица исходов задаётся конфигурацией адаптера {валидный, малформед-undeclared, малформед-тип, чужая schema_version, repairable (валидный со второго раза), unrecoverable, ошибка адаптера}; main.go НЕ подключает планировщик (продакшн-вызывателей НОЛЬ — вызыватель 8.4). (6) Turn-журнал migrations/planner/00001_turn_ledger.sql + internal/planner/store/postgres.go: append-only (AD-10), tenant_id + RLS/FORCE (AD-11, runtime-роли NOBYPASSRLS — платформенная дисциплина); запись {tenant, turn_id, case/conversation/work item refs, исход validated|repaired|failed, поимённая причина отказа, fallback-форма, schema_version предложения, Build, created_at, валидированное предложение компактным JSONB за RLS — бизнес-материал духа reply-строк 2.12, НЕ телеметрия (AR-18-обвязка — 8.6)}; уникальность (tenant, turn_id) = честный конфликт (второго записывания того же хода нет — прецедент ErrIdempotencyConflict); коррекция исхода НЕ существует (append-only: новый ход = новая запись; eval-инвалидация по билду — 8.5). (7) Вертикальная чистота: internal/planner + internal/adapters/modelscripted — платформенные пакеты без вертикальных слов (drift-зоны +2 осознанной правкой; словарь фраз НЕ растёт); fallback-слова — платформенные честные формулировки (honest-stop/handoff/callback — без предметной лексики). (8) RuntimeDictionary БЕЗ presence-флипов: model_route/prompt_assembly/policy_bundle/eval_set/runtime_build/autonomy_envelope остаются честными gap-записками (их поверхности — 8.2/8.4/8.5); sealed-история не пересчитывается (AD-10); Build-константа в журнале — дух runtime_build на уровне записи, компонентный флип ждёт свою поверхность.

**Never:** не строить HTTP-поверхность хода (продакшн-вызывателя нет: сборка контекста из живого разговора и доставка реплики — 8.4; машина доказывается Go-контуром + живой PG-интеграцией — прецедент 7-1/7-4-Calls); не исполнять tool-раунды (read-запросы — ФОРМА предложения, валидируемая против инвентаря контекста; исполнение над реестром 7.2/externaltools.Calls — 8.3); не строить живой модельный адаптер и бюджеты времени/стоимости (параметрический адаптер, prompt assembly, model_route/prompt_assembly presence — 8.2; в срезе раунды ≤2 структурно); не реализовывать предлагаемое действие/commitment/handoff и не применять патч Case-памяти (только формы; контуры — 8.4); не строить eval-машину (8.5) и телеметрию-обвязку (8.6; журнал — бизнес-запись, не телеметрия); не выдавать вывод модели после второй неудачи валидации НИКОГДА (AD-7); не усекать реплику молча (сверх бюджета = отказ валидации); не хранить секреты в контексте/предложении/журнале (AD-11; Authorization-материал будущих адаптеров — AG-4-параметр 8.2); не расширять платформенные словари (словарь типизации — реюз tools.ToolFieldTypes как есть; словари intent/safety/fallback — новые платформенные константы среза, вертикально чистые); не флипать RuntimeDictionary presence и не пересчитывать sealed-манифесты (AD-10); не вводить модельный SDK или внешние зависимости (stdlib; scripted-адаптер — stdlib); не строить голосовой контур (AD-9: тот же контракт для голоса — Epic 9; форма фиксируется текстуально, медиа не строится); не подключать планировщик в main.go (вызыватель — 8.4; composition продакшн-пуст); 1 SQL-миграция (turn-журнал — платформенная дисциплина миграций cases/action: объявлена в спеке с самого начала, отклонений нет).

## I/O & Edge-Case Matrix

- Given контекст с undeclared-ключом или неверным типом поля, when строгий decode ДО модели, then поимённый отказ контекста; модельного раунда НЕТ; журнал не пишется (отказ входа — не ход)
- Given контекст без обязательного поля (факт без provenance / режим вне словаря / инвенторий инструмент без схемы входа), then поимённый отказ до модели
- Given валидный контекст + scripted-модель «валидный», when раунд 1, then strict decode + валидация предложения проходят; запись хода исход validated; JSONB-предложение за RLS
- Given модель «малформед-undeclared» (undeclared-ключ в предложении), then валидация отказ поимённо → repair-проход с причиной
- Given repair-проход модели «валидный» (конфигурация repairable), then запись хода исход repaired; второй записи нет; раундов ровно 2
- Given repair-проход снова малформед (unrecoverable), then вторая неудача персистится (исход failed, поимённая причина) + ход завершает утверждённый fallback по политике контекста — вывод модели НЕ выдаётся НИКОГДА
- Given модель «чужая schema_version», then отказ валидации поимённо (когерентность) → repair → при повторе — failed + fallback
- Given предложение с intent/mode/safety вне словаря, then отказ валидации поимённо
- Given mode предложения ниже по лестнице FR-14, чем mode контекста (контекст safety — предложение sales), then отказ кросс-полевой валидации (лестница не понижается)
- Given read-запрос инструмента, отсутствующего в инвентаре контекста, then отказ валидации поимённо (против инвентаря — TOCTOU-дух 7-4)
- Given read-запрос с аргументом вне схемы инвентаря (тип/enum/границы/обязательность), then отказ поимённо — словарная дисциплина 7-2/7-4
- Given реплика сверх платформенного бюджета, then отказ валидации — без усечения (зеркало 7-3/7-4)
- Given union предлагаемого действия kind=action БЕЗ контракт-рефа, then отказ валидации (реф обязателен для kind ≠ none)
- Given ошибка адаптера (порт; конфигурация «ошибка»), then failed-ход + fallback; слепого retry нет; вывода модели нет
- Given fallback-политика контекста handoff, when вторая неудача, then fallback-форма handoff (закрытые платформенные слова) записана в журнале поимённо
- Given повторная команда хода с тем же turn_id (тот же тенент), then честный конфликт уникальности — второй записи того же хода нет
- Given чтение журнала тенентом B, then записи тенента A структурно отсутствуют (RLS/FORCE — AD-11)
- Given смена Build-константы машины (будущий релиз), then записи нового билда несут новый Build; прежние записи не пересчитываются (append-only — AD-10; eval-инвалидация — 8.5)
- Given продакшн-сборка main.go, then планировщик не подключён: ни HTTP-поверхности, ни вызывателя; scripted-адаптер не в composition (тест-материал)
- Given вертикальный зонд фраз в internal/planner и internal/adapters/modelscripted (drift-зоны +2), then FAIL поимённо — платформенные пакеты вертикально-чисты, словарь фраз НЕ растёт
