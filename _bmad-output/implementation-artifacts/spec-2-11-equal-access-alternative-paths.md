## Intent

**Problem:** Записанных предпочтений связи не существует ни в каком виде: слова клиента «не могу фото», «не пользуюсь web», «не могу говорить голосом», «пишите текстом», «звоните после 18:00» (AC-блок 1) некуда записать — ни таблицы, ни словаря, ни команды; «передаются каждому последующему Response Owner» нечему нести (карточка запроса передачи владения 2-4 про предпочтения клиента молчит — принимающий решение оператор не видит их ДО ack); «редактируемые» нечем обеспечить (нет ревизий, нет деривации текущего набора); граница «не интерпретируются как медицинский диагноз или доказательство личности» не закреплена нигде — единственный контейнер клиентских слов сегодня это fact-каналы 2-2 (факт = материал кейса со статусами подтверждения и дайджестом), что прямо противоречит AC: предпочтение связи — операционная настройка обслуживания, а не материал кейса. Альтернативы Policy (AC-блок 2) отсутствуют: правило-таблица 2-6 не знает «обычную модальность» обязательного факта (media-usual или text-usual), действующий исход не предлагает «разрешённое текстовое описание, диапазон, … callback или Human Handoff», не сообщает «ограничения точности альтернативы», а гейт продажного ответа не удерживает честность структурно: «отсутствие media не приводит к выдуманному точному результату» — сегодня кандидат продажного ответа обязан лишь пройти политику (commercial_answer) и возражение (playbook_step), и ничто не требует от ответа, сопровождающегося отсутствующим media-фактом, заявить ограничение точности. AC-блок 8 «ни один автоматический альтернативный путь не удовлетворяет… → Human Handoff или честно останавливает затронутый путь» — fail_closed 2-6 умеет останавливаться по unknown_intent/mode_blocked, но не по «разрешённых альтернатив нет». Таймлайн причины (AC-блок 10) молчит: запись предпочтения и её ревизии как видимые строки истории кейса отсутствуют — «событие переключения и его причина» нечему показывать.

**Approach:** Первый срез — детерминированный серверный контур записанных предпочтений связи + честные альтернативы Policy (прецедент 2-5…2-10: AI Runtime в контуре НЕТ; продюсер размечает — машина гейтит). Пять частей: (1) словари Domain Pack v0: ключи предпочтений {no_photo, no_web, no_voice, text_first, slowed_pace, mandatory_readback, preferred_channel, available_time} — 6 флаговых + 2 значимых (preferred_channel — слово словаря каналов 2-1; available_time — свободный текст 1..100 рун, НЕ расписание: операционная строка, не парсится машиной); слова альтернативных путей {text_description, range_estimate, callback, human_handoff} с фиксированными честными текстами ограничений точности (по одному на слово, словарь пакета: «точность ниже фото…», «только диапазон, не точный результат», «уточнение голосом с человеком», «продолжит человек» — AC-блок 2 «прямо сообщает ограничения точности»); карта usual-модальности обязательных материальных ключей v0: service_kind → media_photo (в якорном мире автозапчастей «какая деталь/услуга» обычно определяется по фото), urgency/slot_preference → text, неизвестный ключ → text (fail-открыт к text — карта это данные пакета, не гейт); DeriveCurrentAccommodations — read-time деривация (последняя ревизия на ключ; cleared-ревизия убирает ключ из текущего набора — «редактируемые»; прецедент DeriveContinuationLinkState 2-10 / DeriveFactStatus 2-2); гварды записи (ключи, флаг/значимость, пределы); (2) append-only `cases.case_accommodations` (tenant_id, case_id, accommodation_key CHECK-словарь, revision — UNIQUE (tenant, case, key, revision) монотонность, value NULL для флагов / NOT NULL для значимых — CHECK по фиксированным спискам словаря, cleared boolean, note ≤500 рун, actor, recorded_at; ## Boundaries & Constraints

**Always:** append-only `cases.case_accommodations` — гранты INSERT/SELECT, RLS + FORCE ROW LEVEL SECURITY, UPDATE/DELETE/TRUNCATE нет; CHECK-словарь ключей; CHECK флаг/значимость по фиксированным спискам (value IS NULL для флагов, IS NOT NULL для значимых — словарь домена = истина CHECK); UNIQUE (tenant, case, key, revision) — ревизии монотонны, история никогда не правится; DeriveCurrentAccommodations — read-time (последняя ревизия на ключ; cleared убирает ключ), нигде не мутируется; запись команды под advisory-локами case+conversation сортированного lock-плана (урок R1 2-9; прецедент 2-5/2-6); идемпотентность command_records (UNIQUE tenant+actor+command+key; request-hash со всем материалом ВКЛЮЧАЯ value/note/cleared; replay исходной записи до стражей; тот же ключ с иным материалом → ErrCommandKeyConflict 409); операторские гейты: скоуп review ДО материальных стражей (403 словами скоупа, прецедент M1; configuration тоже проходит — прецедент 2-6), не-участник → 404 ×пути, чужой tenant → RLS 404 (регресс 2-1); терминальный кейс → 400 work-rule (продолжать обслуживание нечему); preferences НИКОГДА факты: вне FactChannels/fact_versions/facts_digest (зонд периметра живой пробой), без статусов подтверждения, без влияния на identity-верификацию 2-3 и дайджест коммерческого материала; policy v2: input_snapshot + карта preferences (key→{revision, cleared}); decision_digest канонический над входами+решением; воспроизводимость — та же пара (предложение, якоря, состояние preferences) → тот же дайджест; изменение preferences между оценками → новый исход supersede (номер outcome_no растёт, предшественник читаем); контрольная ветка: набор preferences пуст ИЛИ media-факт подтверждён ИЛИ ключ text-usual → решение идентично прежнему (class/reason/next_steps байт-в-байт; digest честно v2 — исторические строки не пересчитываются); гейт точности ПОСЛЕ возражения ДО CAS; прежние отказы лестницы (владение/режим/раскрытие/политика/возражение) не меняются — их тесты байт-в-байт; qualifier ∈ active_alternatives действующего исхода (строже словаря); без альтернатив поле пусто; client_replies +accuracy_qualifier nullable слово словаря (только sales-строки несут его — гейт словарём, прецедент playbook_step); словари фиксированы compile-time (Domain Pack v0): ключи preferences, слова альтернатив, тексты ограничений, карта usual-модальности (service_kind → media_photo; прочие обязательные ключи → text; неизвестный → text); триггер альтернатив v1 = пара (отсутствует обязательный media-usual факт) ∧ (no_photo в текущем наборе) — единственная детерминированная пара; outbox `case.accommodation_recorded` v1: метаданные key/revision/cleared — value (включая слово preferred_channel), note, available_time НИКОГДА (только идентификаторы и словарные слова ревизии); панель/карточки: preferences словами словаря + значения текстом (операторский контур), история ревизий с cleared честно; a11y 320px/≥44×44/aria-live/flash-focus/без preselect (select квалификатора обязателен к осознанному выбору, вариант не выбран заранее — AC-блок 11); ## I/O & Edge-Case Matrix

- Given кейс in_work и оператор review, when record_accommodation (no_photo, ревизия 1), then append-only строка + outbox (key/revision/cleared, без value/note); панель: секция «Предпочтения связи» показывает слово; текущий набор = {no_photo} (AC-блок 1).
- Given значимый ключ preferred_channel, when запись со значением «phone» (слово словаря каналов 2-1), then value сохранён; панель показывает слово+значение; outbox БЕЗ значения.
- Given значимый ключ available_time, when запись «после 18:00» (1..100 рун), then строка хранит; значение никогда не в outbox (свободный текст — операционная строка, не идентификатор).
- Given guards: неизвестный ключ / флаговый ключ со значением / значимый без значения / preferred_channel ∉ словаря каналов / available_time вне 1..100 рун / note > 500 рун / cleared=true вместе с value, when запись, then 400 словарём гвардов (домен до SQL).
- Given повторная запись того же ключа (иной материал, иной command-ключ), when запись, then ревизия 2 append-only; история ревизии 1 читаема; текущий набор = ревизия 2 («редактируемые», AC-блок 1).
- Given запись с cleared=true, when запись, then ревизия сохранена; ключ исчезает из текущего набора; история показывает cleared-строку честно.
- Given повтор той же команды (тот же command-ключ и материал), when запись, then replay исходной записи (идемпотентность 2-1); тот же ключ с иным материалом → 409 ErrCommandKeyConflict.
- Given оператор audit-only, when record, then 403 словами скоупа ДО стражей (прецедент M1); не-участник → 404 ×пути; чужой tenant → RLS 404 (регресс 2-1).
- Given терминальный кейс (resolved/cancelled), when запись, then 400 work-rule — обслуживать нечего.
- Given записан no_photo И отсутствует обязательный media-usual факт (service_kind) И режим sales, when evaluate_policy, then исход (commercial_answer/clarify по кандидату) + active_alternatives [text_description, range_estimate, callback, human_handoff]; вопрос факта остаётся ask; rule_version intake-policy-v2; input_snapshot + карта preferences; digest детерминирован (AC-блок 2).

- Given no_photo записан НО service_kind подтверждён (дедуп 2-6), then исход без альтернатив — факт не отсутствует; путь прежний.
- Given media-usual ключ отсутствует, preferences пусты, then ask как прежде (контрольная ветка).
- Given media-ключ с пустым словарём альтернатив пакета (unit-словарь), when оценка, then fail_closed reason=no_alternative_path + next_steps human_handoff (AC-блок 8: честная остановка, проверка не ослабляется).
- Given действующий исход закреплённого WI несёт active_alternatives, when send_client_reply (sales) без accuracy_qualifier, then 400 accuracy_qualifier_required со словами активного множества исхода (AC-блок 2 «не выдуманный точный результат»).
- Given qualifier ∉ active_alternatives исхода (чужое слово словаря), then 400 accuracy_qualifier_foreign (подмножество исхода, не словарь вообще).
- Given reply с qualifier=text_description (активен), then проходит лестницу полностью (владение → режим → раскрытие → политика → возражение → точность → CAS); reply-строка несёт слово; панель ответов показывает.
- Given активных альтернатив нет, when reply с непустым qualifier, then 400 accuracy_qualifier_foreign (зеркало objection_step_foreign 2-8: поле ровно одного смысла); путь без поля байт-в-байт прежний (контрольная ветка 2-1..2-10).

- Given повторная оценка с теми же якорями и НЕИЗМЕНЁННЫМ набором preferences, then новый исход с тем же decision_digest (воспроизводимость 2-6 наследуется).
- Given preferences изменились между оценками (ревизия/cleared), then новый исход с иным digest — честный supersede (номер растёт, предшественник читаем).
- Given запрос передачи владения 2-4, when карточка запроса, then текущий набор preferences виден принимающему ДО ack (AC-блок 1 «передаются каждому последующему Response Owner»).
- Given периметр, when зонд, then строки case_accommodations отсутствуют в fact_versions/facts_digest/identity-контуре 2-3 (живая проба: preferences не факты и не доказательство — AC-блок 1).
- Given RLS/гранты 00011, when зонды pg_class + INSERT (урок R1 2-7), then INSERT/SELECT-only подтверждены; UPDATE/DELETE/TRUNCATE отсутствуют; UNIQUE-коллизия ревизий держит пробу; CHECK-бэкстопы словарей живут.
- Given форма выдачи continuation 2-10, when открыт набор preferences с no_web/no_voice, then подсказка словами (машина не блокирует — честная граница capability).
- Given journeys-цепь, when запись → оценка → альтернативы → qualified reply → передача владения → cleared → повторная оценка → контрольная ветка, then сквозной путь живой (прецедент цепи 2-10) + a11y/320px/aria-live/без preselect.

## Implementation Notes

- Ключи preferences — операционная настройка, НЕ факт: класс таблицы case-operations; словарь ключей никогда не расширяется конфигурацией тенанта (Epic 5 — данные пакета).
- DeriveCurrentAccommodations над всеми записями кейса: latest revision на ключ; cleared-ревизия — отсутствие ключа; история целиком читаема (append-only, ревизии монотонны UNIQUE-ем).
- Гейт точности зеркалит GuardSalesReplyAgainstObjections по форме (required/foreign), но строже по словарю: подмножество active_alternatives ДЕЙСТВУЮЩЕГО исхода, не словарь вообще — исход решает, какие слова честны в этом контексте.
- Digest v2: input_snapshot канонически расширен картой preferences; та же пара входов → тот же дайджест; исторические строки v1 не пересчитываются (append-only читаемость); literal-дайджесты в тестах не хранятся (сравнение вычисленных значений — прецедент 2-6).
- Триггер альтернатив v1 строго = (отсутствует обязательный media-usual факт) ∧ (no_photo ∈ текущий набор): единственная детерминированная пара; no_web/no_voice — видимость оператору (подсказки форм), не машинные триггеры — расширение пар слов будущими словарями пакета аддитивно.
- policy_outcomes.active_alternatives хранит СЛОВА (jsonb-массив словаря); тексты ограничений — рендер словаря домена на панелях; в БД текстов нет.
- available_time — свободный текст операционной строки: не парсится, не расписание, не обещание тайминга (2-12 — callback-контур); в outbox/исключения никогда.
- Гонки: запись preferences и оценка исхода — один сортированный advisory-lock-план (case+conversation); request-hash записи включает весь материал (value/note/cleared); replay до стражей.
- Privacy: case_accommodations — case-operations; чтение review/audit, команда review; TestPerimeterIntegrity синхронно; available_time/note — операционные строки, в outbox только key/revision/cleared.
- Контрольная ветка: пустой набор preferences → policy/reply пути идентичны прежним (решение байт-в-байт; tests 2-6/2-8 не меняются кроме механических расширений формы snapshot/rule_version через константы домена — честная запись в Change Log).
- a11y: select квалификатора без preselect/без autofocus; формы required с явными label; ошибки — текст + фокус к описанию; 320px single-column; статусы aria-live=polite (прецеденты 2-9/2-10).
