## Intent

**Problem:** Epic 7 закрыл исходящее направление экспозиции (7-3: платформа как MCP-сервер над реестром 7-2), но обратное направление — потребление внешних MCP-серверов бизнес-систем — не существует: (1) класса Connector «внешний MCP-сервер» нет в каталоге (единственное семейство каталога — синтетическая телефония), значит подключение внешней системы стандартным классом (§4 звезды: «глубокая интеграция в любой бизнес») невозможно, и путь каждой внешней системы выглядел бы кастомной разработкой под систему — противоположно субстратной стратегии эпика; (2) клиентской протокольной машины MCP нет вовсе: ни пиннинга ревизии 2026-07-28 на стороне клиента, ни строгого декодирования недоверенных ответов, ни размерных бюджетов чтения — при том что серверная машина 7-3 уже пиннингует те же словари; (3) живая аутентифицированная проба с учётными данными не существует: пробы 1-8 работают без секретов (синтетика форматов над config), а запечатанные MAC-секреты write-only — архитектура не перечитывает их ни для одной пробы; persist plaintext для живых проб при этом НЕ нужен: ключ можно получить с командой верификации в память и MAC-проверить против принятого seal (HMAC тем же ключом), связав пробу с принятым подключением без единого байта сохранённого секрета; (4) read-tools внешнего сервера не входят ни в какой словарь: нет проекции их JSON Schema в платформенный словарь типизации (обратная проекции 7-3), нет provenance и версии сервера, нет honest-состояний записи, нет динамики ротация→stale→исчезновение для внешнего направления; (5) границы спроса не зафиксированы: интеграции РФ/СНГ (Битрикс24, amoCRM, Мегаплан, 1С, МойСклад, Telegram, WhatsApp) и маркетплейс-листинги обязаны остаться за AG-3-триггером (§6 анти-цель: количество интеграций не самоцель), аннотация epics (листинг = канал дистрибуции, не класс интеграции) требует фиксации в границах среза.

**Approach:** первый срез — класс «внешний MCP-сервер» как карточка каталога коннекторов (единственный платформенный путь нового интеграционного класса: definition + adapter, никогда Tenant-ветка — AD-1/AD-2) с capabilities поимённо и полной операционной семантикой (прецедент карточки телефонии) + клиентская протокольная машина `internal/mcpclient` (stateless 2026-07-28, stdlib, discover/list/call, credential-агностичная — Authorization-материал явный параметр вызывателя, машина никогда не хранит и не логирует его) + composition-роутер верификатора `internal/adapters/connectorprobe` (маршрут по RequiredAccountType «external-mcp» → живая MCP-проба над mcpclient; иначе → verifier.Synthetic без изменений поведения; Build = новая константа — смена билда инвалидирует прежние evidence честно по дизайну 1-8) + осознанные core-правки коннектора для проб с секретом (VerifyCommand несёт секрет в память; app MAC-проверяет против активного seal через новый узкий ReadSeal репозитория; Verifier.Probe получает secrets — прецедент BasicCheck того же интерфейса) + внешний словарь `internal/externaltools` (деривация-чистая-функция над ConnectionsFacts с evidence-саммари: инвентарь пробtools-list едет фильтрованным JSON в redacted_result существующей строки evidence — 0 SQL; проекция в платформенный словарь типизации тотальна для подмножества, вне — поимённые честные отказы на запись; read-only поверхность оператора за лестницей 3-1/7-2 + OpenAPI-зеркало) + машина вызова `externaltools.Calls` без HTTP-поверхности (потребитель — Planner 8.3). Продакшн-карта разрешает окружения ровно {sandbox, test}: живых внешних серверов и production-учётных данных в продакшне НОЛЬ (AG-4), вся динамика доказана fixture-миром (fixture-сервер journeys на /fixture/external-mcp + реальный httptest-wire в Go-тестах + живой PG в интеграционном контуре).

**Ядро честности среза:** (1) write через внешний словарь структурно невозможен: запись ⊆ инструменты с заявленным сервером readOnlyHint ∩ успешная проекция в словарь типизации ∩ applicable evidence; мутации внешней системы = заблокированное Connector capability карточки (ActionGatewayBlock машинально — DeriveCapabilityStates), write-инструмент не существует ни как запись словаря, ни как инструмент модели (AC-1, AD-6/AD-7 — гарантия машинальна, не ревью). (2) Секреты: plaintext никогда не персистится (MAC-инвариант 1-8 дословно); проба получает ключ ТОЛЬКО в памяти из команды верификации, MAC-проверяет против принятого seal; несовпадение/отсутствие = честный отказ ДО сети — неаутентифицированный раунд невозможен fail-closed; ротация → новый SecretID → прежние evidence stale → словарь пустеет (AC-2: секреты через существующее запечатывание, tenant-изоляция scope-машиной). (3) Недоверенный материал (AD-11): конверт строго декодируется (result XOR error, эхо id, когерентность версии), дескрипторы фильтруются до известных полей протокола, инвентарь под размерным бюджетом, аргументы И выход вызова валидируются по закрытой форме спроецированных словарей — undeclared ключ не пересылается; untrusted контент не меняет Tenant/tools/authority/destinations. (4) Словарь = чистая функция фактов (DeriveCapabilityStates-прецедент): нулевая вторая запись состояний, чтение не мутирует, живость выводится из якорей Applicable. (5) Capabilities = факт, не заявление (AR-30): без readOnlyHint / вне словаря типизации / инвентарь сверх бюджета = поимённая строка отклонения В СЛОВАРЕ, не молчание и не ложная запись; query.tool-call карточки заявлена с честным непроверяемым состоянием (declaration ≠ claim — прецедент command.send-sms/event.inbound-call телефонии). (6) Ноль живых внешних серверов в продакшне: карта без production-окружения (AG-4 fail-closed на классе по Границе Epic 7), машина и поверхности при этом полностью отвечают. (7) Смена Build-строки верификатора честно инвалидирует прежние evidence stale (дизайн 1-8 «build change invalidates evidence») — операторы перепробуют; фиксация в DEVLOG.

## Boundaries & Constraints

**Always:** (1) Класс = карточка каталога: `staffy-external-mcp-server@1.0.0`, Type business system, RequiredAccountType «external-mcp» (маркер маршрута роутера проб), AdapterImplemented true (клиентская машина и проба — реальный продакшн-код, не синтетика), AllowedEnvironments ровно {sandbox, test} — production на карте отсутствует (AG-4 fail-closed на классе: ValidateEnvironment отказывает); capabilities поимённо с полной операционной семантикой прецедента телефонии: query.server-discover (read-only probe), query.tools-list (read-only probe — источник инвентаря), query.tool-call (ProbeAllowed false, честная причина: машина доказана тест-контуром, проверка по конкретному инструменту живого словаря — будущий потребитель Planner 8.3), command.external-tool (мутирующая → ActionGatewayBlock машинально — «мутации внешней системы остаются Connector capability за Action Gateway»), event.server-message (честное нереализованное — stateless-клиент подписок не открывает); поля {endpoint (URL, обязательный), server_label (текст, опциональный), api_key (Secret, обязательный, формат sandbox-…)} — ровно ОДИН секрет (граница MAC-проверки среза: HMAC вычисляется над полной картой секретов подключения). (2) Секреты: connect-путь и запечатывание БЕЗ изменений (MAC — plaintext никогда не персистится/не логируется/не эхо, инвариант 1-8 дословно); проба получает секрет ТОЛЬКО в памяти (VerifyCommand.Secrets), app MAC-проверяет против активного seal (verifySeal: HMAC ключом seal_key над отсортированным name\0value\0 — совпадение вектора = тот же ключ); несовпадение = честный RuleError-отказ; проба класса БЕЗ секрета = честный отказ (неаутентифицированный раунд запрещён fail-closed); ReadSeal — узкое чтение существующих колонок secret_seals (sealed, seal_key) активного seal по (tenant, connection, secret_id, revoked_at is null) — 0 SQL-миграций; MAC-проверка выполняется ДО любого сетевого раунда. (3) Клиентская машина internal/mcpclient: пиннинг 2026-07-28 (методы server/discover, tools/list, tools/call; заголовки Mcp-Method/Mcp-Name + MCP-Protocol-Version, сверяются с телом запроса; версия протокола в _meta; одиночное JSON-RPC сообщение); строгий decode ответа: result XOR error, эхо id, когерентность заявленной версии протокола, размерный бюджет чтения тела (≤ бюджета SizeLimit capability — сверх = честная ошибка машины, не усечение); SDK НЕ вводится — stdlib + поимённые тесты; машина credential-агностична: Authorization-материал — явный параметр вызывающего, машина никогда не хранит/не логирует/не эхо его; ctx-бюджет раунда из декларации TimeoutMS capability. (4) AD-11 (untrusted): ответы внешнего сервера не доверяются нигде: фильтрация дескрипторов при decode до известных полей протокола (name/title/description/inputSchema/outputSchema/annotations), неизвестные поля отбрасываются; инвентарь хранится ФИЛЬТРОВАННЫМ компактным JSON в redacted_result строки evidence (секретов в инвентаре нет по протоколу — и фильтр это гарантирует); аргументы и выход вызова валидируются по закрытой форме спроецированных словарей — undeclared ключ = ошибка, не passthrough; Tenant/authority/destinations никогда не берутся из внешнего материала. (5) Словарь = чистая функция фактов (DeriveCapabilityStates-прецедент): вход = ConnectionsFacts тенента (факты подключений + derived capability reports с evidence-саммари, включая redacted_result инвентаря); запись существует ⟺ живое подключение класса ∧ report query.tools-list несёт applicable evidence ∧ проекция дескриптора успешна; якоря Applicable (connection/SecretID/окружение/пин контракта/билд/UpdatedAt/TTL-24ч) — ротация секрета, save-конфига, смена билда, истечение TTL → запись ИСЧЕЗАЕТ; повторная проба возвращает; нулевая вторая запись состояний. (6) Проекция тотальна для подмножества: корень object; свойства типов {string|integer|boolean} + enum → values + minimum/maximum → min/max (целые) + required → обязательность; title/description дескриптора и readOnlyHint annotations; number с дробной частью/object/array/anyOf/oneOf/прочие ключи JSON Schema = поимённый честный отказ НА ЗАПИСЬ словаря с причиной «схема вне платформенного словаря типизации»; additionalProperties игнорируется (платформа накладывает закрытую форму собственной дисциплиной strict-decode); обратной проекции нет — платформенный словарь типизации остаётся единственным языком записей (Never 7-2 «json-schema.org не вводится» сохранён — проекция это провод, не хранение). (7) Лестница членства FIRST на обеих поверхностях словаря (API + страница): 401 резолвера / честный 404 не-member / 403 словами скоупов integrations|configuration ДО материала — прецедент 3-1/7-2 дословно; машинный контракт OpenAPI зеркалит словарь закрытыми формами. (8) Машина вызова externaltools.Calls: пин записи из ТЕКУЩЕЙ деривации (fail-closed: не допущена → честный отказ поимённо с причиной) → strict-валидация аргументов по спроецированному input → раунд mcpclient с Authorization-параметром вызывающего → strict-валидация выхода по спроецированному output fail-closed; продакшн-вызывателей НОЛЬ (AG-4) — форма закреплена под Planner 8.3 (прецедент формы вызова 7-3); HTTP-поверхности вызова НЕТ. (9) Изоляция тенентов: факты по scope тенента из проверенной личности (AD-11: скоуп из верифицированной личности, не из payload); tenant никогда не приходит из материалов внешнего сервера; кросс-тенентных утечек нет структурно — scope в каждом чтении фактов и каждой деривации. (10) Роутер верификатора internal/adapters/connectorprobe: composition-root, маршрут по RequiredAccountType дефиниции (external-mcp → MCP-проба над mcpclient; иначе → verifier.Synthetic с неизменным поведением); Build() = новая константа «connectorprobe/1.0.0» — прежние evidence (в т.ч. телефонии) читаются stale по дизайну 1-8, операторы перепробывают — честная цена смена verifying-бинарника, фиксация в DEVLOG; BasicCheck маршрутизируется тоже: MCP-класс — формат ключа sandbox-… + форма URL endpoint БЕЗ сети; иначе — Synthetic как есть. (11) Вертикальная чистота: internal/mcpclient + internal/externaltools — платформенные пакеты без вертикальных слов (словарь фраз зонда НЕ растёт; зоны drift_test расширяются двумя пакетами осознанной правкой); вертикальные слова (имена инструментов fixture-сервера) — только тест-контур journeys/httptest.

**Never:** не строить HTTP-поверхность вызова внешних инструментов (страница и API словаря — строго read-only; вызыватель — Planner 8.3, форма закреплена машиной Calls, поверхность не строится); не реэкспортировать внешние инструменты через собственную MCP-поверхность 7-3 (ToolSource 7-3 = глобальный встроенный реестр; ## I/O & Edge-Case Matrix

- Given запрос без личности (резолвер отказал) / принципал — не-member тенента / member без скоупов integrations|configuration, when GET /v1/tenants/{id}/tools/external или страница словаря, then 401 / честный 404 / 403 problem со словами скоупов ДО материала (лестница FIRST — прецедент 3-1/7-2)
- Given тенент без подключений класса (и в продакшн-сборке — подключений класса быть не может: карта без production), then словарь честно пуст (пустой массив разделов, не null) с честной фразой отсутствия
- Given создание подключения класса в окружении production, then честный отказ окружения (AllowedEnvironments ровно {sandbox, test} — AG-4 fail-closed на классе)
- Given connect с малформед endpoint (не URL) или ключом вне формата sandbox-…, then BasicCheck failed (роутер: MCP-ветвь формата) → подключение failed с поимённой причиной; секрет не запечатан (невалидные не хранятся — дисциплина 1-8)
- Given verify capability класса с ключом, не совпадающим с принятым (MAC ≠ seal), then честный отказ «секрет не совпадает с принятым подключением» ДО сети; раунда НЕТ; evidence не пишется
- Given verify capability класса БЕЗ ключа, then честный отказ «проба требует секрет подключения» — неаутентифицированный раунд невозможен fail-closed
- Given verify query.server-discover, внешний сервер отвечает чужой ревизией (2025-11-25 / 2025-06-18) или малформед-конвертом (без result/error, id ≠ запроса, версия некогерентна), then probe outcome failed с поимённой честной причиной (клиент требует ровно 2026-07-28); evidence failed; словарь пуст
- Given verify query.tools-list живой (fixture-сервер ревизии 2026-07-28, ключ MAC-проверен), then раунды discover+list под ctx-бюджетом декларации; evidence verified; redacted_result = фильтрованный компактный JSON-инвентарь (только известные поля дескрипторов, под бюджетом SizeLimit)
- Given тело ответа tools/list сверх размерного бюджета capability, then probe failed с честной причиной бюджета — без усечения и без passthrough
- Given словарь после верифицированной пробы, then раздел подключения с provenance {сервер имя/версия (serverInfo), карточка@версия, evidence id, checked/expires}: записи допущенных инструментов (input/output платформенным словарём типизации) + строки честных отклонений поимённо {«схема вне платформенного словаря типизации (тип number/объект/массив/…)»; «сервер не заявляет read-only (annotations.readOnlyHint отсутствует/ложен)»; «мутация внешней системы — Connector capability за Action Gateway, не инструмент модели»}
- Given инструмент мутации в инвентаре внешнего сервера, then он НИКОГДА не запись словаря (AC-1) — только строка честного отклонения + заблокированная capability command.external-tool на странице подключения
- Given ротация секрета после пробы, when повторное чтение словаря, then записи ИСЧЕЗАЮТ (SecretID-якорь Applicable) — динамика внешнего направления (зеркало 7-3); re-verify с новым ключом → записи возвращаются
- Given save-конфига подключения после пробы (UpdatedAt позже RequestedAt evidence), then записи исчезают (якорь UpdatedAt) — change invalidates evidence
- Given TTL evidence истёк (24ч), then записи исчезают; повторная проба возвращает (словарь обновляется живой командой, не фоном)
- Given смена билда верификатора (Build-константа роутера), then прежние evidence читаются stale → словарь пуст до перепробы (дизайн 1-8 — фиксация в DEVLOG)
- Given изоляция: чтение словаря тенента B, then инструменты подключений тенента A структурно отсутствуют (scope каждого чтения фактов — AD-11)
- Given страница словаря / API, then строго read-only: без форм вызова, без кнопок проб (пробы — существующая поверхность подключения 1-8, 0 правок её транспорта); несуществующий/малформед tenant-путь = 404
- Given Calls-машина (Go-контур): валидные аргументы допущенного инструмента живого подключения, then strict-валидация входа по спроецированному input → раунд с Authorization-параметром вызывающего → strict-валидация выхода по спроецированному output → типизированный результат
- Given Calls с неизвестным ключом / типом не по словарю / вне enum / вне min-max / пропущен обязательный, then поимённый отказ валидации — раунда нет (fail-closed до сети)
- Given Calls инструмента, чья запись исчезла (ротация/TTL/stale) или не допущена, then честный отказ поимённо с причиной гейта (пин из текущей деривации — TOCTOU честно повторным вычислением)
- Given ответ сервера с undeclared ключом или неверным типом в output (fixture-тумблер leaky), then fail-closed ошибка валидации, не passthrough (AD-11 — внутренний материал не пересылается вызывающему)
- Given ctx-бюджет раунда исчерпан, then честная ошибка таймаута (unknown — без слепого retry)
- Given продакшн-сборка main.go, then словарь и поверхности отвечают полноценно, подключений класса быть не может (карта без production — AG-4), Calls-вызывателей НОЛЬ
- Given query.tool-call на существующей странице подключения (представление CapabilityState), then состояние unverified с честной причиной (машина доказана тест-контуром; потребитель — Planner 8.3) — declaration ≠ claim; command.external-tool → ActionGatewayBlock честно
- Given вертикальные фразы словаря зонда в прод-.go internal/mcpclient и internal/externaltools (зоны зонда +2 пакета), then FAIL поимённо — платформенные пакеты вертикально-чисты, словарь фраз НЕ растёт

## Implementation Notes

- Пиннинг ревизии: клиент зеркалит словари серверной машины 7-3 (та же ревизия 2026-07-28, те же SEP: stateless-ядро SEP-2575/SEP-2567, заголовки SEP-2243, кэш-слова SEP-2549 НЕ заявляются); Dev сверяет точные wire-имена полей дескрипторов (name/title/description/inputSchema/outputSchema/annotations) по живому чтению официальной схемы ДО контракт-теста — прецедент wire-пиннинга 7-3 (базовый конверт живым чтением, ревизия-специфичные имена пиннингом платформенных тестов)
- Секрет и MAC: sealSecret вычисляет HMAC-SHA256(seal_key) над отсортированной конкатенацией name\0value\0 — verifySeal зеркалит вычисление над поданной картой; совпадение тождественно равенству секретов (карточка несёт ровно один секрет — граница среза зафиксирована); seal_key читается ТОЛЬКО для MAC-проверки, никогда не покидает вызов verify; ключ и секрет не логируются/не эхо (корреляция — correlation_id как у 7-3)
- Роутер и Build: Build() = «connectorprobe/1.0.0» — ЕДИНАЯ константа роутера; прежние evidence (телефония sandbox/test) станут stale после деплоя — операторы перепробывают; это честная семантика 1-8 «build change invalidates evidence» (fixed в DEVLOG step-01)
