## Intent

**Problem:** Между допуском пилота 4-1 (маршрут parts_catalog_abcp требует capability query.identify-vehicle — декларирована abcp-parts 1.1.0, AdapterImplemented false честно) и фактическим разговором об автозапчастях отсутствует сама ИДЕНТИФИКАЦИЯ АВТОМОБИЛЯ в кейсе: версионированной схемы необходимых идентификаторов нет нигде — Domain Pack auto-parts@2.0.0 несёт только variant-поля настроек (parts_interest, matching_depth), материал-ключи идентификации «не зашиваются в ядро» (AC-1), а в паке их нет; VIN, переданный клиентом текстом или голосом, не нормализуется — исходное значение, нормализованное представление и provenance не разделяются (AC-3), допустимые проверки формата и контрольной суммы не выполняются, кириллические омоглифы (А/В/Е/К/М/Н/О/Р/С/Т/У/Х) молчат или исправляются молчаливо; посимвольный readback VIN не существует (AC-4: латиница/цифры/кириллица не различаются словами, переспроса спорных символов нет); клиент не подтверждает распознанное значение по ТОЧНОЙ версии — слово confirmer «client» зарезервировано словарём 2-2 без продюсера с момента первой записи; защищённая передача VIN при неудобстве голоса или ограничениях канала не связана с существующим защищённым продолжением 2-10 (AC-5/AC-6: продолжение умеет только факт-коррекцию, подтверждения не умеет); полный VIN безнаказанно попадает в диагностические сообщения (AC-9); исправление материального признака не инвалидирует прежнее подтверждение (подтверждение не привязано к точной версии профиля — AC-8); «Work Item содержит структурированные признаки, provenance, версию, время и статус проверки» (AC-12) не материализовано для домена автомобиля.

**Approach:** Модуль `internal/cases` — идентификация есть материал разговора: факты 2-2 уже несут append-only версии с полным provenance и подтверждения, привязанные к ТОЧНОЙ версии; продолжение 2-10 уже есть защищённая клиентская поверхность с токеном-credential и PRG-дисциплиной. Срез добавляет: (1) версионированную схему идентификации — новая версия Domain Pack auto-parts@3.0.0 в каталоге employee/packs (материал-ключи + альтернативные достаточные наборы), доставляемая в cases существующим структурным портом PackTaxonomy (+1 метод по прецеденту PackCriticalEntities — «never a hardcoded list»); (2) VIN-домен (нормализация с флагами без молчаливых исправлений, ISO 3779 контрольная цифра, readback-словарь трёх рядов, маска); (3) DeriveVehicleProfile — чистый read-time вывод профиля над фактами кейса с ProfileDigest («точная версия профиля»); (4) клиентское подтверждение существенных признаков через существующее защищённое продолжение: +1 use-kind (миграция cases/00018 — SQL-зеркало 3→4 слова по прецеденту employee/00013), FactConfirmation с confirmer=client — первый продюсер зарезервированного слова (SQL-CHECK 00002 уже допускает). Поверхности: панель карточки работы + блок публичной формы продолжения + OpenAPI зеркала. Без каталога ABCP/Laximo (адаптер не реализован), без AI/ASR (AG-4), без файлов (media edge), без новых таблиц (одна миграция расширения словаря).

**Ядро честности среза:** Vehicle Profile — ВЫВОД, а не хранимая строка: read-time деривация над append-only фактами (идемпотентность байт-стабильным JSON — прецедент DerivePilotAdmission 4-1 / DeriveContinuationLinkState 2-10), новая таблица профиля НЕ создаётся; подтверждение клиента привязано к ТОЧНОЙ версии факта (2-2 канон) — новая версия признака после подтверждения честно возвращает атрибут в unverified со словом «подтверждение относилось к прежней версии (vN)», ProfileDigest меняется — зависимые результаты (будущие результаты каталога) обязаны считаться stale, срез не заявляет результатов каталога вовсе (ABCP-адаптер не реализован — честное слово, как 4-1); VIN никогда не исправляется молча: омоглифы детектируются и переспрашиваются, контрольная цифра вычисляется и СВЕРЯЕТСЯ словами, автозамены нет ни в одном пути; полный VIN виден ровно в двух местах — защищённая форма клиенту (FR-55: клиент видит распознанное значение и может его исправить) и карточка работы оператору (полномочие review); во всех логах, метриках и problem-диагностике — только MaskedVIN (WMI-3 + последние 4); VIN-hash как идентификатор клиента не строится вовсе (ни солёный, ни несолёный); Staffy не выбирает неоднозначный вариант сам — конфликт значений = conflicting 2-2 + уточнение (AC-7); подтверждение профиля разрешает дальнейший подбор и НЕ разрешает создание заказа или внешнее действие (AC-7 хвост — контур действий Epic 3 не активируется); «минимально необходимые вопросы» материальны границей словаря: обязательность задаёт схема пака, MissingKeys честны, подтверждённые атрибуты не перезапрашиваются; ретенция/удаление VIN — периметр case-content 1-10 reused, нового класса данных нет.

## I/O & Edge-Case Matrix

- Given кейс с пином auto-parts@3.0.0 и фактом vehicle.vin « wf0xxxtt4s1234567 » (пробелы, нижний регистр), when нормализация, then Raw сохранён дословно, Normalized «WF0XXXTT4S1234567», флаги пусты, provenance факта неизменен — AC-3.
- Given VIN с кириллической «А» среди латиницы (позиция i), when нормализация, then CyrillicAmbiguities [{i, «А», look-alike «A»}], normalized сохраняет кириллицу (НЕ заменяет), honest-слово «позиция i: кириллица, требуется сверка», readback-фокус переспрашивает только её — AC-3 хвост + AC-4.
- Given VIN с латиницей I, O или Q, when нормализация, then ForbiddenChars с позициями + слово «буквы I, O, Q в VIN не используются — сверьте позицию», значение не отбрасывается и не заменяется.
- Given нормализованный VIN длины ≠ 17, when нормализация, then LengthOK false + слово «длина N ≠ 17», атрибут остаётся unverified, профиль не становится полным по vin-набору.
- Given 17-символьный VIN (без запрещённых/омоглифов), when контрольная цифра, then CheckDigit {Expected позиция-9, Computed, Match} — несовпадение = флаг + «контрольная сумма не совпала — сверьте посимвольно», НЕ отбрасывание; европейский VIN без актуальной проверки — Applicable честно по алфавиту/вычислимости, ложных verdicts нет.
- Given оператор открыл карточку работы кейса с пином auto-parts@3.0.0, when карточка, then панель «Идентификация автомобиля»: атрибуты из схемы пака (зонд: материал-ключи приходят из PackTaxonomy — hardcoded-список в cases отсутствует), MissingKeys честным списком (только неподтверждённые — подтверждённые не перезапрашиваются AC-2).
- Given кейс с пином пак без VehicleIdentification (montagio-services@1.0.0 либо unreadable pin), when карточка, then панель отсутствует с честным словом «схема идентификации пака не определена» — деградация прецедента 2-2, НИКАКОГО хардcode-набора.
- Given оператор выпустил защищённую ссылку (существующая форма 2-10, цель fact_correction, вопрос «подтвердите автомобиль»), when клиент открыл, then форма: ПОЛНЫЙ VIN + readback-слова текстом (блоки 4-4-4-4-1, различение латиница/цифры/кириллица словами), атрибуты с каналом provenance, кнопки «Подтверждаю»/исправить/«Позвать человека»/«Вернуться в разговор» — AC-5/AC-6 (голосовой канал не обязателен: защищённая веб-поверхность).
- Given клиент нажал «Подтверждаю» (атрибуты текущих версий), when POST, then FactConfirmation {confirmer=client, bind ТОЧНЫЕ версии} + use {vehicle_confirmation_submitted} одной транзакцией, PRG 303, лимит ссылки потреблён; повторный клик = consumed-терминальная страница 2-10.
- Given подтверждённая версия vehicle.make (v3), when оператор записал новую версию факта (v4), when деривация, then атрибут unverified + слово «подтверждение относилось к прежней версии (v3)», ProfileDigest изменился — зависимые результаты обязаны считаться stale (AC-8), срез выводит honest-слово «результаты каталога отсутствуют — ABCP-адаптер не реализован (AG-4)».
- Given два значения vehicle.make от разных источников (channel_event и operator), when деривация, then conflicting (read-time 2-2) + «Staffy не выбирает вариант — уточните у клиента» (AC-7), профиль не полный по attributes-набору.
- Given подтверждение профиля выполнено, when любые операции среза, then НИКАКОГО создания заказа/внешнего действия (контур Epic 3 не активируется — AC-7 хвост «само по себе не разрешает создание заказа или внешнее действие»).
- Given VIN попадает в problem-ответ, logger-поле или метрику, then ТОЛЬКО MaskedVIN (первые 3 + … + последние 4); полный VIN — ровно две поверхности: защищённая форма клиенту и карточка оператора (AC-9).
- Given use_kind вне словаря 4 слов, then невозможен: compile-time словарь домена + SQL-CHECK миграции 00018 (зеркала, drift = красный).
- Given просроченная/отозванная/чужая-тенент ссылка подтверждения, then ЕДИНЫЙ generic refusal без раскрытия причины (2-10 канон — причины не различаются клиенту).
- Given повторная деривация профиля без изменений мира, then ТОТ ЖЕ вывод байт-стабильно (JSON ×2), записей НЕТ (счётчики фейк-репо на нуле в read-пути).
- Given публичная форма при клавиатуре/screen reader/320px/увеличенном тексте, then readback и флаги читаются ТЕКСТОМ, ошибки/неопределённость — не только цветом, текстовая альтернатива голосовому readback существует всегда — AC-14.
- Given зонд import-graph, then прод 0 × сетевых вызовов в пути идентификации (ни каталога, ни адаптеров; DeriveVehicleProfile — чистая функция над фактами).

## Implementation Notes

- Решение модуля: идентификация — материал кейса (cases), схема — материал Domain Pack (employee/packs): связка через существующий структурный порт PackTaxonomy (AD-2 — DAG не нарушен, импорта employee в cases НЕТ; immutability каталога в бинарке — TOCTOU между пином и чтением отсутствует, аргумент порта 2-2).
- Профиль — read-time вывод (семейство DerivePilotAdmission 4-1 / DeriveContinuationLinkState 2-10 / DeriveCapabilityStates 1-9): новая таблица НЕ создаётся; «точная версия профиля» = ProfileDigest (SHA-256 канонического JSON {ключ: версия+value-digest}); будущие результаты каталога (срезы после адаптера) обязаны пиннить digest — stale-механика заявлена словарём и словом, материальный потребительdigest — будущий срез (honest-граница, задокументирована).
- Подтверждение клиента = активация зарезервированного слова словаря 2-2 («client» в ConfirmerTypes без продюсера с первой записи; SQL-CHECK 00002 допускал всегда) — расширение словаря продюсером, НЕ словом: это законное продолжение канона 2-2 (срез не добавляет слово — даёт ему производителя); единственное НОВОЕ слово среза — use-kind vehicle_confirmation_submitted (SQL-зеркало 00018 по прецеденту employee/00013: словари-зеркала — материальные зеркала, расширение = миграция append-only).

- VIN-нормализация: исходное значение — факт (raw), нормализованное — вычисление вывода (не хранится); автозамены НЕТ ни в одном пути (омоглифы/запрещённые/длина/контрольная цифра — флаги + слова); check-digit ISO 3779 вычисляется для полного 17-символьного нормализованного VIN без запрещённых символов, Applicable=false для нестандартных — честно (евро-VIN без актуальной цифры не получает ложного verdict).
