## 4. Что сработало — перенести в Epic 4

1. **Write-ahead lease + fencing-токен + persist-before-emit — стержень конвейера.** Ни одна запись исхода не пишется без захваченной lease; submitted фиксируется ДО сетевого вызова; устаревшая запись отвергается fencing-парой (attempt_no + lease_token); гонки двух операторов/параллельных сверок закрыты advisory-замками с типизированными конфликтами и аудитом ОБЕИХ попыток. Unknown ≠ failed — слепой повтор запрещён структурно.
2. **Идемпотентность семействами keyed-HMAC префиксов.** commitment:v1: / external_commitment:v1: / action_preview:v1: / business_intent:v1: / dispatch_key:v1: / recovery_key:v1: — сырые несолёные хэши запрещены (AD-10); один бизнес-интент = одна Operation (UNIQUE структурно); один провайдер-вызов = один dispatch_key на операцию, стабильный между попытками (повтор несёт тот же ключ — провайдер дедупит, новый intent НЕ создаётся).
3. **SAFE-payload дисциплина.** Outbox/квитанции/бандлы несут только ids/пины версий/слова/счётчики/64-hex дайджесты — материал НИКОГДА не покидает свои immutable-строки; Recovery Case = минимальные ссылки вместо копирования (AC-9 структурно). Телефон материала не входит даже в journeys (AD-10).
4. **Словари честных слов compile-time + enum-зеркала OpenAPI контракт-тестами.** Каждый доменный словарь (режимы control 4, delivery 4, исходы адаптера 4, вердикты сверки 3+no_answer, ledger 8, триггеры recovery 3, recovery-виды 5+2, состояния видов 3) пиннится зеркалами — drift = красный; вне-словарное слово не выводится и не хранится (AD-7). Тексты границ PRD переносятся дословно и пиннятся байт-стабильностью.
5. **Живые матрицы интеграции поверх reused-миров.** Единственная Major-находка эпика (INSERT без tenant_id → RLS WITH CHECK отказ живьём) поймана ТОЛЬКО живой матрицей — unit-фейки структурно не видят RLS. Правило: первая миграция модуля = первая живая матрица; миры предыдущих историй reused (матрица 3-9 целиком поверх мира 3-8).
6. **Read-time деривация вместо записи, когда запись не нужна.** 3-9 — первый срез эпика без SQL: политика = чистый вывод из записанного, идемпотентность выводом (×3 DeepEqual байт-стабильно), зонд нулевых записей живым PG. Экстремум принципа «состояния — чистые функции read-time» из Epic 2, доведённый до отсутствия таблиц.
7. **session-start.sh + порядок доверия — инвестиция 135-infra.** Устаревание платформенных сводок ×19+ подряд в первой трети эпика деградировало позицию сессий; после внедрения (одна команда, ~1 секунда, read-only: git-факты/RPO/DEVLOG next/sprint-status/worklog/check-continuity, честная деградация без токена/сети) восстановление позиции = ~2 минуты по порядку доверия git > sprint-status.yaml > DEVLOG > пересказ. Хвост эпика (3-5…3-9) отставания сводок больше не останавливал.
8. **Батч-дисциплина журнала.** 56 записей против 131 у Epic 2 при бо́льших шагах: push батчем, промежуточные записи только на реальных событиях (push-stop/разблокировка/инфра-находки). Журнал остался достаточным для восстановления позиции каждой сессией.
9. **Surgical-правки замороженных секций.** Все 9 историй расширяли код surgical-правками; QA-дифф 3-9 поимённо: 18 файлов +3247/−8, замороженные секции спек 3-1..3-8 не тронуты, −8 = флипы статусов/расширения списков. Правило 161 (смена доменного слова = journeys-сьют обязателен) соблюдено на 3-8/3-9: замороженные слова байт-стабильны, новые пиннятся.
10. **Протокол CI ×3 + sha-pinned merge.** 9/9 merge-точек зелёные поимённо; пин слияния в теле PR; mergeable True/clean проверяется ДО merge; ветки удаляются по MERGED-зонду после поручения владельца.

1. **Устаревшие сводки контекста ×19+ до 135-infra.** Корень: платформенная автокомпакция диалога не контролируется — сводка отстаёт на стадии при живом git-факте («story 3-1 step-05» при закрытой 3-2). Закрыто СТРУКТУРНО внутри эпика (134-расследование трёх уровней → 135-infra: session-start.sh + AGENTS.md «сводка — НЕ источник истины» + протокол возобновления 5 шагами, drilled на fresh clone: гейт ориентации 1 секунда при бюджете 300). В отличие от Epic 2, где отставание ловилось только вручную.
2. **Токен — по-прежнему единственный хрупкий канал.** Одна верифицированная смерть (3-2 CHECKPOINT 1, 401 × 6) → push-долг 2 коммита, RPO=2 временно, разблокировка при живом токене; ≥15 передач открытым текстом за эпик (24 упоминания ревокации в DEVLOG); env-only per-invocation выдержан без исключений. Ревокация владельцем так и не исполнена (retro-2-6 → retro-3-6).
3. **Слой инструментов искажает записи — три класса (3-2 step-04, пятый прецедент за проект).** (а) Edit переиндентирует легаси-файлы целиком — 3 поимки (fixture_server.go 1611 строк, store/postgres.go 449, tenant_test.go 1169): откат git checkout + хирургические байтовые вставки python-скриптами с exact-анкорами, верификация git diff --stat + gofmt -l; (б) слой записи мутировал кавычку ord39→ord96 в z30 (unterminated string, пойман машинным вердиктом playwright): починка по ord-кодам, байтовая проверка парности; (в) слой отображения поглощает двухсимвольные последовательности (retro-2-4 подтверждён и расширен на grep/playwright-кадры: несуществующее 'formethod' при корректном файле). Противоядие общее: верить только машинным вердиктам (прогонам/parse/счётчикам), не чтению глазами.
4. **Латентный пробел check-continuity (138-infra).** Чтение статуса спеки байтовым окном read(2500): title спек растёт от среза к срезу, статус 3-5 оказался в байте 3005 — чекер слеп к рассинхрону, вскрылось первым же прогоном ПОСЛЕ коммита спеки (SM-сессия гоняла чекер ДО коммита — спеки ещё не было в дереве). Урок: байтовые окна против растущих документов — отложенная мина; границы парсить структурно; чекер гонять сразу после каждого статусного коммита.
