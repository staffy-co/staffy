## Intent

**Problem:** Epic 1 настроил все компоненты ИИ-сотрудника по отдельности (Brief, Domain Pack с Tenant-вариантами, Knowledge Sources, поведение, голос, подключения с capabilities, периметр данных, entitlement), но нигде не существует версионированного сочетания конфигурации: нельзя точно сказать, какая комбинация версий компонентов тестировалась, публиковалась или восстанавливалась. Нет конфигурационной версии со стабильным идентификатором, монотонным номером, автором и описанием изменения; нет Release Manifest, связывающего конфигурацию с Connection IDs, версиями контрактов и adapter builds, применимыми capability evidence и runtime-компонентами; нет канонического digest и неизменяемого снимка; отсутствующие/просроченные/неподтверждённые capabilities нигде не фиксируются как явные gap-ы; интерфейс не отличает проверяемого кандидата от допущенного release; восстановление из прошлой версии не создаёт новый draft с отчётом о несовместимостях. Readiness (Stories 1.13–1.14) не имеет объекта проверки: нечего связывать с Operating Profile, eval и стадиями трафика.

**Approach:** Ввести в модуле `employee` (владелец релиза по спайну) два append-only артефакта и один mutable черновик. Конфигурационная версия — immutable снимок ссылок: точные версии Employee Brief (draft version), Domain Pack (id, версия, Tenant-варианты), поведения, Knowledge Sources (source_id + версия каждого) и Voice; монотонный номер на Employee, actor, время, описание изменения; отсутствие компонента фиксируется честной записью отсутствия, а не пустотой. Release Manifest запечатывается из конфигурационной версии: содержание — детерминированный канонический JSON (фиксированный порядок полей, отсортированные массивы) с sha256-digest; статус `candidate|incomplete` выводится из присутствия компонентов (в этом срезе runtime-компоненты — model/media routes, prompt assembly, tool schemas, policy bundle, eval set, runtime build, autonomy envelope — не имеют поверхностей, поэтому запечатанный manifest честно `incomplete` с перечнем компонентов и их владельцев). Манифест включает Connection IDs без секретов, версии Connector contracts, adapter builds, среды и производные состояния capabilities с evidence-ссылками; непроверенная, просроченная или неподтверждённая capability — явный gap, не подменяемый возможностью другого аккаунта или провайдера. Сборка/обновление черновика — mutable draft с ревизией для optimistic concurrency: параллельные попытки запечатать одну draft-ревизию дают ровно один manifest, вторая — конфликт с актуальным состоянием для сравнения; под одной конфигурационной версией не может быть двух манифестов (UNIQUE). Восстановление — новый draft, ссылающийся на выбранную версию как источник, с честным отчётом несовместимостей против текущего каталога и фактов подключений; прошлые версии, манифесты, evidence и внешние эффекты не изменяются. Чтение манифеста — по версии схемы: неизвестная версия или неизвестные поля дают явное состояние quarantine с причиной, без молчаливого отбрасывания; digest перепроверяется при чтении. Допуск/release — никогда: манифест всегда «проверяемый кандидат», направления трафика и admission остаются за Story 1-14 и GATE-REGISTRY.

**Решение владельца:** ожидает CHECKPOINT 1. Предложение SM: первый срез — локальный контур по образцу Stories 1-9/1-10/1-11: конфигурационная версия собирается из существующих фактов модулей (без новых поверхностей настройки); манифест запечатывается с честным `incomplete` (runtime-компонентов в системе ещё нет — это фиксируется как явные gap-ы с владельцами, а не как успех); статус `candidate` и полный набор компонентов покрыты доменной функцией и юнит-тестами (как `admission_state` в 1-11); commit/release pointer, admission, traffic stages и gate-компиляция — Story 1-13/1-14 и Epic 2; миграционные сценарии schema_version — чтение текущей версии и честный quarantine неизвестной, полный upgrade/rollback-конвертер появится с первой реальной сменой схемы.

## Boundaries & Constraints

**Always:** Конфигурационная версия создаётся только командой обладателя полномочия `configuration` (Owner по умолчанию) с optimistic concurrency по ревизии draft: присваивается стабильный идентификатор, монотонный номер на Employee, время, actor и описание изменения (1–300); версия ссылается на точные версии Employee Brief, Domain Pack (id, версия, Tenant-варианты), поведения, Knowledge Sources и Voice Profile; отсутствующий компонент записывается честной записью отсутствия с пояснением; ранее созданная версия неизменна (append-only, гранты INSERT/SELECT без UPDATE/DELETE). Release Manifest формируется из конфигурационной версии и фактов подключений на момент запечатывания: фиксирует Connection IDs без секретов и их подсказок, версии Connector contracts, adapter builds, среды, состояния подключений и применимые capability evidence (evidence_id, outcome, время, срок) с честной причиной каждого состояния; отсутствующая, просроченная или неподтверждённая capability сохраняется как явный gap с причиной и владельцем reconciliation, gap не подменяется возможностью другого аккаунта или провайдера (состояния выводятся из фактов конкретного подключения). Runtime-часть манифеста перечисляет компоненты model/media routes, prompt assembly, tool schemas, policy bundle, eval set, runtime build и autonomy envelope: отсутствующий компонент делает manifest `incomplete` с указанием владельца; модель или поставщик не заменяются внутри запечатанного manifest — любая материальная перемена требует новой версии и нового запечатывания. Изменение входящего компонента после запечатывания создаёт или обновляет только mutable draft (новая ревизия, CAS); запечатанный manifest и его digest не изменяются; зависимые preview/eval результаты помечаются `stale`, если их входные версии больше не совпадают (существующий вывод staleness voice-preview по версиям сохраняется). Запечатывание выполняется только обладателем `configuration` под ожидаемой ревизией draft в транзакции с блокировкой строки: система вычисляет канонический digest содержимого, сохраняет неизменяемый снимок со статусом `candidate` или `incomplete`; секреты, подсказки секретов, raw PII, transcripts и содержимое защищённых медиа в версию и манифест не включаются (только идентификаторы, версии, состояния, счётчики и digest); под одной конфигурационной версией существует не более одного манифеста (UNIQUE), попытка второго — честный конфликт. Манифест без утверждённого Operating Profile и обязательных gate evidence просматривается с явным сообщением «проверяемый кандидат, а не допущенный release»: недостающие зависимости и их владельцы перечисляются (runtime — AI Runtime/Epic 2 и Technical Lead; Operating Profile — Story 1.13; gates — владельцы GATE-REGISTRY); направить на manifest internal, controlled или live traffic нельзя — поверхностей направления трафика в системе нет, публикация и admission остаются за Story 1-14. Восстановление из прошлой версии: выбор обладателем `configuration` создаёт новый draft, ссылающийся на выбранную версию как источник, и показывает устаревшие Connectors, capabilities, policies и другие несовместимости против текущих фактов; прошлые версии, манифесты, evidence, receipts и уже произошедшие внешние эффекты не изменяются. Чтение манифеста идёт по версии схемы: manifest текущей или непосредственно предыдущей поддерживаемой версии обрабатывается совместимо; неизвестная версия схемы или неизвестные поля — явное состояние `quarantine` с причиной, payload не отбрасывается молча; digest пересчитывается из сохранённого содержания при чтении, расхождение — честный quarantine о нарушении целостности. Полномочия применяются на сервере до SQL: сборка draft, создание версии, запечатывание и восстановление — только `configuration`; просмотр версий и манифестов — `configuration`, `review` или `audit`; участники без этих полномочий получают честный отказ; данные другого Tenant недоступны через UI, API и журналы (RLS во всех таблицах). UI: версия, состояние, digest, автор, время и изменённые компоненты доступны текстом; сравнение версий не зависит только от цвета; длинные идентификаторы (digest, UUID) переносятся или прокручиваются внутри своего блока без горизонтального скролла страницы; клавиатура, screen reader, 320 px, цели ≥44×44 px; результат запечатывания/конфликта объявляется доступно (aria-live) без неожиданного перемещения focus.

**Never:** Не включать секреты, подсказки секретов, raw PII, transcripts или содержимое защищённых медиа в конфигурационные версии и манифесты. Не изменять и не удалять созданную версию или запечатанный манифест (грантов UPDATE/DELETE нет; digest фиксирует целостность). Не создавать второй манифест под одной конфигурационной версией и не «проглатывать» гонку запечатывания — конфликт возвращается честной ошибкой. Не выдавать отсутствующий компонент за присутствующий и не показывать `candidate` при отсутствующих компонентах; не подменять gap по capability возможностью другого аккаунта, подключения или провайдера. Не заявлять допущенный release, approved-статус или направление трафика: манифест — проверяемый кандидат; admission и публикация — Story 1-14 + GATE-REGISTRY. Не отбрасывать молча неизвестные поля, старые payload-ы или неизвестную версию схемы при чтении манифеста — только явный quarantine с причиной. Не заменять ссылку на точную версию компонента «текущим состоянием»: снимок фиксирует версии, позднейшие изменения не переписывают прошлое. Не позволять управление версиями без полномочия `configuration` и просмотр без `configuration|review|audit`. Не «мигрировать» манифест на месте: смена схемы — новая версия схемы с явным конвертером и проверяемыми upgrade/rollback-сценариями. Не изменять при восстановлении прошлые версии, манифесты, evidence, receipts и внешние эффекты. Не заменять честное сравнение при конфликте (ожидаемая/текущая ревизия и ссылки) молчаливым перезапуском операции.

**Acceptance Criteria:**
- Given сохранённый черновик Employee, when уполномоченный настройщик создаёт новую конфигурационную версию, then система присваивает ей стабильный идентификатор, монотонный номер, время, actor и описание изменения; версия ссылается на точные версии Employee Brief, Domain Pack, Tenant-вариантов, поведения, Knowledge Sources и Voice Profile; ранее созданная версия остаётся неизменной; отсутствующий компонент записан честно.
- Given подключённые интеграции, when формируется Release Manifest, then он фиксирует Connection IDs без секретов, версии Connector contracts и adapter builds, среду и применимые capability evidence; отсутствующая, просроченная или неподтверждённая capability сохранена как явный gap; gap не подменён возможностью другого аккаунта или провайдера.
- Given настроенный AI Runtime, when формируется manifest, then он связывает точные model/media routes, версии prompt assembly, tool schemas, policy bundle, eval set, runtime build и autonomy envelope; отсутствующий компонент делает manifest `incomplete`; модель или поставщик не заменены внутри запечатанного manifest (в этом срезе runtime-компоненты честно перечислены как отсутствующие с владельцами).
- Given конфигурационная версия ещё редактируется, when настройщик изменяет входящий компонент, then система создаёт или обновляет только mutable draft; запечатанный Release Manifest не изменяется (digest неизменен); зависимые preview/eval результаты `stale` при несовпадении входных версий.
- Given все доступные компоненты выбраны, when настройщик запечатывает Release Manifest, then система вычисляет канонический digest/hash его содержимого; manifest становится неизменяемым снимком со статусом `candidate` или `incomplete`; secret values, raw PII, transcripts и содержимое защищённых медиа в него не входят.
- Given manifest ещё не имеет утверждённого Operating Profile или обязательного gate evidence, when пользователь просматривает его, then интерфейс явно сообщает, что это проверяемый кандидат, а не допущенный release; недостающие зависимости и их владельцы перечислены; направить на него internal, controlled или live traffic нельзя.
- Given две параллельные попытки запечатать одну draft-версию, when одна уже изменила ревизию, then вторая завершается конфликтом optimistic concurrency с актуальным состоянием для сравнения; пользователь может создать новый draft; система не создаёт два разных manifest под одним version ID.
- Given настройщик выбирает предыдущую конфигурационную версию, when он начинает восстановление, then система создаёт новый draft, ссылающийся на выбранную версию как источник, и показывает устаревшие Connectors, capabilities, policies и другие несовместимости; прошлые Action Receipts, evidence и внешние эффекты не изменяются.
- Given contract или schema обновляется в пределах rollout, when система читает manifest текущей или непосредственно предыдущей поддерживаемой версии, then он обрабатывается совместимо либо помещается в явное состояние quarantine; неизвестное поле или старый payload не отбрасывается молча; digest перепроверяется при чтении.
- Given список версий и Commitment Review кандидата, when пользователь работает с клавиатурой, screen reader, увеличенным текстом или 320 px, then версия, состояние, digest, автор, время и изменённые компоненты доступны текстом; сравнение версий не зависит только от цвета; длинные идентификаторы переносятся или прокручиваются внутри своего блока без горизонтального скролла страницы.

## Implementation Notes

- Каноническая сериализация: `encoding/json` структур с фиксированным порядком полей (не map); массивы детерминированно отсортированы (подключения по connection_id, capabilities по id, знания по source_id); digest — sha256 от канонических байтов, hex (char(64)).
- Runtime-словарь фиксирован в домене: `model_route, media_route, prompt_assembly, tool_schemas, policy_bundle, eval_set, runtime_build, autonomy_envelope`. В этом срезе ни один компонент не имеет поверхности: каждый записан gap-ом с владельцем (AI Runtime — Epic 2, ответственный Technical Lead); из-за честных runtime gap-ов запечатанный манифест всегда `incomplete` — статус `candidate` выводится доменной функцией и покрыт юнит-тестом на полном наборе (прецедент — `admission_state` 1-11).
- Adapter build и contract version берутся из фактов connector-модуля (константа сборки адаптера и `Connection.ConnectorVer`, как в CapabilityState); среда — `Connection.Environment`; в content попадают только идентификаторы, версии, состояния, evidence-ссылки — никогда секреты и их подсказки.
- `release_drafts` — единственная mutable таблица среза: UPDATE нужен для ревизии CAS и ссылок; `config_versions` и `release_manifests` — INSERT/SELECT only. Монотонный номер версии вычисляется в транзакции создания (MAX+1 под блокировкой строки draft).
- Конфликт запечатывания: ответ содержит ожидаемую и текущую ревизию и ссылки текущего draft — сравнение для пользователя; «создать новый draft» = повторная сборка (assemble) с новыми фактами.
- Восстановление не копирует содержимое компонентов (они immutable — ссылки валидны вечно), а фиксирует ссылки выбранной версии как источник нового draft; отчёт несовместимостей сверяется с текущим каталогом Pack (доступность версии), текущими состояниями подключений и применимостью capability evidence, текущими версиями знаний.
- Staleness preview: voice-preview уже выводит `stale` по несовпадению версий (Story 1-7); манифест не трогает существующие preview-записи — только не заявляет их актуальность.
- Полномочия: управление — `configuration` (Owner по умолчанию); просмотр — `configuration|review|audit`; отказ бес прав — честная ошибка на сервере (как в entitlement: одинаковая фильтрация для JSON и HTML — уровень вычисляется в сервисе).
- Проверки на текущем дереве: `go test ./...`, `go vet ./...`, `go test -tags=integration ./tests/integration/...`, `npm test --prefix tests/journeys`, контракт-тест OpenAPI, `git diff --check`.

## Design Notes

- Размещение в модуле `employee` соответствует спайну epic-1-context («employee — настройкой, профилем и релизом») — на этот раз без отклонения от архитектурной строки (в отличие от `privacy`/`entitlement`, где отклонения документированы).
- Факты подключений собираются через узкий порт в `employee/app` к `connector`-модулю (List + CapabilityState): employee — потребитель готовой честной деривации, повторного вывода состояний capabilities в employee нет (одна истина — connector/domain.DeriveCapabilityStates).
- Указатель активного release (release pointer), связывание turn/Operation с манифестом, компиляция gate-зависимостей и стадии трафика — Story 1.13/1-14 и Epic 2: манифест первого среза — проверяемый кандидат без допуска.
- Экспорт манифеста не строится (поверхности экспорта нет); изоляция утверждается для всех существующих поверхностей: UI, API, журналы, RLS.
- Схема манифеста: `schema_version` в строке; сейчас поддерживается только текущая версия; честный quarantine неизвестной — обратимая позиция: первая реальная смена схемы добавит явный конвертер с тестами upgrade/rollback, не изменяя прошлое.
