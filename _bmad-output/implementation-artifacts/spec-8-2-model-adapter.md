## Intent

**Problem:** Контракт хода 8-1 закрыл протокольную машину «мозга» (формы, strict decode, repair ×1, персистимая честность, fallback), но адаптерная сторона осталась пустотой: (1) ПРОМПТ не существует ни в какой форме — путь от Turn Context к материалу модели не построен: сегодня scripted-модель синтезирует прямо из контракта (тест-материал), а любой будущий живой адаптер собирал бы промпт по-своему — ровно «неотслеживаемый промпт», от которого Story 8.2 требует избавиться («каждый ход … никогда не зависел от неотслеживаемого промпта»); сборка должна быть версионируемой платформенной формой, иначе AR-17 нечего пинить в Release Manifest; (2) БЮДЖЕТЫ не существуют: AD-7 требует «tool rounds, execution time and cost are bounded», но ни одна машина не ограничивает время/стоимость модельного раунда — исчерпание сегодня неотличимо от молчаливого продолжения; раунды ≤2 структурны формой машины 8-1 (это уже честно), время/стоимость — параметрическая сторона, которой нет; (3) §8.1-пин раскрытия ИИ закреплён в контракте контекста (AIDisclosureRequired), но НЕ доезжает до материала модели — закрепление «в контракте хода» требует, чтобы пин входил в собранный материал (модель обязана видеть требование); (4) RuntimeDictionary несёт устаревшие gap-записки: prompt_assembly/runtime_build/model_route объявлены «поверхность ещё не существует» — после 8-2 это ложь для prompt_assembly (сборка существует) и runtime_build (идентичность сборки рантайма существует), а model_route требует честной специфичной записки (форма есть, живого маршрута нет — AG-4); владелец-метка «AI Runtime (Epic 2)» устарела (факт DEVLOG 323, отложен в кодовой срез — этот срез и есть кодовой); (5) журнал хода несёт Provenance выхода (schema_version предложения, Build машины), но не входа — запись не отвечает, какой версией сборки собран промпт и какими бюджетами ограничен ход.

**Value:** срез закрывает адаптерную сторону «мозга» так, чтобы живая модель (за AG-4, с вызывателем 8.4) вошла в ГОТОВЫЕ тиски: промпт — версионируемая детерминированная платформенная форма (проверяемость = детерминизм + версия: материал пересчитываем из контекста, персистенции материала НЕТ — без дублирования PII-материала дела, AD-10/AD-11); модель структурно видит только материал (AD-8 evidence-скоупинг по построению, не по дисциплине адаптера); бюджеты — закрытые формы с честным исчерпанием (unknown + fallback, без слепого retry — AD-7 дословно); манифест честно пинит компоненты рантайма (AR-17); журнал несёт полную Provenance хода (вход+выход+бюджеты). Всё, что строится позже (tool-раунды 8.3, вызыватель 8.4, eval 8.5, телеметрия 8.6), входит в готовые формы.

## Boundaries & Constraints

**Always:** (1) Сборка промптов — версионируемая платформенная форма internal/planner/assembly.go: AssembleRoundMaterial(context TurnContext, repair string) → RoundMaterial — закрытая форма, детерминированная (фиксированный порядок полей, JSON), с версией сборки (слово сборки — платформенная константа, дух Build-константы машины); материал несёт: слово версии сборки, референсы хода (tenant/case/conversation/work item/employee/turn), подтверждённые факты С ПОЛНОЙ Provenance {источник, версия, время} — AD-8: authority/source/version/time, режим + активную лестницу (зеркало ModeLadder), пины политики РЕФЕРЕНСАМИ (id@версия — материал политик НЕ входит: сборщик материала за политиками — будущая поверхность), инвентарь read-инструментов (имя@версия + типизированные схемы входа — словарь tools.ToolFieldTypes без расширения), пин §8.1 раскрытия ИИ (bool контракта входит в материал — модель обязана видеть требование), fallback-политику хода, бюджет реплики, версию схемы предложения + закрытые словари формы (intent/mode/safety/union-виды — модель отвечает в форму контракта), repair-причину поимённо (второй раунд). Материал — ТОЛЬКО вход модели: не персистится (ни журнал, ни отдельная таблица; проверяемость = детерминизм + версия), скрытой цепочки рассуждений нет (AD-8), извлечённого материала нет (форма закрыта — вход извлечения не существует; операционные факты FR-20 не подменяемы по построению), секретов нет (AD-11). (2) ModelPort эволюционирует: Round принимает МАТЕРИАЛ раунда (не контекст) — модель структурно не видит сырого Turn Context; адаптер ошибок остаётся адаптером ошибок (поток машины 8-1 неизменен: failed + fallback без слепого retry); рефайнмент ожидания 8-1 «сборка на стороне адаптера» сознателен и документирован: платформенная сборка — единственный способ исключить неотслеживаемый промпт (адаптер не может собрать свой промпт — ему не дают контекста). (3) Бюджеты — закрытые платформенные формы internal/planner/budgets.go: Budgets{MaxRounds, RoundTimeout, RoundCostUnits, MaxCostUnits} — валидация при построении поимёнными отказами: MaxRounds ∈ [1,2] (бюджет НИКОГДА не расширяет структурную границу машины — только сужает), RoundTimeout > 0, стоимости ≥ 0, MaxCostUnits ≥ RoundCostUnits (ход хотя бы одного раунда декларируем). (4) Ограниченный адаптер internal/adapters/modelbounded: обёртка над любым ModelPort — гард раундов (счётчик вызовов: сверх MaxRounds = поимённая ошибка бюджета), дедлайн раунда (context.WithTimeout(RoundTimeout): истёк = поимённая ошибка таймаута бюджета), стоимостной учёт (кумулятив RoundCostUnits: сверх MaxCostUnits = поимённая ошибка стоимости); ЛЮБОЕ исчерпание = честная ошибка адаптера → машина 8-1 завершает ход failed + утверждённый безопасный fallback — исход unknown, без слепого retry, без молчаливого продолжения (AD-7); ошибки бюджета поимённы в RefusalReason записи журнала. (5) Журнал хода расширяется миграцией migrations/planner/00002: колонки assembly_version (слово версии сборки; NULL для истории до 8-2 — честное отсутствие: те ходы шли без сборки) + budgets (компактный JSONB декларации Budgets; NULL для истории — честное отсутствие); UPDATE/DELETE прежних записей запрещены правами (append-only грантами 8-1 — не трогается); новые записи несут полную Provenance хода {версия сборки входа, декларированные бюджеты, schema_version предложения, Build машины}; запись бюджетов в запись хода — декларация, соблюдение которой доказуемо исходами (исчерпание = поимённая причина). (6) RuntimeDictionary честные presence — surgical-правка internal/employee/domain/release.go: BuildRuntimeState выводит для НОВЫХ seal: prompt_assembly → Present=true, Ref=слово версии сборки (поверхность существует платформенно с этого среза — прецедент tool_schemas 7-2: поверхность есть, продакшн-вызыватель позже 8.4); runtime_build → Present=true, Ref=составное слово идентичности рантайма (Build машины + версия сборки — когерентно журналу: запись хода несёт те же слова); model_route → Present=false, записка становится специфично-честной: «Форма маршрута модели и ограниченный адаптер построены (Story 8.2); живой маршрут и model-credentials — за AG-4; первый продакшн-маршрут — с вызывателем 8.4»; владелец-метка словаря «AI Runtime (Epic 2)» → «AI Runtime (Epic 8)» (7 строк компонент; media_route не трогается — его эпик 9); sealed-история НЕ пересчитывается (AD-10) — производные только новых seal, прежние манифесты несут свои запечатанные слова; сигнатура BuildRuntimeState НЕ меняется (производные платформенно-статичны внутри — вызовы app/release.go и fixture не трогаются, если Dev-фаза не найдёт более честную форму с явными входами). (7) Scripted-модель эволюционирует: синтез ИЗ МАТЕРИАЛА (не из контракта) — матрица исходов 8-1 сохраняется {valid, malformed_undeclared, malformed_type, foreign_version, repairable, unrecoverable, adapter_error}, валидный материал зеркалит материал раунда (mode из материала, §8.1-пин доезжает); это доказательство полноты сборки: scripted-модель отвечает ТОЛЬКО на то, что прибыло в материале. (8) Составы для тестов: machine(bounded(scripted)) — бюджеты исполняются в живых Go-прогонах; продакшн-composition НЕ подключает планировщик (main.go — 0 правок; вызыватель 8.4). (9) Вертикальная чистота: internal/planner + internal/adapters/{modelscripted, modelbounded} — платформенные пакеты без вертикальных слов (drift-зоны +modelbounded; словарь фраз НЕ растёт); слова бюджета/сборки — платформенные честные формулировки. (10) Полный регресс включает ЖИВОЙ release-journey: поверхность манифеста затронута (новые seal несут новые presence-слова) — journeys-батарея прогоняется живьём (правка ассерта владельца в zzzzzzz-release.spec.ts: подстрока, выживающая смену эпик-метки).

**Never:** не строить живой модельный адаптер, model-credentials, сеть, SDK (Граница эпика AG-4 — scripted + bounded за портом, stdlib); не исполнять tool-раунды (инвентарь в материале — форма для модели; исполнение над реестром 7.2/externaltools.Calls — 8.3); не строить продакшн-вызывателя, HTTP-поверхность, подключение в main.go (8.4); не строить eval-машину (8.5) и телеметрию-обвязку AR-18 (8.6 — журнал остаётся бизнес-записью за RLS); не строить retrieval/извлечение знаний (порт извлечения AD-8 — будущая поверхность с собственной спекой; сборка работает над Turn Context ТОЛЬКО); не флипать model_route в present=true (живого маршрута нет — честный false со специфичной запиской; флип — с первым живым маршрутом за AG-4); не пересчитывать sealed-манифесты и sealed-записи журнала (AD-10 — NULL истории = честное отсутствие, не обратная заливка); не персистить материал раунда (ни целиком, ни частично — проверяемость детерминизмом+версией, PII-материал не дублируется); не расширять платформенные словари (типизация — реюз tools.ToolFieldTypes; словари intent/safety/fallback — константы среза 8-1 без расширения); не менять семантику журнала 8-1 (Build «planner/1.0.0» неизменен; уникальность (tenant, turn_id); append-only гранты; RLS/FORCE); не вводить поведенческую доказательность §8.2 (эмоции правдивыми средствами — eval-набор 8.5; срез закрепляет контрактную сторону §8.1-пина); не строить голосовой контур (Epic 9 — AD-9: форма текстуальна); не менять форму Turn Context/Turn Proposal (контракт 8-1 sealed — эволюция формы = новая schema_version с собственной спекой); 1 SQL-миграция (00002 — расширение журнала, объявлена с самого начала).

## I/O & Edge-Case Matrix

- Given один и тот же Turn Context + repair-причина, when сборка материала дважды, then байтово-идентичный материал (детерминизм — проверяемость формы)
- Given контекст с фактом, when материал собран, then факт несёт полную Provenance {источник, версия, время} — AD-8 authority/source/version/time; слот фактов не смешивается ни с чем (форма закрыта, входа извлечения нет)
- Given контекст с AIDisclosureRequired=true, when материал собран, then §8.1-пин входит в материал (модель видит требование раскрытия); =false — пин отсутствует/выключен поимённо
- Given контекст с инвентарём read-инструментов, when материал собран, then инвентарь в материале {имя@версия + схемы словарём типизации} — модель видит, что может ЗАПРОСИТЬ (исполнение — 8.3)
- Given repair-раунд, when материал собран, then поимённая причина первого отказа входит в материал (модель узнаёт ПОЧЕМУ — не молчаливый фикс)
- Given модель за портом (scripted), when машина вызывает Round, then порт несёт МАТЕРИАЛ, не контекст — сырой Turn Context недостижим для адаптера (AD-8 по построению; git-зонд: RoundRequest не содержит TurnContext)
- Given Budgets{MaxRounds: 2} и scripted «unrecoverable», when ход, then 2 раунда, failed + fallback — гард раундов не срабатывает (структурная граница = граница бюджета)
- Given Budgets{MaxRounds: 1} (сужение), when первый раунд отказал валидацией, then гард bounded-адаптера отказывает второй раунд поимённо → failed + fallback (бюджет СУЖАЕТ структурный предел — честно)
- Given RoundTimeout истёк в раунде, when bounded-адаптер, then поимённая ошибка таймаута бюджета → failed + fallback; слепого retry нет; RefusalReason журнала несёт причину поимённо
- Given кумулятивная стоимость превышает MaxCostUnits, when следующий раунд, then поимённая ошибка стоимости → failed + fallback (unknown — без молчаливого продолжения)
- Given Budgets{MaxRounds: 3}, when построение, then поимённый отказ валидации бюджета (структурная граница машины — платформенный предел нерасширяем декларацией)
- Given Budgets{MaxCostUnits < RoundCostUnits} или {RoundTimeout ≤ 0}, when построение, then поимённый отказ валидации бюджета (недекларируемый ход — честный отказ конфигурации)
- Given валидный ход, when запись журнала, then запись несёт assembly_version + budgets JSONB + schema_version + Build — полная Provenance хода; Proposal JSONB за RLS как в 8-1
- Given ход до 8-2 (история), when чтение журнала, then assembly_version/budgets = NULL — честное отсутствие; UPDATE истории не существует (гранты; зонд permission denied)
- Given повторная запись того же turn_id, then честный ErrTurnConflict (уникальность 8-1 неизменна миграцией)
- Given чтение журнала тенентом B, then записи тенента A отсутствуют (RLS/FORCE — миграция 00002 наследует дисциплину 00001)
- Given новый seal манифеста (после 8-2), when BuildRuntimeState, then prompt_assembly Present=true Ref=слово версии сборки; runtime_build Present=true Ref=составное слово; model_route Present=false со специфичной запиской (AG-4/8.4)
