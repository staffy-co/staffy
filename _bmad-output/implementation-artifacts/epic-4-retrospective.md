## 4. Что сработало — перенести в Epic 5

1. **Domain Pack как носитель вертикали.** Магазинные словари/схемы/политики живут в версионированном паке auto-parts (структурные порты PackTaxonomy: IdentificationSchema → PartRequestSchema → FitmentSchema → ComparisonSchema), ядро не знает слов магазина, fork невозможен структурно (AD-1/AD-2). Каждый срез = новая версия пака с UpgradeFrom-совместимостью — Epic 5 (Montagio) должен повторить этот ход своим паком.
2. **Read-time деривации + digest-пины вместо триггеров.** ProfileDigest/PartRequestDigest/FitmentDigest/OfferDigest/OrderDigest: «точная версия» = канонический SHA-256, stale-вывод при изменении любого входа — без единого триггера в БД. «Оператор НЕ вводит дайджесты» — билдер выводит живьём (гварды отсекают ручное мнение).
3. **Продуктовый каталог поверх машины действия.** Первый продуктовый энтри `create_abcp_customer_order@1.0.0` резолвится из декларации 4-1; машины предложения/подтверждения/операции/диспетчера/сверки/recovery 3-4..3-8 переиспользованы as-is; лестница диспетчера заморожена — 4-7/4-8 добавляли контуры, НЕ трогая порядок шагов (живые счётчики порядка в тестах).
4. **Нулевой рост словаря outbox.** 11 story-вертикаль без НИ ОДНОГО нового семейства событий — материалы легли в существующие `case.*`/`operation.queued`. Словарный фонд — стабильная платформа, а не растущий долг.
5. **Честные слова в UI как норма.** Панели деградируют словами («Схема пака не определена»), unknown ≠ failed, закупочная цена — Commercial-скоуп со словом, «отправлен» — агрегат только при полном покрытии, перечня заказов не существует никогда. Владелец видит правду, а не комфорт.
6. **Идемпотентность BY KEY.** Факты 4-9 и запросы 4-10: UNIQUE полного ключа — повтор команды = сохранённый исход; изменившееся состояние доверия = НОВАЯ запись (лестница доверия видна в истории).
7. **Append-only дисциплина без исключений.** Все 9 новых столов: гранты INSERT/SELECT, RLS+FORCE, UPDATE/DELETE/TRUNCATE нет; суперсид — новой записью с бо́льшим номером, никогда обновлением.
8. **CI ×3 + sha-pinned merge + немедленное удаление веток.** 11/11 merge-точек зелёные поимённо; пин слияния в теле PR; правило владельца «слитая ветка удаляется сразу в трёх местах» исполнялось штатно на всех 11.
