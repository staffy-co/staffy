# CONTINUITY — система непрерывности разработки staffy

> Спроектирована экспертным консилиумом (5 экспертов: GitOps, BMAD-процесс,
> AgentOps, Security, QA/надёжность) 2026-10-06 и внедрена тем же днём.
> Задача: при сбросе сессии агента и/или полного сброса окружения разработка
> продолжается точно с места остановки, и ни один файл проекта не теряется.

## 1. Принципы (синтез консилиума)

1. **Git (origin) — единственный долговечный носитель.** Правило: «незакоммичено
   или не запушено — не существует». Локальный worklog песочницы — черновик,
   не источник истины (погибает при сбросе окружения).
2. **Один источник истины на каждый факт:**
   - git-история — что реально сделано (факт);
   - `sprint-status.yaml` — BMAD-статусы story (канон, позиция вычисляется
     детерминированно, вплоть до родного `sprint_plan.py status`);
   - `DEVLOG.md` — нарратив: решения, блокеры, `next:` (указатель продолжения);
   - `AGENTS.md` — статичный протокол (никогда не хранит позицию).
3. **Никакого STATE.md.** Отдельный файл позиции = третий писатель = второй
   источник истины = гарантированный рассинхрон (вердикт 3/5 экспертов).
   Проверяемость обеспечивает `scripts/check-continuity.sh`.
4. **Порядок доверия при расхождении:** git (origin) > sprint-status.yaml >
   DEVLOG > пересказ диалога. Расхождение лечится записью `correction:`,
   а не переписыванием прошлого.
5. **Двухступенчатое чтение для агента-преемника** («тёплый старт» ~4K токенов
   вместо ~20K при чтении вслепую): сначала дешёвая фиксация позиции
   (AGENTS.md → git log → хвост DEVLOG → sprint-status), затем точечное
   чтение только по текущей роли.

## 2. Компоненты

| Компонент | Роль |
|---|---|
| `AGENTS.md` | Точка входа агента: миссия, протокол возобновления, ритуалы, правила git/секретов; graphify-секция сохранена |
| `DEVLOG.md` | Append-only журнал; поле `next:` последней записи = указатель продолжения; `commit:` = последний подтверждённый коммит |
| `scripts/bootstrap.sh` | Идемпотентное восстановление окружения: код → Go → PostgreSQL → БД → миграции → smoke → `scripts/env.sh` |
| `third_party/portable-pg16.tar.xz` | Вендоренный портативный PostgreSQL 16.4 (единственный критичный бинарник без надёжного внешнего источника: EDB отдаёт 403) |
| `scripts/git-credential-staffy.sh` | Secret-free credential helper: токен только из env `STAFFY_GH_TOKEN`, remote URL всегда чистый |
| `.githooks/pre-commit, pre-push` | Скан секретов (GitHub PAT, приватные ключи) в стейдже и в уходящих коммитах; `--no-verify` запрещён |
| `scripts/check-continuity.sh` | Сверка: дерево чистое, нет незапушенного, статусы спек == sprint-status, коммит DEVLOG существует |
| `_bmad-output/implementation-artifacts/sprint-status.yaml` | Канонический трекер BMAD (существовал и до системы) |

## 3. Ритуалы фиксации

| Ритуал | Триггер | Действия |
|---|---|---|
| **Подшаг завершён** | Тесты зелёные / завершён BMAD-шаг (спека готова, патч применён, review закрыт) | DEVLOG-запись → обновить артефакты статуса → conventional commit → push (WIP-пуши — `[skip ci]`) |
| **SOS** | Близость исчерпания контекста, риск сбоя | `git add -A && git commit -m "wip: <шаг> [SOS]" && git push`; DEVLOG-запись `[SOS]` с точным `next:`; не «дорассказывать» словами то, что уже в коммите |
| **Конец сессии** | Пользователь завершает / граница story | Финальная DEVLOG-запись → push → `check-continuity.sh` → `git status -sb` чист |
| **Orphan checkpoint** | На старте сессии найдено грязное дерево | Это WIP предшественника: читать хвост DEVLOG, немедленно закоммитить WIP, потом разбираться |
| **Отказ push** | push отклонён (сеть/токен/права) | СТОП новому подшагу; `unpushed: N` в DEVLOG; эскалация токена владельцу |

## 4. Режимы отказа и гарантии (выдержка из таблицы QA-эксперта)

| Сценарий | Выдерживает? | Контрмера |
|---|---|---|
| Сброс сессии между коммитами | Да (файлы остаются) | Грязное дерево = orphan checkpoint; чтение DEVLOG-хвоста |
| Сброс сессии посреди правок | Да (файлы остаются) | Smoke в bootstrap: build/vet/test — не доверять, проверять |
| Сброс посреди SM/Dev/Review-фазы | Да | Спека и Triage Log коммитятся инкрементально; `next:` в DEVLOG |
| Полный сброс окружения, всё запушено | **Да (после внедрения)** | `STAFFY_GH_TOKEN=… bash scripts/bootstrap.sh` — полное восстановление |
| Полный сброс при незапушенном | Теряется ≤1 подшаг (RPO) | Push сразу за коммитом; SOS-ритуал |
| Push отклонён | Да | СТОП-протокол (выше) |
| Рассинхрон источников | Да | `check-continuity.sh`; порядок доверия git > sprint-status > DEVLOG |
| Force-push / rewrite истории | Защищается дисциплиной | Branch protection недоступна (free-план); запрет force-push в AGENTS.md; CI `on: push` ловит регресс |
| Сбой посреди bootstrap | Да | Идемпотентность: каждый шаг под маркером наличия; атомарные загрузки (.part + rename); логи шагов |
| Миграции vs код другой версии | Да | Миграции применяет integration-суит (drop+re-apply); staffy_test — disposable |
| Утечка токена | Предотвращена | Токен только в env; скан .githooks; аудит консилиума чист |

## 5. Секреты (регламент Security-эксперта)

- Токен GitHub (fine-grained PAT) выдаётся владельцем в чате на сессию:
  живёт только в env `STAFFY_GH_TOKEN`; remote URL всегда чистый.
- Никогда: в файлы репо, коммит-месседжи, имена веток, DEVLOG, логи,
  вывод `git remote -v` (печатать только маску `github_pat_***`).
- `.gitignore`: `.env*`, `*.token`, `*.pem`, `*.key`, `credentials*`,
  `.git-credentials`, `.netrc`, `.npmrc`, ключи ssh; `scripts/env.sh` (генерируемый).
- Ротация: по завершении проекта / при подозрении на утечку; при факте
  push секрета — сначала revoke, потом чистка истории.
- Рекомендуемые права токена: только этот репозиторий, Contents RW + Metadata R, срок ≤90 дней.

## 6. Учения (drill) — протокол проверки с «чистого листа»

Обязателен после любого изменения `bootstrap.sh` или схемы непрерывности.
Выполняется в отдельном каталоге песочницы (основной клон не трогается),
со своим PostgreSQL (другой порт) и свежим клоном:

1. **Фаза 0 — ожидания:** зафиксировать HEAD основного клона и позицию BMAD.
2. **Фаза 1 — fresh clone:** `git clone` → PASS-1: HEAD совпадает (RPO=0).
3. **Фаза 2 — ориентация (гейт ≤5 минут):** «холодный» агент читает только
   AGENTS.md → хвост DEVLOG → sprint-status → git log и должен назвать
   текущую story, статус, следующий шаг и команду bootstrap.
4. **Фаза 3 — bootstrap:** REPO_DIR/PG_HOME/PG_DATA/PG_PORT переопределены
   в drill-каталог; полное восстановление, включая распаковку vendored PG,
   initdb, создание БД (single-user mode), миграции через integration-суит.
5. **Фаза 4 — батарея:** go build / go vet / go test ./... / integration —
   зелёные; повторный запуск bootstrap (идемпотентность); основной клон
   не пострадал (git status чист, PG основной жив).
6. **Фаза 5 — разбор:** стоп drill-PG, `rm -rf` drill-каталог, отчёт
   (гейты + время) — записью в DEVLOG.

Definition of Done системы: RPO ≤ 1 подшаг; ориентация ≤5 мин по ≤3 файлам;
env-green ≤30 мин одной командой; идемпотентность доказана; `check-continuity`
зелёный на каждом коммите, трогающем `_bmad-output/**`.
